Пять CSV в папке выгрузок, а в чат Cursor снова копируете куски руками или цепляете файлы через @ по одному. MCP в Cursor – это розетки для агента: он сам вызывает инструменты и читает папку, браузер или таблицы без копипаста содержимого в диалог. За 20–40 минут подключите первый сервер (файлы), проверите зелёный статус и заставите Agent собрать summary по CSV в data/ – без ручной вставки строк.

MCP расшифровывается как Model Context Protocol – открытый протокол, через который Cursor подключает внешние инструменты и источники данных. Простыми словами: без MCP агент видит то, что вы положили в чат; с MCP у него появляются кнопки-инструменты (tools), и он сам дергает их за свежими данными. Это не "магический доступ к 1С" и не повод писать свой сервер с нуля в день 1.

В моей практике граница такая: разовые два файла – хватит @ и скрипта из гайда Cursor: скрипт сверки и дашборд. Когда файлов много, прогоны повторяются каждый месяц, а копипаст бесит – подключаю MCP. Агентный контур отчётности целиком – в Cursor AI-агенты для финотчётности. Здесь – один сервер и один сценарий отчёта по папке.

Разберите MCP простыми словами: зачем финансисту, а не только разработчику

Аналогия, которой я пользуюсь: MCP – как USB-C или розетка. Сам провод (протокол) ничего не считает. В розетку втыкаете готовый прибор – filesystem читает папку, browser открывает localhost, табличный сервер тянет строки. Cursor – хозяин (host): показывает tools в Agent и спрашивает разрешение перед вызовом.

Без MCP типичный вечер финансиста: открыли CSV → выделили кусок → вставили в чат → потеряли кодировку → повторили для второго файла. С MCP: "перечисли файлы в data/ и прочитай заголовки" → Agent вызывает tool → вы подтверждаете → получаете список и схему колонок без ручной вставки.

Вердикт: для финотдела MCP нужен как доступ агента к папке выгрузок и проверке локального экрана. Не делайте: ставить в день 1 GitHub, Figma и Kubernetes "потому что в топ-10". Сначала готовый сервер под файлы, свой MCP писать – только после 2–3 рабочих готовых.

Сделайте: зафиксируйте Definition of Done до установки: агент читает папку data/, выдаёт список файлов + свод, без копипаста CSV в чат. Не делайте: цель "подключить 15 серверов из Marketplace".

Выберите первый стек: файлы, браузер, таблицы – без магии 1С

Один пилот – один-два сервера. API здесь – как защищённый курьер между системами; MCP-сервер – коробка с кнопками, которые курьер умеет нажимать. К боевой 1С MCP в день 1 не подключают: нужен отдельный контур (OData / HTTP-сервис / выгрузка CSV в папку).

Задача финотдела Тип MCP Чего ждать
Папка выгрузок CSV/Excel Filesystem (узкий path) Список файлов, чтение заголовков и строк без копипаста
Проверить localhost-дашборд Browser Снимок/обход локальной страницы после Streamlit
Строки в облачной таблице Табличный / Sheets-сервер Чтение/правка реестра по API; ключи в env – см. MCP Google Sheets
Живая 1С Не MCP day-1 Сначала CSV в data/ или OData – иначе другой проект
Схема пилота: CSV в data/ → filesystem MCP → Agent вызывает tool → summary / out/report.md → (опционально) browser на localhost

Сделайте: стартуйте с filesystem на одну папку выгрузок. Не делайте: обещать себе "MCP к 1С за вечер" и раздавать серверу весь диск C.

Установите MCP в Cursor и проверьте вызов инструмента

Канон шагов – официальный help Cursor: Settings → Tools & MCP. Hotkey: Ctrl+Shift+J (Windows/Linux) или Cmd+Shift+J (Mac). Два пути: one-click из Marketplace / Add to Cursor или ручной mcp.json.

  1. Откройте Settings → Tools & MCP и нажмите Add to Cursor (или выберите сервер в Marketplace).
  2. Пройдите OAuth или вставьте ключ, если сервер просит доступ к внешнему сервису.
  3. Либо создайте проектный файл .cursor/mcp.json в корне папки (удобно шарить с командой) или глобальный %USERPROFILE%\.cursor\mcp.json на Windows.
  4. Для локального сервера задайте command / args / env; для удалённого – url и при необходимости headers. Секреты – только через env / ${env:VAR}, не строкой в git.
  5. Сохраните JSON и перезапустите Cursor (после ручной правки mcp.json официальный help указывает рестарт).
  6. Проверьте зелёный индикатор сервера в Tools & MCP. Если серый/красный – Output → MCP Logs, toggle, remove+re-add, убедитесь что Node/npx и переменные env видны Cursor.
  7. В Agent напишите тестовый промпт: "перечисли файлы в data/ через MCP" или "прочитай заголовки всех CSV в папке". Подтвердите allow tool – по умолчанию Agent спрашивает.
{
  "mcpServers": {
    "files-exports": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "D:/projects/fin-pilot/data"]
    }
  }
}

Путь в примере замените на свою узкую папку выгрузок. Имена серверов в проектном и глобальном конфиге мержатся; при конфликте приоритет у проектного .cursor/mcp.json.

Tools включаются в списке вверху чата. С Cursor 3.6+ есть Auto-review и allowlist в Approvals & Execution – на пилоте я оставляю ручное подтверждение.

Сделайте: один зелёный сервер + один успешный approve tool. Не делайте: включать Auto-run всех tools, пока не понимаете, что именно вызывается.

Прогоните сценарий: агент читает папку выгрузок и собирает отчёт

Те же CSV, что в вечернем пилоте со скриптом, – только доступ другой: не @файл по одному, а tool по папке. Pandas-скрипт писать здесь не обязательно: сначала пусть агент сам снимет инвентаризацию и свод. JSON на выходе – как акт сверки: у каждого поля своё место; для глаз часто хватает out/report.md.

Через MCP filesystem:
1) перечисли все файлы в data/;
2) для каждого CSV покажи заголовки и число строк;
3) по ключевому полю (уточни по заголовкам) найди дубли;
4) по сумме (если есть колонка amount/summa) дай итог;
5) запиши краткий отчёт в out/report.md.
Не переписывай проект. Не трогай файлы вне data/ и out/.
  1. Положите обезличенные выгрузки в data/ (ФИО/ИНН убрать или заменить кодами – см. обезличивание данных перед ChatGPT).
  2. Вставьте промпт в Agent, дождитесь запроса на tool и подтвердите только чтение нужной папки.
  3. Проверьте, что появился out/report.md или полный ответ со списком файлов и цифрами.
  4. Сверьте глазами 2–3 строки с исходным CSV – как выборочная инвентаризация.
  5. Если кодировка или разделитель сбились – короткий follow-up: "перечитай только заголовки с CP1251 / разделитель ;, остальное не трогай".

Если нужен скрипт сверки и Streamlit – вернитесь к B20: MCP не заменяет pandas, он убирает копипаст. Я сначала делаю инвентаризацию через tool, потом точечный скрипт, если свод повторяется без чата.

Разборы таких контуров публикую в Telegram "Финансист, который кодит".

Сделайте: один DoD-отчёт по папке. Не делайте: промпт "сам придумай архитектуру интеграции с 1С".

Проверьте риски: права, секреты в .env, что нельзя отдавать серверу

Filesystem MCP видит только то, к чему дан path. Широкий путь = широкий удар. Секреты в открытом mcp.json, уехавшем в git, – классика утечек. Сырые ПДн в облачный MCP-сервис – риск 152-ФЗ и коммерческой тайны.

  • Path только на папку выгрузок (data/), не на диск C и не на всю сетевую шару финотдела.
  • API-ключи и токены – в .env / переменных окружения / UI; .env в .gitignore.
  • Не коммитьте mcp.json с паролями 1С, Bearer-токенами и полными дампами.
  • На пилоте оставляйте confirmation tools; allowlist – только понятным read-only.
  • Боевые срезы – Privacy Mode в Cursor; в чат не вставляйте сырые ФИО/ИНН "для контекста".
  • Облачные MCP с чужим хранилищем – только на обезличенных данных.

Сделайте: чеклист path / env / gitignore / approve до второго сервера. Не делайте: Auto-run всего подряд и "временно" вписать пароль 1С в JSON.

Что дальше

  1. Откройте Tools & MCP и подключите filesystem на узкую папку data/.
  2. Добейтесь зелёного статуса и одного подтверждённого вызова tool.
  3. Прогоните промпт-отчёт: список файлов → заголовки → свод → out/report.md.
  4. Закройте секреты: .env, .gitignore, без боевых ПДн в облачных MCP.
  5. Когда пилот стабилен – rules/AGENTS.md под финотдел и следующий сервер (browser), не десять сразу.

Частые вопросы

MCP это доступ к 1С напрямую?

Нет. MCP даёт агенту tools: файлы, API, браузер. К 1С идите отдельно через OData, HTTP-сервис или выгрузку CSV в папку, которую читает filesystem MCP. Не обещайте себе "розетку в базу" за один вечер.

Бесплатно ли подключить MCP в Cursor?

Протокол открытый. Клиент – Cursor: старт с Hobby с лимитами Agent; стабильная агентная работа с MCP обычно на Pro – сверяйте актуальный тариф на cursor.com/pricing. Community-серверы часто free, но могут просить ключи сторонних API.

Чем MCP лучше, чем просто прикрепить файл через @?

Один-два файла разово – хватит @. Много файлов, повторные прогоны, свежие данные с диска или API – MCP, чтобы не копипастить. Для сверки двух CSV за вечер см. гайд про скрипт и дашборд.

Куда писать mcp.json на Windows?

Проект: .cursor/mcp.json в корне папки. Глобально: %USERPROFILE%\.cursor\mcp.json. Секреты держите в env, не в git. После ручной правки – перезапуск Cursor.

Почему сервер красный или серый?

Откройте Output → MCP Logs. Проверьте Node/npx, путь к папке, видны ли env из shell-профиля. Сделайте remove+re-add, toggle сервера, рестарт после правки JSON.

Нужно ли разрешать Auto-run всех tools?

На пилоте – нет. Оставляйте confirmation. Allowlist включайте только для понятных read-only tools, когда уже видели, что именно вызывается.
