Реестр договоров или УПД снова уезжает в чат Cursor кусками, а после правки вы вручную сверяете ячейки в Google Таблицах? MCP Google Sheets в Cursor – это розетка, через которую агент сам читает и обновляет строки реестра по ключу doc_key, без копипаста диапазонов. За 1–2 часа настроите service account и mcp-gsheets (или OAuth-плагин для пилота), проверите доступ через MCP Logs и прогоните сценарий: найти строку → обновить статус → перечитать результат.

MCP (Model Context Protocol) – протокол внешних инструментов Cursor. Без него агент видит только вставленный в чат текст; с MCP он вызывает tools Google Sheets API – как защищенный курьер между редактором и таблицей. Ответ в JSON – как акт сверки с фиксированными полями.

Три маршрута: Path A – Marketplace + OAuth (пилот); Path B – freema/mcp-gsheets + service account (production финконтура); Path C – официальный remote Google на sheetsmcp.googleapis.com (advanced). Для финконтура я беру Path B: changelog Cursor от 03.08.2026 детализирует Drive, Gmail и Calendar, а Sheets в витрине мог исчезнуть. Обзор MCP – в гайде по MCP в Cursor; запись скриптом с тем же SA – в интеграции Sheets API.

Оцените, когда MCP Sheets нужен финотделу (и когда нет)

Подключайте MCP, если реестр уже в Google Таблицах (договоры, УПД, SaaS, заявки), правки еженедельные, а копипаст диапазонов бесит. Не делайте Sheets единственным источником правды при жестком audit trail, enterprise ACL или более 200–300 активных договоров – тогда CLM/1С, таблица остается staging.

Подготовьте реестр и безопасность (без сырых ПДн)

Одна строка = одна сущность. Колонка doc_key – стабильный код (DOG-2026-014). Лист staging – для импорта из 1С/Forms; лист "Реестр" агент правит только в status и comment.

В облако: ИНН, сумма, статус – да; паспорт, полные ФИО payroll, карты – нет. Для тестов: "Контрагент_01", округленные суммы. Чеклист – в гайде по обезличиванию.

SA видит только файлы, расшаренные на client_email; IAM Cloud не заменяет Share. Scope spreadsheets = read/write всего файла – защищайте лист ProtectedRange. JSON-ключ не в git. Учитывайте indirect prompt injection: ячейки могут содержать тексты-инструкции для агента.

Схема: Sheets → (SA | OAuth | remote MCP) → Cursor → update по doc_key → перечитка → регламент CFO

Сделайте: отдельный SA, share "Редактор", без "Уведомить". Не делайте: боевые ПДн в тестовый реестр.

Настройте Path B: GCP, SA и mcp.json пошагово

mcp-gsheets: Node.js v20+, Sheets API, JSON SA. Конфиг: .cursor/mcp.json или ~/.cursor/mcp.json; при конфликте имен побеждает проектный.

  1. Создайте проект в Google Cloud → Enable APIs → Google Sheets API.
  2. Service account: IAM → Service Accounts → Create → Keys → JSON. Скопируйте client_email, файл вне git.
  3. Расшарьте реестр на client_email ролью "Редактор", снимите "Уведомить". Без Share – 403.
  4. Добавьте блок в mcp.json с абсолютным путем к ключу:
{
  "mcpServers": {
    "mcp-gsheets": {
      "command": "npx",
      "args": ["-y", "mcp-gsheets@latest"],
      "env": {
        "GOOGLE_PROJECT_ID": "your-project-id",
        "GOOGLE_APPLICATION_CREDENTIALS": "/absolute/path/to/sa-registry.json"
      }
    }
  }
}
  1. Перезапустите Cursor после правки mcp.json.
  2. Проверьте: Customize → MCPs → зеленый статус; ошибки – Output → MCP Logs (Ctrl+Shift+U). Tool sheets_check_access или чтение A1:C5 листа "Реестр".
  3. Approval на write: Agent спрашивает перед MCP-tool; на пилоте не включайте Auto-run всех write.

Tools: sheets_get_values, sheets_update_values, sheets_append_values, sheets_get_metadata. Для append – INSERT_ROWS.

Сделайте: зеленый сервер + check_access + тестовое чтение. Не делайте: коммит пути к ключу в git.

Подключите Path A или кратко Path C

Path A: Customize → MCPs → Google Sheets → Add → OAuth, минимальные scopes. 03.08.2026 анонсированы Workspace plugins (Drive, Gmail, Calendar); Sheets мог пропасть из витрины – проверяйте на дату установки. "Connected" ≠ авторизация: нужен живой read/write.

Path C (advanced): url https://sheetsmcp.googleapis.com/mcp/v1 + OAuth client и Sheets MCP API в GCP. Для первого реестра не обязателен – начните с Path B.

Сделайте: если плагин в Marketplace – OAuth и тест чтения; иначе Path B. Не делайте: считать зеленый индикатор финальной проверкой.

DoD: одна строка по doc_key + diff после write. Квота: 300 write/мин; при 429 – пауза и batch.

  1. sheets_get_metadata – лист и заголовки на месте.
  2. Найти строку по doc_key через get_values.

Проверьте результат и типичные ошибки

  • 403 – нет Share на client_email или неверный путь к JSON.
  • Серый MCP – MCP Logs; Node v20+, абсолютный путь в env.
  • 429 – батчите; не update ячейку в цикле.
  • Append – явно INSERT_ROWS.
  • OAuth – сбой consent или переход на Path B.

При >80–100 заявок/мес Forms→Sheets таблица – staging перед ERP/n8n; MCP – transport точечных правок. Планируйте ротацию ключа SA и allowlist write-tools.

Частые вопросы

Можно ли без программиста?

Path A: да для пилота, если плагин в витрине. Path B: по инструкции; первый реестр 1–2 часа с GCP и Share.

Сколько займет внедрение?

SA + mcp.json + тестовый update – около 1–2 часов. OAuth быстрее при доступном плагине.

OAuth или service account?

OAuth – личный пилот. SA – командный реестр и blast radius только на расшаренные файлы.

Какие риски для данных?

OAuth = права вашего Google; SA = все расшаренные таблицы. Без сырых ПДн; подтверждайте write; следите за injection из ячеек.

Чем B92 отличается от B82?

B82 – скрипт по cron. B92 – Agent через MCP без скрипта; тот же SA и Share.

Что такое sheetsmcp.googleapis.com?

Официальный remote MCP Google (Path C): url + OAuth в GCP. Для первого реестра хватит Path B.

Работает ли в Cloud Agents?

Локальный OAuth не переезжает. Нужен SA в env или коннектор в Cloud Agents dashboard.
