Реестр договоров или УПД снова уезжает в чат Cursor кусками, а после правки вы вручную сверяете ячейки в Google Таблицах? MCP Google Sheets в Cursor – это розетка, через которую агент сам читает и обновляет строки реестра по ключу doc_key, без копипаста диапазонов. За 1–2 часа настроите service account и mcp-gsheets, проверите доступ через MCP Logs и прогоните сценарий: найти строку, обновить статус, перечитать результат.

MCP (Model Context Protocol) – протокол, через который Cursor подключает внешние инструменты. Без MCP агент видит только то, что вы вставили в чат; с MCP у него появляются tools, и он сам дергает Google Sheets API, как защищенный курьер между редактором и таблицей. Ответ в JSON – как акт сверки: у каждого поля свое место. Итог для финотдела: статус в реестре меняется из чата Cursor, а не через ручной копипаст диапазона.

Два маршрута. Path A – плагин из Marketplace через OAuth (пилот, если Sheets в витрине). Path B – mcp-gsheets на service account: share только рабочего файла, ключ в env. Для финконтура в августе 2026 я беру Path B: changelog 03.08.2026 детализирует Drive, Gmail и Calendar, а Sheets мог исчезнуть из витрины 04.08. Обзор MCP – в гайде по MCP в Cursor; скрипт с тем же SA – в интеграции Sheets API.

Оцените, когда MCP Sheets нужен финотделу (и когда нет)

Подключайте MCP, если реестр уже в Google Таблицах (договоры, УПД, SaaS, заявки), правки повторяются, а копипаст бесит. Симптом: CFO просит сменить статус по doc_key, а вы боитесь сдвинуть формулы. Не делайте Sheets единственной правдой при жестком audit trail или более 200–300 активных договоров – тогда CLM/1С, таблица = staging.

Вердикт: реестр в Sheets + правки через Cursor → MCP убирает копипаст. No-code – в автоматизации финансов без кода.

Подготовьте реестр и безопасность (без сырых ПДн в облако)

Одна строка = одна сущность. Колонка doc_key – стабильный код вроде DOG-2026-014. Лист staging – сырые импорты из 1С/Forms; лист "Реестр" агент правит точечно в status и comment.

В облако: ИНН, сумма, статус – да; паспорт, полные ФИО payroll, карты – нет. Для теста: "Контрагент_01", округленные суммы. Чеклист – в гайде по обезличиванию.

Service account – как "сотрудник-бот" с client_email: видит только расшаренные таблицы. IAM Cloud ≠ Share файла. Scope spreadsheets = read/write всего файла; чувствительные листы – ProtectedRange. JSON-ключ – не в git, только в GOOGLE_APPLICATION_CREDENTIALS.

Схема: реестр в Sheets → (SA share | OAuth) → MCP в Cursor → update по doc_key → перечитка → регламент CFO

Сделайте: отдельный SA, share одного файла "Редактор", без "Уведомить". Не делайте: боевые ПДн в тестовый реестр.

Настройте Path B: Google Cloud, SA и mcp.json пошагово

mcp-gsheets (freema/mcp-gsheets): Node.js v20+, Sheets API, JSON SA. Конфиг: .cursor/mcp.json (проект) или ~/.cursor/mcp.json (глобальный); при конфликте имен побеждает проектный.

  1. Создайте проект на console.cloud.google.com → Enable APIs → Google Sheets API.
  2. Service account: IAM → Service Accounts → Create → Keys → JSON. Скопируйте client_email, ключ вне git.
  3. Расшарьте реестр на client_email "Редактор", снимите "Уведомить". Без Share – 403.
  4. Добавьте блок в mcp.json с абсолютным путем к ключу:
{
  "mcpServers": {
    "mcp-gsheets": {
      "command": "npx",
      "args": ["-y", "mcp-gsheets@latest"],
      "env": {
        "GOOGLE_PROJECT_ID": "your-project-id",
        "GOOGLE_APPLICATION_CREDENTIALS": "/absolute/path/to/sa-registry.json"
      }
    }
  }
}
  1. Перезапустите Cursor после правки mcp.json.
  2. Проверьте: Customize → MCPs → зеленый статус; ошибки – Output → MCP Logs (Ctrl+Shift+U). Tool sheets_check_access или чтение A1:C5 листа "Реестр".
  3. Approval на write: Agent спрашивает перед MCP-tool; на пилоте не включайте Auto-run всех write.

Tools: sheets_get_values, sheets_update_values, sheets_append_values, sheets_batch_get_values, sheets_get_metadata, sheets_check_access. Перед боевыми правками сначала check_access. Для append указывайте INSERT_ROWS: default OVERWRITE перезаписывает ячейки не так, как ждете в журнале заявок.

Сделайте: зеленый сервер + check_access + тестовое чтение. Не делайте: коммит mcp.json с путем к ключу.

Проверьте результат и типичные ошибки

После каждой записи – перечитка того же диапазона.

  • 403 – нет Share на client_email или неверный путь к JSON.
  • Серый MCP – MCP Logs; Node v20+, npx, абсолютный путь в env.
  • 429 – батчите; не update на каждую ячейку в цикле.
  • Append – явно INSERT_ROWS.
  • OAuth – bug cursor:// или переход на Path B.

При более 80–100 заявок/мес через Forms→Sheets таблица = staging перед ERP/n8n; MCP – транспорт точечных правок, не главная книга учета. Планируйте ротацию ключа SA и allowlist только нужных write-tools.

Частые вопросы

Можно ли без программиста?

Path A: да для пилота, если плагин в витрине. Path B: по инструкции и help Cursor; первый реестр 1–2 часа с GCP и Share.

Сколько займет внедрение?

SA + mcp.json + тестовый update – около 1–2 часов. OAuth быстрее, если плагин доступен и OAuth без бага.

OAuth или service account?

OAuth – личный пилот. SA – командный реестр, минимальный blast radius: только расшаренные файлы, удобнее для Cloud Agents.

Какие риски для данных?

OAuth = права вашего Google; SA = все расшаренные таблицы. Без сырых ПДн; подтверждайте write-tools; injection из ячеек. Обезличивание – в гайде выше.

Чем это отличается от скрипта Sheets API?

Скрипт пишет в staging по cron. Здесь Agent правит через MCP без отдельного кода; тот же SA и Share.

Работает ли в Cloud Agents?

Локальный OAuth в облако не переезжает. Для Cloud Agents – SA в env или MCP через dashboard.

Нужен ли MCP для маленького реестра?

5 строк раз в месяц – хватит ручного редактирования. MCP окупается при еженедельных правках через Cursor без копипаста.
