Реестр договоров или УПД снова уезжает в чат Cursor кусками, а после правки вы вручную сверяете ячейки в Google Таблицах? MCP Google Sheets в Cursor - это розетка, через которую агент сам читает и обновляет строки реестра по ключу doc_key, без копипаста диапазонов. За 1-2 часа настроите service account и mcp-gsheets, проверите доступ через MCP Logs и прогоните сценарий: найти строку, обновить статус, перечитать результат.

MCP (Model Context Protocol) - протокол, через который Cursor подключает внешние инструменты. Без MCP агент видит только то, что вы вставили в чат; с MCP у него появляются tools, и он сам дергает Google Sheets API, как защищенный курьер между редактором и таблицей. JSON в ответе - как акт сверки: у каждого поля свое место.

Три маршрута на сентябрь 2026. Path A - плагин google-sheets из Marketplace через OAuth (быстрый пилот). Path B - mcp-gsheets на service account: расшарили только рабочий файл, ключ в env. Path C - официальный remote Sheets MCP Google (Developer Preview) по sheetsmcp.googleapis.com. Для финконтура я опираюсь на Path B: changelog Cursor от 03.08.2026 детализирует Drive, Gmail и Calendar, а Sheets в витрине мог временно исчезнуть. Обзор MCP - в гайде по MCP в Cursor; запись скриптом с тем же SA - в интеграции Sheets API.

Оцените, когда MCP Sheets нужен финотделу (и когда нет)

Подключайте MCP, если реестр уже в Google Таблицах (договоры, УПД, SaaS, заявки на расход), правки повторяются каждую неделю, а копипаст диапазонов в чат бесит. Типичный симптом: CFO просит сменить статус по doc_key, а вы выделяете 40 строк и боитесь сдвинуть формулы. Не делайте Sheets единственным источником правды при жестком audit trail, сотнях таблиц с enterprise ACL или более 200-300 активных договоров - тогда CLM или 1С, таблица остается staging-слоем.

Подготовьте реестр и безопасность (без сырых ПДн в облако)

Одна строка = одна сущность (договор, УПД, подписка). Колонка doc_key - стабильный код вроде DOG-2026-014; по нему агент ищет строку, а не по названию контрагента. Лист staging - для сырых импортов из 1С или Forms; боевой лист "Реестр" агент правит точечно в колонках status и comment.

В облако отправляйте ИНН контрагента, сумму, статус - да; паспорт, полное ФИО в payroll, номера карт - нет. Замените названия на "Контрагент_01", суммы округлите для тестов. Чеклист - в гайде по обезличиванию данных.

SA видит только таблицы, расшаренные на client_email; IAM Cloud не заменяет Share. JSON-ключ - не в git, только в GOOGLE_APPLICATION_CREDENTIALS. Риск indirect prompt injection: текст в ячейке может выглядеть как инструкция агенту - human approval на каждый write обязателен.

Схема: реестр в Sheets → (SA share | OAuth plugin | Google remote MCP) → MCP в Cursor → update по doc_key → перечитка → регламент CFO

Сделайте: отдельный SA, share одного файла "Редактор", без "Уведомить". Не делайте: боевые ПДн в тестовый реестр.

Настройте Path B: Google Cloud, SA и mcp.json пошагово

Сервер mcp-gsheets (freema/mcp-gsheets) требует Node.js v20+, Google Sheets API и JSON SA. Конфиг: проектный .cursor/mcp.json или глобальный ~/.cursor/mcp.json; при конфликте имен побеждает проектный.

  1. Создайте проект на console.cloud.google.com → Enable APIs → Google Sheets API.
  2. Service account: IAM → Service Accounts → Create → Keys → JSON. Скопируйте client_email, файл вне git.
  3. Расшарьте реестр на client_email "Редактор", снимите "Уведомить". Без Share - 403.
  4. Добавьте блок в mcp.json с абсолютным путем к ключу:
{
  "mcpServers": {
    "mcp-gsheets": {
      "command": "npx",
      "args": ["-y", "mcp-gsheets@latest"],
      "env": {
        "GOOGLE_PROJECT_ID": "your-project-id",
        "GOOGLE_APPLICATION_CREDENTIALS": "/absolute/path/to/sa-registry.json"
      }
    }
  }
}
  1. Перезапустите Cursor после правки mcp.json (официальный help Cursor).
  2. Проверьте: Customize → MCPs → зеленый статус; ошибки - Output → MCP Logs (Ctrl+Shift+U). Tool sheets_check_access или чтение A1:C5 листа "Реестр".
  3. Approval на write: по умолчанию Agent спрашивает перед MCP-tool; на пилоте не включайте Auto-run всех write.

Tools реестра: sheets_get_values, sheets_update_values, sheets_append_values, sheets_get_metadata. Для append указывайте INSERT_ROWS: default OVERWRITE перезаписывает иначе, чем ждете. Квоты: 300 write/мин на проект; 429 - пауза и батч.

Сделайте: зеленый сервер + check_access + тестовое чтение. Не делайте: коммит mcp.json с путем к ключу.

Проверьте результат и типичные ошибки

После каждой записи - перечитка того же диапазона.

  • 403 - нет Share на client_email или неверный путь к JSON.
  • Серый MCP - MCP Logs; Node v20+, npx, абсолютный путь в env.
  • 429 - батчите; не update на каждую ячейку в цикле.
  • Append - явно INSERT_ROWS.
  • OAuth / Preview - bug cursor:// или переход на Path B.

При более 80-100 заявок/мес через Forms→Sheets таблица становится staging перед ERP или n8n; MCP - transport точечных правок, не главная книга. Дальше - ротация ключа SA (B93) и allowlist write-tools.

Сделайте: чеклист share / env / MCP Logs / re-read. Не делайте: чинить 403 промптом без Share.

Частые вопросы

Можно ли без программиста?

Path A: да для пилота, если плагин в витрине. Path B: по инструкции и help Cursor; первый реестр 1-2 часа с GCP и Share. Path C: OAuth remote, если Preview доступен.

Сколько займет внедрение?

SA + mcp.json + тестовый update - около 1-2 часов. OAuth быстрее, если плагин или remote доступны без bug.

OAuth или service account?

OAuth - личный пилот (Path A/C). SA - командный реестр, минимальный blast radius: только расшаренные файлы.

Какие риски для данных?

OAuth = права вашего Google; SA = все расшаренные таблицы. Без сырых ПДн; подтверждайте write-tools; indirect injection из ячеек. Обезличивание - в гайде по ссылке выше.

Чем B92 отличается от B82?

B82 - скрипт в staging по cron. B92 - Agent правит через MCP без скрипта; тот же SA и Share.

Работает ли в Cloud Agents?

Локальный OAuth в облако не переезжает. Для Cloud Agents - SA в env или отдельный коннектор.

Нужен ли MCP для маленького реестра?

5 строк раз в месяц - хватит ручного редактирования. MCP окупается при еженедельных правках через Cursor без копипаста.
