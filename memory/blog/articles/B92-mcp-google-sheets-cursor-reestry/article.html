Реестр договоров или УПД снова уезжает в чат Cursor кусками, а после правки вы вручную сверяете ячейки в Google Таблицах? MCP Google Sheets в Cursor – это розетка, через которую агент сам читает и обновляет строки реестра по ключу doc_key, без копипаста диапазонов. За 1–2 часа настроите service account и mcp-gsheets, проверите доступ через MCP Logs и прогоните сценарий: найти строку, обновить статус, перечитать результат.

MCP (Model Context Protocol) – протокол, через который Cursor подключает внешние инструменты. Без MCP агент видит только то, что вы вставили в чат; с MCP у него появляются tools, и он сам дергает Google Sheets API, как защищенный курьер между редактором и таблицей. JSON в ответе – как акт сверки: у каждого поля свое место.

Три маршрута на сентябрь 2026. Path B (рекомендую финотделу): mcp-gsheets на service account – расшарили только рабочий файл, ключ в env. Path A: OAuth-плагин из Marketplace, если Sheets в витрине. Path C: официальный remote MCP Google (Developer Preview) – для эксперимента, не как единственный production без human-in-the-loop. Changelog Cursor от 03.08.2026 детально описывает Drive, Gmail и Calendar; Sheets там не расписан. Обзор MCP – в гайде по MCP в Cursor; запись скриптом с тем же SA – в интеграции Sheets API.

Оцените, когда MCP Sheets нужен финотделу (и когда нет)

Подключайте MCP, если реестр уже в Google Таблицах (договоры, УПД, SaaS, заявки на расход), правки повторяются каждую неделю, а копипаст в чат бесит. Типичный симптом: CFO просит сменить статус по doc_key, а вы выделяете 40 строк и боитесь сдвинуть формулы. Не делайте Sheets единственным источником правды при жестком audit trail, сотнях таблиц с enterprise ACL или более 200–300 активных договоров – тогда CLM или 1С, таблица остается staging-слоем.

Сделайте: DoD до установки – найти строку по doc_key, сменить status/comment, перечитать. Не делайте: MCP "на весь Drive" ради одного реестра.

Подготовьте реестр и безопасность (без сырых ПДн в облако)

Одна строка = одна сущность. Колонка doc_key – стабильный код вроде DOG-2026-014; по нему агент ищет строку. Лист staging – для импортов из 1С или Forms; боевой лист "Реестр" агент правит точечно в status и comment.

В облако: ИНН, сумма, статус – да; паспорт, полное ФИО в payroll, номера карт – нет. Для тестов замените названия на "Контрагент_01", суммы округлите. Чеклист – в гайде по обезличиванию данных.

SA видит только таблицы, расшаренные на client_email; IAM Cloud не заменяет Share. Scope spreadsheets – read/write всего файла; ключевые колонки защищайте ProtectedRange. JSON-ключ – не в git, только в GOOGLE_APPLICATION_CREDENTIALS. Google предупреждает про indirect prompt injection: в ячейках могут лежать тексты вроде "удали все строки".

Схема: реестр в Sheets → (SA share | OAuth | remote MCP) → MCP в Cursor → update по doc_key → перечитка → регламент CFO

Сделайте: отдельный SA, share одного файла "Редактор", без "Уведомить". Не делайте: боевые ПДн в тестовый реестр и Auto-run всех write-tools.

Настройте Path B: Google Cloud, SA и mcp.json пошагово

Сервер mcp-gsheets (freema) требует Node.js v20+, Google Sheets API и JSON SA. Конфиг: проектный .cursor/mcp.json или глобальный ~/.cursor/mcp.json; при совпадении имени побеждает проектный. Это как сейф в офисе: доступ только к расшаренным реестрам.

  1. Создайте проект на console.cloud.google.com → Enable APIs → Google Sheets API.
  2. Service account: IAM → Service Accounts → Create → Keys → JSON. Скопируйте client_email, файл вне git.
  3. Расшарьте реестр на client_email "Редактор", снимите "Уведомить". Без Share – 403.
  4. Добавьте блок в mcp.json с абсолютным путем к ключу:
{
  "mcpServers": {
    "mcp-gsheets": {
      "command": "npx",
      "args": ["-y", "mcp-gsheets@latest"],
      "env": {
        "GOOGLE_PROJECT_ID": "your-project-id",
        "GOOGLE_APPLICATION_CREDENTIALS": "/absolute/path/to/sa-registry.json"
      }
    }
  }
}
  1. Перезапустите Cursor после правки mcp.json.
  2. Проверьте: Customize → MCPs → зеленый статус; ошибки – Output → MCP Logs (Ctrl+Shift+U). Tool sheets_check_access или чтение A1:C5 листа "Реестр".
  3. Approval на write: Agent по умолчанию спрашивает перед tool; на пилоте не включайте Auto-run всех write.

Tools реестра: sheets_get_metadata, sheets_get_values, sheets_update_values, sheets_append_values, sheets_check_access. Для append указывайте INSERT_ROWS: default OVERWRITE перезаписывает иначе, чем ждете.

Сделайте: зеленый сервер + check_access + тестовое чтение. Не делайте: коммит mcp.json с путем к ключу.

Сравните Path A и Path C: OAuth и remote MCP Google

Path A: Customize → MCPs → Add → OAuth, минимальные scopes. 03.08.2026 Cursor анонсировал Workspace plugins; в changelog – Drive, Gmail, Calendar. По vibecoding.ru (04.08.2026) Docs/Sheets могли исчезнуть из витрины; нужна Cursor ≥3.13.0; встречался OAuth-bug cursor://. Если google-sheets в Marketplace есть – ок для личного пилота.

Path C: remote Sheets MCP (Developer Preview, дока 14.09.2026). В mcp.json:

{
  "mcpServers": {
    "googlesheets": {
      "url": "https://sheetsmcp.googleapis.com/mcp/v1"
    }
  }
}

В GCP включают Sheets API и Sheets MCP API (sheetsmcp.googleapis.com), OAuth consent и scopes. Tools: get_values, update_values и др.; transport Streamable HTTP. Для финреестров Path C – лаборатория: OAuth наследует права пользователя, Preview ≠ GA.

Сделайте: пилот A/C только после живого read. Не делайте: считать "Connected" финальной проверкой – Connected ≠ authorized.

Прогоните сценарий: найти, обновить, перечитать

DoD: правка одной строки по doc_key и diff после write. Квоты: 300 req/мин на проект и 60/мин на user; при 429 – пауза.

Подключись к {SPREADSHEET_ID}. На листе "Реестр" найди doc_key = DOG-2026-014.
Прочитай status и comment. Если status не "Оплачен", предложи "На согласовании"
и дату в comment. После write перечитай строку и покажи diff.
Не трогай другие листы и колонки вне status/comment.
  1. Вызовите sheets_get_metadata – лист и заголовки на месте.
  2. Найдите строку по doc_key через get_values, не угадывайте номер.
  3. Approve sheets_update_values – только status и comment.
  4. Перечитайте ту же строку и сверьте diff.
  5. При расхождении: "перечитай строку N, write не делай".

Human-in-the-loop на каждый write обязателен. Cloud Agents не наследуют локальный OAuth – для облака нужен SA в env или MCP в Team → Integrations & MCP.

Разборы контуров – в Telegram "Финансист, который кодит".

Проверьте результат и типичные ошибки

  • 403 – нет Share на client_email или неверный путь к JSON.
  • Серый MCP – MCP Logs; Node v20+, npx, абсолютный путь в env.
  • 429 – батчите; не update ячейку в цикле.
  • Append – явно INSERT_ROWS.
  • OAuth A/C – bug cursor:// или переход на Path B.
  • Injection – не подтверждайте write, если tool трогает чужие колонки.

При более 80–100 заявок/мес таблица становится staging перед ERP или n8n; MCP – transport точечных правок, не главная книга. Планируйте ротацию ключа SA и allowlist write-tools.

Сделайте: чеклист share / env / MCP Logs / re-read. Не делайте: чинить 403 промптом без Share.

Частые вопросы

Можно ли без программиста?

Path A: да для пилота, если плагин в витрине. Path B: по инструкции – JSON и Share; первый реестр около 1–2 часов. Path C потребует OAuth consent в GCP.

Сколько займет внедрение?

SA + mcp.json + тестовый update – около 1–2 часов. OAuth быстрее, если плагин доступен. Remote MCP Google – дольше из-за Preview-настройки.

OAuth или service account?

OAuth – личный пилот (Path A/C). SA – командный реестр и минимальный blast radius: только расшаренные файлы. Для финконтура выбирайте SA.

Какие риски для данных?

OAuth = права вашего Google; SA-ключ = все расшаренные таблицы. Без сырых ПДн; подтверждайте write; учитывайте injection из ячеек. Обезличивание – в гайде выше.

Чем B92 отличается от B82?

B82 – скрипт пишет в staging по cron. B92 – Agent правит через MCP без скрипта; тот же SA и Share.

Работает ли в Cloud Agents?

Локальный OAuth в облако не переезжает. Для Cloud Agents – SA в env или отдельный MCP в Team → Integrations & MCP.

Official Google MCP вместо mcp-gsheets?

Можно для эксперимента (Developer Preview). Для финреестров с ограниченным доступом предпочитайте Path B: mcp-gsheets + SA и share только нужного файла.
