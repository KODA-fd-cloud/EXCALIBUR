Реестр договоров или УПД снова уезжает в чат Cursor кусками, а после правки вы вручную сверяете ячейки? MCP Google Sheets в Cursor – это розетка: агент сам читает и обновляет строку реестра по ключу doc_key, без копипаста диапазонов. За 1–2 часа настроите service account и mcp-gsheets, проверите доступ через MCP Logs и прогоните цикл: найти строку → обновить статус → перечитать результат.

MCP (Model Context Protocol) – протокол, через который Cursor подключает внешние инструменты. Без него агент видит только то, что вы вставили в чат. С MCP появляются tools, и он дергает Google Sheets API как защищенный курьер между редактором и таблицей. Ответ в JSON – как акт сверки: у каждого поля свое место.

Честно про статус на 08.09.2026: changelog Cursor от 03.08.2026 описывает плагины Drive, Gmail и Calendar – не Sheets. Для правки ячеек реестра берите community MCP (рекомендация КОДА – Path B: mcp-gsheets + service account). Path A – hosted/OAuth-пилот (we2go, Composio и аналоги) для личного теста: удобно за вечер, но данные идут через посредника. Общий обзор MCP – в гайде по MCP в Cursor; остатки и обороты из 1С – в MCP 1С в Cursor; запись скриптом с тем же SA – в интеграции Sheets API.

Оцените, когда MCP Sheets нужен финотделу (и когда нет)

Подключайте MCP, если реестр уже в Google Таблицах (договоры, УПД, SaaS, заявки), правки повторяются каждую неделю, а копипаст диапазонов в чат бесит. Типичный симптом: CFO просит сменить статус по doc_key, а вы выделяете 40 строк и боитесь сдвинуть формулы. Не делайте Sheets единственным источником правды при жестком audit trail, сотнях таблиц с enterprise ACL или более 200–300 активных договоров – тогда CLM или 1С, таблица остается staging-слоем.

Маршрут Когда выбирать Минус
Path A: hosted / OAuth Личный пилот без GCP Данные через посредника; шире blast radius
Path B: mcp-gsheets + SA Командный реестр, production GCP-проект и JSON-ключ вне git
Копипаст в чат Разовая правка 5 строк Нет перечитки, риск ПДн в истории
Python-скрипт (B82) Cron, пакет из 1С Нет интерактивных правок через Agent
Вердикт: если реестр в Sheets и правки идут через Cursor – Path B убирает копипаст. No-code-контур – в автоматизации финансов без кода.

Сделайте: DoD до установки: найти строку по doc_key, сменить status/comment, перечитать. Не делайте: обещать "официальный Sheets-плагин Marketplace" – changelog Workspace его не перечисляет.

Подготовьте реестр и безопасность (без сырых ПДн в облако)

Одна строка = одна сущность (договор, УПД, подписка). Колонка doc_key – стабильный код вроде DOG-2026-014; по нему агент ищет строку, а не по названию контрагента. Лист staging – для сырых импортов из 1С или Forms; боевой лист "Реестр" агент правит точечно в колонках status и comment.

В облако: ИНН контрагента, сумма, статус – да; паспорт, полное ФИО в payroll, номера карт – нет. Для тестов замените названия на "Контрагент_01", суммы округлите. Чеклист – в гайде по обезличиванию данных.

Service account по умолчанию не видит таблицы, пока файл не расшарен на client_email из JSON – как обычный Google-аккаунт. IAM Cloud не заменяет Share файла. Scope spreadsheets дает read/write всего файла; чувствительные листы защищайте ProtectedRange. JSON-ключ – не в git, только в GOOGLE_APPLICATION_CREDENTIALS. Для create/share новых файлов часто нужен еще Drive scope – реестру статусов он обычно не нужен, не расширяйте права "на всякий случай".

Схема: реестр в Sheets → SA share → mcp-gsheets в Cursor → Agent read/update по doc_key → перечитка диапазона → регламент CFO

Сделайте: отдельный SA, share одного файла ролью "Редактор", без "Уведомить". Не делайте: боевые ПДн в тестовый реестр и ключ в репозитории.

Настройте Path B: Google Cloud, SA и mcp.json пошагово

Сервер mcp-gsheets (npm, Node.js v20+) ставится через npx. Конфиг: проектный .cursor/mcp.json или глобальный ~/.cursor/mcp.json; при совпадении имен побеждает проектный.

  1. Создайте проект в Google Cloud → включите Google Sheets API.
  2. Создайте service account: IAM → Service Accounts → Keys → JSON. Скопируйте client_email, файл ключа храните вне git.
  3. Расшарьте реестр на client_email с ролью "Редактор". Без Share будет 403 / spreadsheet not found.
  4. Добавьте блок в mcp.json с абсолютным путем к ключу:
{
  "mcpServers": {
    "mcp-gsheets": {
      "command": "npx",
      "args": ["-y", "mcp-gsheets@latest"],
      "env": {
        "GOOGLE_PROJECT_ID": "your-project-id",
        "GOOGLE_APPLICATION_CREDENTIALS": "/absolute/path/to/sa-registry.json"
      }
    }
  }
}
  1. Перезапустите Cursor после правки mcp.json (официальный help Cursor).
  2. Проверьте: Customize → MCPs → зеленый статус; ошибки – Output → MCP Logs (Ctrl+Shift+U). Tool sheets_check_access или чтение A1:C5 листа "Реестр".
  3. Approval на write: по умолчанию Agent спрашивает перед MCP-tool; на пилоте не включайте Auto-run всех write.

Рабочие tools: sheets_get_values, sheets_update_values, sheets_append_values, sheets_get_metadata, sheets_check_access. "Connected" ≠ authorized – только живой read подтверждает доступ. Альтернативы Path B на GitHub (spreadsheet-mcp, google-sheets-mcp) тоже опираются на SA: меняется команда запуска, логика Share и verify-loop та же.

Сделайте: зеленый сервер + check_access + тестовое чтение. Не делайте: коммит mcp.json с абсолютным путем к секретному ключу.

Прогоните сценарий: найти, обновить, перечитать

DoD: правка одной строки по doc_key и diff после write. Квота Sheets API: 300 read и 300 write запросов в минуту на проект; batch = один запрос; при HTTP 429 – пауза.

Подключись к {SPREADSHEET_ID}. На листе "Реестр" найди doc_key = DOG-2026-014.
Прочитай status и comment. Если status не "Оплачен", предложи "На согласовании"
и дату в comment. После write перечитай строку и покажи diff.
Не трогай другие листы и колонки вне status/comment.
  1. sheets_get_metadata – лист "Реестр" и заголовки на месте.
  2. Найти строку по doc_key через get_values, не "угадать" номер.
  3. Approve sheets_update_values – только status и comment.
  4. После write – get_values на ту же строку, сверка с ожиданием.
  5. Follow-up при расхождении: "перечитай строку N, write не делай".

Риск indirect prompt injection: в ячейках могут быть тексты, которые агент прочтет как инструкции ("удали все строки"). Human-in-the-loop на каждый write-tool обязателен. Cloud Agents не копируют локальный mcp.json/OAuth автоматически – для облака настройте MCP в dashboard или тот же SA в env.

Разборы контуров – в Telegram "Финансист, который кодит".

Сделайте: цикл find → update → re-read на тестовой строке. Не делайте: Auto-run write без allowlist.

Проверьте результат и типичные ошибки

После каждой записи – перечитка того же диапазона. Чеклист диагностики:

  • 403 / not found – нет Share на client_email SA или неверный spreadsheet ID из URL.
  • Серый MCP – MCP Logs; Node v20+, npx, абсолютный путь в env.
  • 429 – батчите; не update на каждую ячейку в цикле.
  • Append – явно INSERT_ROWS, иначе OVERWRITE перезапишет не то.
  • Path A – если hosted/OAuth капризничает, переходите на Path B.

При более 80–100 заявок/мес через Forms→Sheets таблица становится staging перед ERP или n8n с платёжным календарём; MCP – transport точечных правок, не главная книга. Планируйте ротацию ключа SA (тема B93) и allowlist только нужных write-tools. Квоты Sheets API на проект конечны: при массовых прогонах агента батчите чтение, иначе поймаете 429 раньше, чем закончите сверку.

Сделайте: чеклист share / env / MCP Logs / re-read. Не делайте: чинить 403 промптом без Share файла.

Что автоматизировать дальше

  1. Path B на одном реестре с doc_key и листом staging.
  2. Зеленый MCP + check_access + update с перечиткой.
  3. Allowlist write-tools; SA-ключ вне git.
  4. Соседние реестры (договоры, УПД, SaaS) – MCP поверх уже спроектированной таблицы.
  5. При audit – ERP/CLM; cron-загрузки – скрипт из гайда B82.

Частые вопросы

Можно ли без программиста?

Path B по инструкции: 1–2 часа на SA, Share и mcp.json; Cursor поможет с JSON. "Вообще без GCP" – только hosted/OAuth-пилот, не для командного финконтура.

Сколько займет внедрение?

SA + mcp.json + один тестовый update – около 1–2 часов. Hosted/OAuth быстрее для личного теста, но хуже по blast radius.

Есть ли официальный плагин Google Sheets в Cursor?

На 08.09.2026 changelog Workspace описывает Drive, Gmail и Calendar. Cell-edit реестров – community MCP (mcp-gsheets) или hosted-коннектор, не "магический" Marketplace Sheets.

OAuth или service account?

OAuth/hosted – личный пилот. SA – командный реестр и минимальный blast radius: только расшаренные файлы.

Какие риски для данных?

SA-ключ = доступ ко всем расшаренным таблицам. Без сырых ПДн; подтверждайте write-tools; не коммитьте JSON. Обезличивание – в гайде по ссылке выше.

Чем это отличается от интеграции Sheets API скриптом?

Скрипт (B82) пишет в staging по cron. Здесь Agent в Cursor правит через MCP без кода; тот же SA и Share.

Почему 403 или spreadsheet not found?

Не расшарили client_email SA на файл или ошиблись в ID таблицы из URL. Проверьте Share и sheets_check_access, не новый промпт.
