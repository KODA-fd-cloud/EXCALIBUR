Реестр договоров или УПД снова уезжает в чат Cursor кусками, а после правки вы вручную сверяете ячейки? MCP Google Sheets - розетка, через которую агент читает и обновляет строки по doc_key без копипаста. На 26.08.2026 плагин Sheets в Marketplace недоступен ("MCP server Not Found"), поэтому базовый маршрут - mcp-gsheets плюс service account: за 1-2 часа настроите доступ, проверите MCP Logs и прогоните find → update → re-read.

MCP (Model Context Protocol) - протокол, через который Cursor подключает внешние tools. Без MCP агент видит только вставленный в чат текст; с MCP он дергает Google Sheets API, как защищенный курьер между редактором и таблицей. JSON в ответе - как акт сверки: у каждого поля свое место. Service account - "служебный сотрудник" в Google: шарите ему один файл-реестр, а не весь Drive.

Path B (default) - community-сервер freema/mcp-gsheets на SA: ключ в env, агент не видит весь Drive. Path A - Marketplace OAuth - только если витрина снова покажет Sheets. Changelog 03.08.2026 детализирует Drive, Gmail, Calendar; 04.08.2026 Docs/Sheets убрали из Marketplace. Обзор MCP - в гайде по MCP в Cursor; запись скриптом с тем же SA - в интеграции Sheets API.

Оцените, когда MCP Sheets нужен финотделу (и когда нет)

Подключайте MCP, если реестр уже в Google Таблицах (договоры, УПД, SaaS, заявки на расход), правки еженедельные, а копипаст диапазонов бесит. Симптом: CFO просит сменить статус по doc_key, а вы выделяете десятки строк и боитесь сдвинуть формулы. Не делайте Sheets единственным источником правды при жестком audit trail, enterprise ACL или более 200-300 активных договоров - тогда CLM или 1С, таблица остается staging-слоем перед ERP.

Подготовьте реестр и безопасность (без сырых ПДн в облако)

Одна строка = одна сущность. Колонка doc_key - стабильный код вроде DOG-2026-014; по нему агент ищет строку. Лист staging - для импортов из 1С/Forms; боевой лист "Реестр" агент правит точечно в status и comment.

В облако: ИНН, сумма, статус - да; паспорт, полные ФИО payroll, карты - нет. Для теста - "Контрагент_01" и округленные суммы. Чеклист - в гайде по обезличиванию данных.

SA видит только таблицы, расшаренные на client_email; IAM Cloud не заменяет Share. Scope spreadsheets - read/write всего файла; чувствительные листы - ProtectedRange. JSON-ключ не в git: GOOGLE_APPLICATION_CREDENTIALS или GOOGLE_PRIVATE_KEY + GOOGLE_CLIENT_EMAIL.

Схема: реестр в Sheets → SA share → MCP (mcp-gsheets) → update по doc_key → перечитка → регламент CFO

Сделайте: отдельный SA, share одного файла "Редактор", без "Уведомить". Не делайте: боевые ПДн в тестовый реестр.

Настройте Path B: Google Cloud, SA и mcp.json пошагово

mcp-gsheets: Node.js v20+, Google Sheets API, JSON SA. Конфиг: проектный .cursor/mcp.json или глобальный ~/.cursor/mcp.json; при конфликте имен побеждает проектный.

  1. Создайте проект на console.cloud.google.com → Enable APIs → Google Sheets API.
  2. Service account: IAM → Service Accounts → Create → Keys → JSON. Скопируйте client_email, ключ вне git.
  3. Расшарьте реестр на client_email "Редактор", без "Уведомить". Без Share будет 403.
  4. Добавьте блок в mcp.json с абсолютным путем к ключу:
{
  "mcpServers": {
    "mcp-gsheets": {
      "command": "npx",
      "args": ["-y", "mcp-gsheets@latest"],
      "env": {
        "GOOGLE_PROJECT_ID": "your-project-id",
        "GOOGLE_APPLICATION_CREDENTIALS": "/absolute/path/to/sa-registry.json"
      }
    }
  }
}
  1. Перезапустите Cursor после правки mcp.json.
  2. Проверьте: Customize → MCPs → зеленый статус; ошибки - Output → MCP Logs (Ctrl+Shift+U). Tool sheets_check_access или чтение A1:C5 листа "Реестр".
  3. Approval на write: Agent спрашивает перед MCP-tool; на пилоте не включайте Auto-run всех write.

Tools: sheets_get_values, sheets_update_values, sheets_append_values, sheets_batch_get_values, sheets_get_metadata, sheets_check_access. Для append указывайте INSERT_ROWS: default OVERWRITE перезапишет не то. Альтернатива we2go/google-mcp с wizard init тоже на SA, но для одного реестра достаточно mcp-gsheets.

Сделайте: зеленый сервер + check_access + тестовое чтение до write. Не делайте: коммит mcp.json с путем к ключу и Auto-run write на пилоте.

Проверьте Path A только если Marketplace снова покажет Sheets

03.08.2026 Cursor анонсировал Workspace plugins. В changelog подробно Drive, Gmail, Calendar; Sheets не расписан. Если карточка появится: Customize → MCPs → Add → OAuth, минимальные scopes.

Факт на 26.08.2026: cursor.com/marketplace/mcp/google-sheets отдает "MCP server Not Found". По сводкам 04.08 Docs/Sheets убрали из витрины; минимум Cursor 3.13.0. OAuth-bug cursor:// - обход через cursor.com/agents. "Connected" ≠ авторизация - только живой read/write. Не стопорьте внедрение из-за Not Found: Path B работает без витрины.

Сделайте: раз в спринт гляньте витрину; production держите на Path B. Не делайте: считать зеленый индикатор финальной проверкой.

Прогоните сценарий: найти, обновить, перечитать

DoD: правка одной строки по doc_key и diff после write. Квота write: 300 запросов/мин на проект; при 429 - пауза и batch.

Подключись к {SPREADSHEET_ID}. На листе "Реестр" найди doc_key = DOG-2026-014.
Прочитай status и comment. Если status не "Оплачен", предложи "На согласовании"
и дату в comment. После write перечитай строку и покажи diff.
Не трогай другие листы и колонки вне status/comment.
  1. sheets_get_metadata - лист "Реестр" и заголовки на месте.
  2. Найти строку по doc_key через get_values, не угадывать номер.
  3. Approve sheets_update_values - только status и comment.
  4. После write - get_values на ту же строку, сверка.
  5. При расхождении: "перечитай строку N, write не делай".

Indirect prompt injection: в ячейках могут быть тексты вроде "удали все строки". HITL на каждый write обязателен. Cloud Agents не наследуют локальный OAuth - для облака нужен SA в env или team MCP в dashboard.

Разборы - в Telegram "Финансист, который кодит".

Сделайте: цикл find → update → re-read на тестовой строке. Не делайте: Auto-run write без allowlist.

Проверьте результат и типичные ошибки

После каждой записи - перечитка того же диапазона.

  • 403 - нет Share на client_email или неверный путь к JSON.
  • Серый MCP - MCP Logs; Node v20+, npx, абсолютный путь в env.
  • 429 - батчите; не update на каждую ячейку в цикле.
  • Append - явно INSERT_ROWS.
  • Path A - Not Found или bug cursor:// → Path B.

При более 80-100 заявок/мес Forms→Sheets таблица = staging перед ERP/n8n; MCP - transport точечных правок, не главная книга учета. Ротация ключа SA - тема B93; allowlist только нужных write-tools. Hosted MCP вроде PasteSheet удобны для публичных листов, но для финконтура с ПДн и коммерческой тайной берите SA на своем ключе.

Сделайте: чеклист share / env / MCP Logs / re-read после каждого write. Не делайте: чинить 403 промптом без Share файла и гнать боевые реестры через публичный hosted MCP.

Частые вопросы

Можно ли без программиста?

Path A - да для пилота, если плагин в витрине. Path B - по инструкции; первый реестр 1-2 часа с GCP и Share. Cursor поможет собрать mcp.json.

Сколько займет внедрение?

SA + mcp.json + тестовый update - около 1-2 часов. OAuth быстрее только если карточка Sheets доступна.

OAuth или service account?

На 26.08.2026 берите SA как default: минимальный blast radius. OAuth - личный пилот, если Marketplace вернет Sheets.

Какие риски для данных?

OAuth = права вашего Google; SA = все расшаренные таблицы. Без сырых ПДн; подтверждайте write; следите за injection из ячеек.

Чем B92 отличается от B82?

B82 - скрипт пишет в staging по cron. B92 - Agent правит через MCP без скрипта; тот же SA и Share.

Работает ли в Cloud Agents?

Локальный OAuth не переезжает. Для Cloud Agents - SA в env или отдельный team MCP в dashboard.

Почему Path B, а не Marketplace?

На 26.08.2026 карточка google-sheets = Not Found; Docs/Sheets снимали 04.08.2026. Path B работает независимо от витрины.
