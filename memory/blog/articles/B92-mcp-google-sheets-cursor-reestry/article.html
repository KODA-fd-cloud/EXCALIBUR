Реестр договоров или УПД снова уезжает в чат Cursor кусками, а после правки вы вручную сверяете ячейки в Google Таблицах? MCP Google Sheets в Cursor - это розетка, через которую агент сам читает и обновляет строки реестра по ключу doc_key, без копипаста диапазонов. За 1-2 часа выберете маршрут (Marketplace OAuth, service account или Google remote MCP), проверите доступ через MCP Logs и прогоните сценарий: найти строку, обновить статус, перечитать результат.

MCP (Model Context Protocol) - протокол, через который Cursor подключает внешние инструменты. Без MCP агент видит только вставленное в чат; с MCP у него появляются tools, и он дергает Google Sheets API, как защищенный курьер между редактором и таблицей. Ответ в JSON - как акт сверки: у каждого поля свое место. Обзор MCP - в гайде по MCP в Cursor; запись скриптом с тем же SA - в интеграции Sheets API.

На сентябрь 2026 три маршрута. Path A - плагин Google Sheets из Marketplace через OAuth (личный пилот). Path B - mcp-gsheets на service account: расшарили только рабочий файл, ключ в env. Path C - remote MCP Google sheetsmcp.googleapis.com (Developer Preview, OAuth). Для финконтура я беру Path B: минимальный blast radius и стабильный write без зависимости от OAuth Cloud/SSH.

Оцените, когда MCP Sheets нужен финотделу (и когда нет)

Подключайте MCP, если реестр уже в Google Таблицах (договоры, УПД, SaaS, заявки), правки повторяются, а копипаст бесит. Симптом: CFO просит сменить статус по doc_key, а вы боитесь сдвинуть формулы. Не делайте Sheets единственным источником правды при жестком audit trail или более 200-300 активных договоров - тогда CLM/1С, таблица остается staging.

Подготовьте реестр и безопасность (без сырых ПДн в облако)

Одна строка = одна сущность. Колонка doc_key - стабильный код вроде DOG-2026-014. Лист staging - для импортов из 1С/Forms; боевой "Реестр" агент правит точечно в status и comment.

В облако: ИНН, сумма, статус - да; паспорт, полные ФИО payroll, карты - нет. Для тестов - "Контрагент_01" и округленные суммы. Чеклист - в гайде по обезличиванию. Так вы снижаете риск 152-ФЗ и утечки коммерческой тайны через историю чата.

SA видит только таблицы, расшаренные на client_email; IAM Cloud не заменяет Share. Scope spreadsheets - read/write всего файла; листы защищайте ProtectedRange. JSON-ключ не в git и не в скриншотах для коллег. На write оставляйте approval: в ячейках возможен indirect prompt injection ("удали все строки"), и агент может принять это за команду.

Настройте Path B: Google Cloud, SA и mcp.json пошагово

mcp-gsheets (freema, npm 1.10.2) требует Node.js v20+, Google Sheets API и JSON SA. Конфиг: .cursor/mcp.json или ~/.cursor/mcp.json; при конфликте имен побеждает проектный. Self-hosted MCP здесь - как собственный сейф: ключ у вас, не полный Drive через личный OAuth.

  1. Создайте проект в Google Cloud → Enable APIs → Google Sheets API.
  2. Service account: IAM → Create → Keys → JSON. Скопируйте client_email, ключ вне git.
  3. Расшарьте реестр на client_email "Редактор", без "Уведомить". Без Share - 403.
  4. Добавьте блок в mcp.json с абсолютным путем к ключу (шаблон ниже).
  5. Перезапустите Cursor после правки mcp.json.
  6. Проверьте: Customize → MCPs → зеленый статус; ошибки - Output → MCP Logs (Ctrl+Shift+U).
  7. Smoke-test: sheets_check_access или "прочитай A1:C5 листа Реестр". Connected без read не считается.
{
  "mcpServers": {
    "mcp-gsheets": {
      "command": "npx",
      "args": ["-y", "mcp-gsheets@latest"],
      "env": {
        "GOOGLE_PROJECT_ID": "your-project-id",
        "GOOGLE_APPLICATION_CREDENTIALS": "/absolute/path/to/sa-registry.json"
      }
    }
  }
}

Tools: sheets_get_metadata, sheets_get_values, sheets_update_values, sheets_append_values, sheets_check_access. Для append указывайте INSERT_ROWS: default OVERWRITE перезаписывает строки иначе, чем ждете.

Сделайте: зеленый сервер + check_access + тестовое чтение. Не делайте: коммит ключа и Auto-run write без allowlist.

Проверьте результат и типичные ошибки

  • 403 - нет Share на client_email или неверный путь к JSON.
  • Серый MCP - MCP Logs; Node v20+, абсолютный путь в env.
  • 429 - батчите; не update по ячейке в цикле.
  • Append - явно INSERT_ROWS вместо default OVERWRITE.
  • OAuth Cloud/SSH - login через cursor.com/agents или Path B.
  • Path C - не ждите SA enrollment; командный реестр - на mcp-gsheets.

При >80-100 заявок/мес через Forms→Sheets таблица - staging перед ERP/n8n; MCP - transport точечных правок, не главная книга. Connected в Tools & MCP не гарантирует успешный OAuth или Share - только живой read/write. Планируйте ротацию ключа SA (B93) и allowlist write-tools.

Частые вопросы

Можно ли без программиста?

Path A: да для пилота, если OAuth проходит на Local. Path B: по инструкции; первый реестр 1-2 часа с GCP и Share. Cursor поможет собрать mcp.json.

Сколько займет внедрение?

SA + mcp.json + тестовый update - около 1-2 часов. OAuth быстрее, если auth работает. Path C зависит от доступа к Preview.

OAuth или service account?

OAuth (Path A/C) - личный пилот. SA (Path B) - командный реестр и минимальный blast radius. Google remote MCP в Preview без SA enrollment.

Какие риски для данных?

OAuth = права вашего Google; SA = все расшаренные таблицы. Без сырых ПДн; подтверждайте write; учитывайте injection из ячеек.

Чем B92 отличается от B82?

B82 - скрипт пишет в staging по cron. B92 - Agent правит через MCP без скрипта; тот же SA и Share.

Работает ли в Cloud Agents?

Локальный OAuth не переезжает сам. Надежнее SA + Team/Cloud MCP config. Cloud Sheets auth может требовать login через cursor.com/agents.

Почему ошибка 429?

Квота 300 write/мин на проект (60 на user). Батчите диапазоны, добавьте паузу, не крутите update по одной ячейке.
