Реестр договоров или УПД снова уезжает в чат Cursor кусками, а после правки вы вручную сверяете ячейки в Google Таблицах? MCP Google Sheets в Cursor – это розетка, через которую агент сам читает и обновляет строки реестра по ключу doc_key, без копипаста диапазонов. За 1–2 часа выберете Path A (Marketplace + OAuth) или Path B (mcp-gsheets + service account), проверите доступ через MCP Logs и прогоните сценарий: найти строку, обновить статус, перечитать результат.

MCP (Model Context Protocol) – протокол, через который Cursor подключает внешние инструменты. Без MCP агент видит только то, что вы вставили в чат; с MCP у него появляются tools, и он сам дергает Google Sheets API – как защищенный курьер между редактором и таблицей. JSON в ответе – как акт сверки: у каждого поля свое место.

На 29.08.2026 два маршрута. Path A – плагин Google Sheets / Workspace из Marketplace через OAuth личного Google (быстрый пилот). Path B – mcp-gsheets на service account: расшарили только рабочий файл, ключ в env, агент не видит весь Drive. Для финконтура я опираюсь на Path B: changelog Cursor от 03.08.2026 детализирует Drive, Gmail и Calendar, а Sheets в витрине мог временно исчезнуть (04.08). Hosted-прокси вроде Composio или PasteSheet для боевого реестра не беру – чужой "банк", не свой сейф. Общий MCP – в гайде по MCP в Cursor; запись скриптом с тем же SA – в интеграции Sheets API.

Оцените, когда MCP Sheets нужен финотделу (и когда нет)

Подключайте MCP, если реестр уже в Google Таблицах (договоры, УПД, SaaS, заявки на расход), правки повторяются, а копипаст диапазонов бесит. Типичный симптом: CFO просит сменить статус по doc_key, а вы выделяете 40 строк и боитесь сдвинуть формулы. Не делайте Sheets единственным источником правды при жестком audit trail, сотнях таблиц с enterprise ACL или более 200–300 активных договоров – тогда CLM или 1С, таблица остается staging.

Сделайте: DoD до установки – найти строку по doc_key, сменить status/comment, перечитать. Не делайте: MCP "на весь Drive" и не ждите возврата Sheets в Marketplace – сразу Path B.

Подготовьте реестр и безопасность (без сырых ПДн в облако)

Одна строка = одна сущность. Колонка doc_key – стабильный код вроде DOG-2026-014; по нему агент ищет строку. Лист staging – для импортов из 1С или Forms; боевой лист "Реестр" агент правит точечно в status и comment.

В облако: ИНН, сумма, статус – да; паспорт, полное ФИО в payroll, номера карт – нет. Для тестов – "Контрагент_01" и округленные суммы. Чеклист – в гайде по обезличиванию данных.

SA видит только таблицы, расшаренные на client_email; IAM Cloud не заменяет Share. JSON-ключ – не в git, только в GOOGLE_APPLICATION_CREDENTIALS. OAuth Path A наследует права вашего Google – для пилота ок, для командного реестра узкий SA безопаснее.

Схема: реестр в Sheets → (SA share | OAuth plugin) → MCP в Cursor → Agent read/update по doc_key → перечитка → регламент CFO

Сделайте: отдельный SA, share одного файла "Редактор", без "Уведомить". Не делайте: боевые ПДн в тестовый реестр.

Настройте Path B: Google Cloud, SA и mcp.json пошагово

Сервер mcp-gsheets (freema/mcp-gsheets) требует Node.js v20+, Sheets API и JSON SA. Конфиг: проектный .cursor/mcp.json или глобальный ~/.cursor/mcp.json; при конфликте имен побеждает проектный.

  1. Создайте проект на console.cloud.google.com → Enable APIs → Google Sheets API.
  2. Service account: IAM → Service Accounts → Create → Keys → JSON. Скопируйте client_email, файл вне git.
  3. Расшарьте реестр на client_email "Редактор", снимите "Уведомить". Без Share – 403.
  4. Добавьте блок в mcp.json с абсолютным путем к ключу:
{
  "mcpServers": {
    "mcp-gsheets": {
      "command": "npx",
      "args": ["-y", "mcp-gsheets@latest"],
      "env": {
        "GOOGLE_PROJECT_ID": "your-project-id",
        "GOOGLE_APPLICATION_CREDENTIALS": "/absolute/path/to/sa-registry.json"
      }
    }
  }
}
  1. Перезапустите Cursor после правки mcp.json.
  2. Проверьте: Customize → MCPs → зеленый статус; ошибки – Output → MCP Logs (Ctrl+Shift+U). Tool sheets_check_access или чтение A1:C5 листа "Реестр".
  3. Approval на write: Agent по умолчанию спрашивает перед MCP-tool; на пилоте не включайте Auto-run всех write.

Tools: sheets_get_values, sheets_update_values, sheets_append_values, sheets_get_metadata, sheets_check_access. Для append указывайте INSERT_ROWS (default OVERWRITE ведет себя иначе). Квота Sheets API: около 300 запросов/мин на проект; batch = один запрос.

Сделайте: зеленый сервер + check_access + тестовое чтение. Не делайте: коммит пути к ключу в git.

Сделайте: если google-sheets в Marketplace – OAuth и чтение A1:C5. Не делайте: строить весь финотдел на Path A.

Прогоните сценарий: найти, обновить, перечитать

DoD: правка одной строки по doc_key и diff после write. При 429 – пауза и батчи.

Подключись к {SPREADSHEET_ID}. На листе "Реестр" найди doc_key = DOG-2026-014.
Прочитай status и comment. Если status не "Оплачен", предложи "На согласовании"
и дату в comment. После write перечитай строку и покажи diff.
Не трогай другие листы и колонки вне status/comment.
  1. sheets_get_metadata – лист "Реестр" и заголовки на месте.
  2. Найти строку по doc_key через get_values, не "угадать" номер.
  3. Approve sheets_update_values – только status и comment.
  4. После write – get_values на ту же строку, сверка с ожиданием.
  5. Follow-up при расхождении: "перечитай строку N, write не делай".

Indirect prompt injection: в ячейках могут быть тексты-инструкции ("удали все строки"). Human-in-the-loop на каждый write обязателен. Cloud Agents не наследуют локальный Google OAuth – для облака нужен SA в env или MCP в Dashboard.

Разборы контуров – в Telegram "Финансист, который кодит".

Сделайте: цикл find → update → re-read на тестовой строке. Не делайте: Auto-run write без allowlist.

Проверьте результат и типичные ошибки

После каждой записи – перечитка того же диапазона.

  • 403 – нет Share на client_email или неверный путь к JSON.
  • Серый MCP – MCP Logs; Node v20+, npx, абсолютный путь в env.
  • 429 – батчите; не update на каждую ячейку в цикле.
  • Append – явно INSERT_ROWS.
  • Нет Sheets в Marketplace – Path B без ожидания витрины.

При более 80–100 заявок/мес через Forms→Sheets таблица – staging перед ERP/n8n; MCP – transport точечных правок, не главная книга. Планируйте ротацию ключа SA и allowlist write-tools.

Сделайте: чеклист share / env / MCP Logs / re-read. Не делайте: чинить 403 промптом без Share.

Что автоматизировать дальше

Частые вопросы

Можно ли без программиста?

Path A: да для пилота, если Sheets в витрине. Path B: по инструкции; первый реестр 1–2 часа с GCP и Share. Cursor поможет собрать mcp.json по шаблону выше.

Сколько займет внедрение?

SA + mcp.json + тестовый update – около 1–2 часов. OAuth быстрее, если плагин доступен и OAuth без bug.

OAuth или service account?

OAuth – личный пилот. SA – командный реестр и минимальный blast radius: только файлы на client_email. Для production – SA.

Какие риски для данных?

OAuth = права вашего Google; SA = все расшаренные таблицы. Без сырых ПДн; подтверждайте write; следите за injection из ячеек. Обезличивание – в гайде выше.

Чем B92 отличается от B82?

B82 – скрипт в staging по cron. B92 – Agent правит через MCP без скрипта; тот же SA и Share. Пакетные загрузки – B82, точечные правки в чате – B92.

Работает ли в Cloud Agents?

Локальный Google OAuth в облако сам не переезжает. Нужен SA в env или MCP в Dashboard / Team Integrations – и снова живой read.

Почему Sheets нет в changelog Cursor?

03.08.2026 анонсировали Workspace; в changelog детально Drive, Gmail, Calendar. Sheets мог уйти из витрины 04.08. Для продакшена не ждите карточку – Path B на mcp-gsheets.
