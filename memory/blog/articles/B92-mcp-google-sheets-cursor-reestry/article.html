Реестр договоров или УПД снова уезжает в чат Cursor кусками, а после правки вы вручную сверяете ячейки в Google Таблицах? MCP Google Sheets в Cursor – это розетка, через которую агент сам читает и обновляет строки реестра по ключу doc_key, без копипаста диапазонов. За 1–2 часа настроите service account и mcp-gsheets, проверите доступ через MCP Logs и прогоните сценарий: найти строку, обновить статус, перечитать результат.

MCP (Model Context Protocol) – протокол, через который Cursor подключает внешние инструменты. Без MCP агент видит только то, что вы вставили в чат; с MCP у него появляются tools, и он сам дергает Google Sheets API, как защищенный курьер между редактором и таблицей. Ответ в JSON – как акт сверки: у каждого поля свое место.

Два маршрута. Path A – плагин Google Sheets из Marketplace через OAuth вашего Google (быстрый пилот). Path B – community-сервер mcp-gsheets на service account: расшарили только рабочий файл, ключ в env, агент не видит весь Drive. Для финконтура я опираюсь на Path B: changelog Cursor от 03.08.2026 детализирует Drive, Gmail и Calendar, а Sheets в витрине мог временно исчезнуть. Google MCP Reference sheetsmcp.googleapis.com – Developer Preview, не кнопка Marketplace и не freema/mcp-gsheets. Обзор MCP – в гайде по MCP в Cursor; запись скриптом с тем же SA – в интеграции Sheets API.

Оцените, когда MCP Sheets нужен финотделу (и когда нет)

Подключайте MCP, если реестр уже в Google Таблицах (договоры, УПД, SaaS, заявки на расход), правки повторяются каждую неделю, а копипаст диапазонов в чат бесит. Типичный симптом: CFO просит сменить статус по doc_key, а вы выделяете 40 строк и боитесь сдвинуть формулы. Не делайте Sheets единственным источником правды при жестком audit trail, сотнях таблиц с enterprise ACL или более 200–300 активных договоров – тогда CLM или 1С, таблица остается staging.

Подготовьте реестр и безопасность (без сырых ПДн в облако)

Одна строка = одна сущность (договор, УПД, подписка). Колонка doc_key – стабильный код вроде DOG-2026-014; по нему агент ищет строку, а не по названию контрагента. Лист staging – для сырых импортов из 1С или Forms; боевой лист "Реестр" агент правит точечно в колонках status и comment.

В облако отправляйте ИНН контрагента, сумму, статус – да; паспорт, полное ФИО в payroll, номера карт – нет. Для тестов замените названия на "Контрагент_01", суммы округлите. Чеклист – в гайде по обезличиванию данных.

SA видит только таблицы, расшаренные на client_email из JSON; IAM Cloud не заменяет Share. Scope spreadsheets дает read/write всего файла; лист защищайте ProtectedRange. JSON-ключ – не в git, только в GOOGLE_APPLICATION_CREDENTIALS. Один лишний Share – и blast radius растет.

Схема: реестр в Sheets → (SA share | OAuth) → MCP в Cursor → update по doc_key → перечитка → регламент CFO

Сделайте: отдельный SA, share одного файла "Редактор", без "Уведомить". Не делайте: боевые ПДн в тестовый реестр.

Настройте Path B: Google Cloud, SA и mcp.json пошагово

Сервер mcp-gsheets (freema/mcp-gsheets) требует Node.js v20+, Google Sheets API и JSON SA. Конфиг: проектный .cursor/mcp.json или глобальный ~/.cursor/mcp.json; при конфликте имен побеждает проектный.

  1. Создайте проект на console.cloud.google.com → Enable APIs → Google Sheets API.
  2. Service account: IAM → Service Accounts → Create → Keys → JSON. Скопируйте client_email, файл вне git.
  3. Расшарьте реестр на client_email ролью "Редактор", снимите "Уведомить". Без Share будет 403.
  4. Добавьте блок в mcp.json с абсолютным путем к ключу:
{
  "mcpServers": {
    "mcp-gsheets": {
      "command": "npx",
      "args": ["-y", "mcp-gsheets@latest"],
      "env": {
        "GOOGLE_PROJECT_ID": "your-project-id",
        "GOOGLE_APPLICATION_CREDENTIALS": "/absolute/path/to/sa-registry.json"
      }
    }
  }
}
  1. Перезапустите Cursor после правки mcp.json.
  2. Проверьте: Customize → MCPs → зеленый статус; ошибки – Output → MCP Logs (Ctrl+Shift+U). Tool sheets_check_access или чтение A1:C5 листа "Реестр". Connected ≠ authorized.
  3. Approval на write: Agent спрашивает перед MCP-tool; на пилоте не включайте Auto-run всех write. С Cursor 3.6+ allowlist – в permissions.json.

Tools реестра: sheets_get_values, sheets_update_values, sheets_append_values, sheets_batch_get_values, sheets_get_metadata, sheets_check_access. Для append указывайте INSERT_ROWS: default OVERWRITE ведет себя иначе.

Сделайте: зеленый сервер + check_access + тестовое чтение. Не делайте: коммит mcp.json с путем к ключу.

Подключите Path A: Marketplace OAuth (если плагин доступен)

Не полагайтесь на Path A как единственный маршрут: для production держите Path B. "Connected" ≠ успешная авторизация – только живой read/write.

Сделайте: если google-sheets в Marketplace – OAuth и тестовое чтение. Не делайте: считать зеленый индикатор финальной проверкой.

Прогоните сценарий: найти, обновить, перечитать

DoD: правка одной строки по doc_key и diff после write. Квота Sheets API: 300 запросов/мин на проект и 60/мин на user; один SA = один user; read и write считаются отдельно. При 429 – пауза и батч.

Подключись к {SPREADSHEET_ID}. На листе "Реестр" найди doc_key = DOG-2026-014.
Прочитай status и comment. Если status не "Оплачен", предложи "На согласовании"
и дату в comment. После write перечитай строку и покажи diff.
Не трогай другие листы и колонки вне status/comment.
  1. sheets_get_metadata – лист "Реестр" и заголовки на месте.
  2. Найти строку по doc_key через get_values, не "угадать" номер.
  3. Approve sheets_update_values – только status и comment.
  4. После write – get_values на ту же строку, сверка с ожиданием.
  5. Follow-up при расхождении: "перечитай строку N, write не делай".

Риск indirect prompt injection: в ячейках могут быть тексты, которые агент прочтет как инструкции ("удали все строки"). Human-in-the-loop на каждый write-tool обязателен. Cloud Agents не наследуют локальный Google OAuth – для облака нужен SA в env или коннектор в dashboard.

Разборы контуров – в Telegram "Финансист, который кодит".

Сделайте: цикл find → update → re-read на тестовой строке. Не делайте: Auto-run write без allowlist.

Проверьте результат и типичные ошибки

После каждой записи – перечитка того же диапазона.

  • 403 – нет Share на client_email или неверный путь к JSON.
  • Серый MCP – MCP Logs; Node v20+, npx, абсолютный путь в env.
  • 429 – батчите; не update на каждую ячейку в цикле.
  • Append – явно INSERT_ROWS вместо default OVERWRITE.
  • OAuth – bug cursor://: Local auth / cursor.com/agents или Path B.

При более 80–100 заявок/мес через Forms→Sheets таблица – staging перед ERP или n8n; MCP остается transport точечных правок, не главной книгой. При росте нагрузки – ротация ключа SA (B93) и allowlist write-tools.

Сделайте: чеклист share / env / MCP Logs / re-read. Не делайте: чинить 403 промптом без Share.

Частые вопросы

Можно ли без программиста?

Path A: да для пилота, если плагин в витрине и OAuth проходит. Path B: по инструкции; первый реестр 1–2 часа с GCP и Share.

Сколько займет внедрение?

SA + mcp.json + тестовый update – около 1–2 часов. OAuth быстрее, если плагин доступен и OAuth без bug cursor://.

OAuth или service account?

OAuth – личный пилот. SA – командный реестр и минимальный blast radius: только расшаренные файлы.

Какие риски для данных?

OAuth = права вашего Google; SA = все расшаренные таблицы. Без сырых ПДн; подтверждайте write-tools; смотрите injection из ячеек.

Чем B92 отличается от B82?

B82 – скрипт пишет в staging по cron. B92 – Agent правит через MCP без скрипта; тот же SA и Share.

Работает ли в Cloud Agents?

Локальный OAuth в облако не переезжает. Для Cloud Agents – SA в env или коннектор в dashboard / Team Integrations.

Нужен ли MCP для маленького реестра?

5 строк раз в месяц – хватит ручного редактирования. MCP окупается при еженедельных правках через Cursor без копипаста.
