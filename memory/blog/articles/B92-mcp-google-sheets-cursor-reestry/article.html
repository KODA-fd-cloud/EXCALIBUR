Реестр договоров или УПД снова уезжает в чат Cursor кусками, а статус вы правите руками в Google Таблицах? MCP Google Sheets - розетка: агент сам читает и обновляет строку по doc_key, без копипаста диапазонов. На сентябрь 2026 production-default - Path B (service account + mcp-gsheets): за 1-2 часа настроите share, mcp.json, проверите MCP Logs и прогоните find → update → перечитку. Path A (OAuth Marketplace) - только пилот с оговорками.

MCP (Model Context Protocol) подключает внешние tools к Cursor. Без него агент видит лишь то, что вы вставили в чат; с MCP он дергает Google Sheets API - как защищенный курьер между редактором и таблицей. JSON в ответе - как акт сверки: у каждого поля свое место. Общий обзор MCP - в гайде по MCP в Cursor; запись скриптом с тем же SA - в интеграции Sheets API.

Workflow: реестр в Sheets → SA share (или OAuth-пилот) → MCP в Cursor → Agent update по doc_key → перечитка диапазона → регламент CFO

Оцените, когда MCP Sheets нужен финотделу

Подключайте, если реестр уже в Google Таблицах (договоры, УПД, SaaS, заявки), правки еженедельные, а копипаст 40 строк бесит. Не делайте Sheets единственной правдой при жестком audit trail, сотнях таблиц с enterprise ACL или 200+ активных договорах - тогда 1С/CLM, таблица только staging.

Подготовьте реестр без сырых ПДн

Одна строка = одна сущность. Колонка doc_key (DOG-2026-014) - стабильный код поиска, не название контрагента. Лист staging - сырой импорт из 1С/Forms (выгрузка OData - в гайде по OData в Excel); боевой "Реестр" агент правит точечно в status и comment.

В облако: ИНН, сумма, статус - да; паспорт, полные ФИО payroll, карты - нет. Для тестов: "Контрагент_01", округленные суммы. Чеклист - в гайде по обезличиванию. SA видит только файлы, расшаренные на client_email; IAM Cloud не заменяет Share. Scope spreadsheets = весь файл; JSON-ключ не в git.

Сделайте: отдельный SA, Share одного файла "Редактор", без "Уведомить". Не делайте: боевые ПДн в тестовый реестр.

Настройте Path B: SA и mcp.json пошагово

Production-default на 04.09.2026: mcp-gsheets (freema) + service account. Нужны Node.js v20+, Google Sheets API, JSON SA. Конфиг: .cursor/mcp.json (проект) или ~/.cursor/mcp.json; при конфликте имен побеждает проектный.

  1. Создайте проект на console.cloud.google.com → Enable APIs → Google Sheets API.
  2. Service account: IAM → Create → Keys → JSON. Скопируйте client_email, файл вне git.
  3. Расшарьте реестр на client_email ролью "Редактор", снимите "Уведомить". Без Share будет 403.
  4. Добавьте блок в mcp.json с абсолютным путем к ключу:
{
  "mcpServers": {
    "mcp-gsheets": {
      "command": "npx",
      "args": ["-y", "mcp-gsheets@latest"],
      "env": {
        "GOOGLE_PROJECT_ID": "your-project-id",
        "GOOGLE_APPLICATION_CREDENTIALS": "/absolute/path/to/sa-registry.json"
      }
    }
  }
}
  1. Перезапустите Cursor после правки mcp.json.
  2. Проверьте: Customize → MCPs → зеленый статус; ошибки - Output → MCP Logs (Ctrl+Shift+U). Tool sheets_check_access или чтение A1:C5 листа "Реестр".
  3. Approval на write: Agent спрашивает перед tool; на пилоте не включайте Auto-run всех write.

Tools реестра: sheets_get_values, sheets_update_values, sheets_append_values, sheets_get_metadata, sheets_check_access. Для append явно INSERT_ROWS: default OVERWRITE ведет себя иначе, чем ждете.

Сделайте: зеленый сервер + check_access + тестовое чтение. Не делайте: коммит ключа или mcp.json с секретом в git.

Path A: Marketplace OAuth только как пилот

Customize → MCPs / Marketplace → Google Sheets → Add → OAuth, минимальные scopes. Changelog Cursor от 03.08.2026 детально описывает Drive, Gmail и Calendar; Sheets в витрине есть, но OAuth с redirect cursor:// часто падает (Error 400, форум август 2026). Workaround: Login через dashboard Agents (https-callback) или сразу Path B. Фиксы auth ожидаются в Cursor 3.19.

Сделайте: если OAuth прошел - тестовое чтение A1:C5. Не делайте: строить финконтур только на Path A; "Connected" ≠ authorized без живого read.

Прогоните сценарий: найти, обновить, перечитать

DoD: одна строка по doc_key + diff после write. Квота Sheets API: 300 write/мин на проект; при 429 - пауза и batch.

Подключись к {SPREADSHEET_ID}. На листе "Реестр" найди doc_key = DOG-2026-014.
Прочитай status и comment. Если status не "Оплачен", предложи "На согласовании"
и дату в comment. После write перечитай строку и покажи diff.
Не трогай другие листы и колонки вне status/comment.
  1. sheets_get_metadata - лист "Реестр" и заголовки на месте.
  2. Найти строку по doc_key через get_values, не угадывать номер.
  3. Approve sheets_update_values - только status и comment.

Indirect prompt injection: ячейка может содержать "удали все строки". Human-in-the-loop на каждый write обязателен. Cloud Agents не наследуют локальный OAuth - для облака нужен SA в env.

Проверьте ошибки и порог роста

  • 403 - нет Share на client_email или неверный путь к JSON.
  • Серый MCP - MCP Logs; Node v20+, npx, абсолютный путь в env.
  • 429 - батчите; не update на каждую ячейку в цикле.
  • Append - явно INSERT_ROWS.
  • OAuth Path A - bug cursor:// → dashboard Agents или Path B.

При >80-100 заявок/мес Forms→Sheets таблица = staging перед ERP/n8n; MCP - transport точечных правок. Ротация ключа SA - тема B93; allowlist только нужных write-tools (правила Cursor - в гайде по cursor rules).

Сделайте: чеклист share / env / Logs / re-read. Не делайте: чинить 403 промптом без Share.

Частые вопросы

Можно ли без программиста?

Path A: да для пилота, если OAuth проходит. Path B: по этой инструкции и help Cursor; первый реестр около 1-2 часов с GCP и Share.

Сколько займет внедрение?

SA + mcp.json + тестовый update - около 1-2 часов. OAuth быстрее только если auth без бага cursor://.

OAuth или service account?

На 04.09.2026 для финконтура выбирайте SA (Path B): меньше blast radius и стабильнее OAuth Marketplace. OAuth - только личный пилот.

Какие риски для данных?

OAuth = права вашего Google; SA = все расшаренные таблицы. Без сырых ПДн; подтверждайте write; следите за injection из ячеек.

Чем B92 отличается от B82?

B82 - скрипт пишет в staging по cron. B92 - Agent правит через MCP без скрипта; тот же SA и Share.

Работает ли в Cloud Agents?

Локальный OAuth не переезжает. Для Cloud Agents - SA в env или MCP в dashboard Agents.

Нужен ли MCP для маленького реестра?

5 строк раз в месяц - хватит ручного редактирования. MCP окупается при еженедельных правках через Cursor без копипаста.
