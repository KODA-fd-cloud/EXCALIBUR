Реестр договоров или УПД снова уезжает в чат Cursor кусками, а после правки вы вручную сверяете ячейки в Google Таблицах? MCP Google Sheets в Cursor – это розетка, через которую агент сам читает и обновляет строки реестра по ключу doc_key, без копипаста диапазонов. За 1–2 часа настроите service account и mcp-gsheets (или OAuth-плагин для пилота), проверите доступ через MCP Logs и прогоните сценарий: найти строку → обновить статус → перечитать результат.

MCP (Model Context Protocol) – протокол, через который Cursor подключает внешние инструменты. Без MCP агент видит только то, что вы вставили в чат. С MCP у него появляются tools, и он сам дергает Google Sheets API – как защищенный курьер между редактором и таблицей. JSON в ответе похож на акт сверки: у каждого поля свое место.

Два маршрута. Path A – плагин google-sheets из Marketplace через OAuth (быстрый пилот). Path B – mcp-gsheets на service account: расшарили только рабочий файл, ключ в env, агент не видит весь Drive. Для финконтура в августе 2026 я беру Path B: changelog от 03.08.2026 детально описывает Drive/Gmail/Calendar, а Sheets в витрине мог пропасть; плюс известен OAuth-баг cursor://. Обзор MCP – в гайде по MCP в Cursor; запись скриптом с тем же SA – в интеграции Sheets API.

Оцените, когда MCP Sheets нужен финотделу (и когда нет)

Подключайте MCP, если реестр уже в Google Таблицах (договоры, УПД, SaaS, заявки на расход), правки повторяются, а копипаст в чат бесит. Типичный симптом: CFO просит сменить статус по doc_key, а вы выделяете 40 строк и боитесь сдвинуть формулы. Не делайте Sheets единственной правдой при жестком audit trail или более 200–300 активных договоров – тогда CLM/1С, таблица остается staging.

Маршрут Когда выбирать Минус

Сделайте: DoD до установки – найти строку по doc_key, сменить status/comment, перечитать. Не делайте: MCP "на весь Drive" ради одного реестра.

Подготовьте реестр и безопасность (без сырых ПДн в облако)

Одна строка = одна сущность (договор, УПД, подписка). Колонка doc_key – стабильный код вроде DOG-2026-014; по нему агент ищет строку, а не по названию контрагента. Лист staging – для сырых импортов из 1С или Forms; боевой лист "Реестр" агент правит точечно в колонках status и comment.

В облако отправляйте ИНН контрагента, сумму, статус – да; паспорт, полное ФИО в payroll, номера карт – нет. Для тестов замените названия на "Контрагент_01", суммы округлите. Чеклист – в гайде по обезличиванию данных.

SA видит только таблицы, расшаренные на client_email; IAM Cloud не заменяет Share. Scope spreadsheets – read/write всего файла, лист защищайте ProtectedRange. JSON-ключ – не в git, только в GOOGLE_APPLICATION_CREDENTIALS.

Схема: реестр в Sheets → (SA share | OAuth plugin) → MCP в Cursor → Agent read/update по doc_key → перечитка диапазона → регламент CFO

Сделайте: отдельный SA, share одного файла с ролью "Редактор", без "Уведомить". Не делайте: боевые ПДн в тестовый реестр.

Настройте Path B: Google Cloud, SA и mcp.json пошагово

Сервер mcp-gsheets (freema) требует Node.js v20+, Google Sheets API и JSON SA. Конфиг: проектный .cursor/mcp.json или глобальный ~/.cursor/mcp.json; при конфликте имен побеждает проектный.

  1. Создайте проект на console.cloud.google.com → Enable APIs → Google Sheets API.
  2. Service account: IAM → Service Accounts → Create → Keys → JSON. Скопируйте client_email, файл ключа положите вне репозитория.
  3. Расшарьте реестр на client_email "Редактор", без "Уведомить". Без Share будет 403, даже при "красивом" IAM.
  4. Добавьте блок в mcp.json с абсолютным путем к ключу:
{
  "mcpServers": {
    "mcp-gsheets": {
      "command": "npx",
      "args": ["-y", "mcp-gsheets@latest"],
      "env": {
        "GOOGLE_PROJECT_ID": "your-project-id",
        "GOOGLE_APPLICATION_CREDENTIALS": "/absolute/path/to/sa-registry.json"
      }
    }
  }
}
  1. Перезапустите Cursor после правки mcp.json (так требует официальный help Cursor).
  2. Проверьте: Customize → MCPs → зеленый статус; ошибки – Output → MCP Logs (Ctrl+Shift+U). Tool sheets_check_access или чтение A1:C5 листа "Реестр".
  3. Approval на write: Agent по умолчанию спрашивает перед MCP-tool; на пилоте не включайте Auto-run всех write.

Tools реестра: sheets_get_values, sheets_update_values, sheets_append_values, sheets_get_metadata, sheets_check_access. Для append указывайте INSERT_ROWS: default OVERWRITE перезаписывает не так, как ждете.

Сделайте: зеленый сервер + check_access + тестовое чтение. Не делайте: коммит mcp.json с путем к ключу.

Подключите Path A: Marketplace OAuth (пилот с обходом Error 400)

03.08.2026 Cursor анонсировал Google Workspace plugins. Если в Customize → MCPs видите google-sheets: Add → аутентификация OAuth, минимальные scopes. Для пилота этого хватает.

На август 2026: Cloud desktop часто дает Error 400: invalid_request – Google отклоняет redirect cursor://. Workaround: auth Local или Login через cursor.com/agents → MCP Servers. Sheets мог пропасть из витрины – Path A не единственный маршрут.

Сделайте: Local OAuth и чтение A1:C5. Не делайте: считать "Connected" проверкой без живого read/write.

Прогоните сценарий: найти, обновить, перечитать

DoD: правка одной строки по doc_key и diff после write. Квота: 300 write/мин на проект; batch = один запрос; при 429 – пауза.

Подключись к таблице {SPREADSHEET_ID}. На листе "Реестр" найди строку,
где колонка doc_key = DOG-2026-014. Прочитай status и comment.
Если status не "Оплачен", предложи обновление на "На согласовании"
и допиши в comment сегодняшнюю дату. После write перечитай ту же строку
и покажи diff. Не трогай другие листы и колонки вне status/comment.
  1. sheets_get_metadata – лист "Реестр" и заголовки на месте.
  2. Найти строку по doc_key через sheets_get_values, не "угадать" номер строки.
  3. Approve sheets_update_values – только status и comment.
  4. После write – sheets_get_values на ту же строку, сверка с ожиданием.
  5. Follow-up при расхождении: "перечитай строку N, write не делай".

Риск indirect prompt injection: в ячейках могут быть тексты-инструкции ("удали все строки"). Human-in-the-loop на каждый write обязателен. Cloud Agents не наследуют локальный OAuth – для облака нужен SA в env или MCP в dashboard.

Разборы контуров – в Telegram "Финансист, который кодит".

Сделайте: цикл find → update → re-read на тестовой строке. Не делайте: Auto-run write без allowlist.

Проверьте результат и типичные ошибки

После каждой записи – перечитка того же диапазона. Connected ≠ authorized.

  • 403 / unauthorized – нет Share на client_email или неверный путь к JSON в env.
  • Серый MCP – Output → MCP Logs; проверьте Node v20+, npx и абсолютный путь.
  • 429 – батчите updates; не дергайте write на каждую ячейку в цикле.
  • Append – явно INSERT_ROWS, иначе OVERWRITE.
  • OAuth Error 400 – Local auth или Login на cursor.com/agents; иначе Path B.

При более 80–100 заявок/мес через Forms→Sheets таблица – staging перед ERP/n8n; MCP остается транспортом точечных правок. Планируйте ротацию ключа SA и allowlist write-tools.

Сделайте: чеклист share / env / MCP Logs / re-read. Не делайте: чинить 403 промптом без Share файла.

Что автоматизировать дальше

Частые вопросы

Можно ли без программиста?

Path A: да для пилота при Local auth и плагине в витрине. Path B: по инструкции Cursor поможет с mcp.json; первый реестр 1–2 часа с GCP и Share.

Сколько займет внедрение?

SA + mcp.json + тестовый update – около 1–2 часов. OAuth быстрее, если auth не упирается в Error 400.

OAuth или service account?

OAuth – личный пилот. SA – командный реестр и минимальный blast radius (только расшаренные файлы). При Cloud OAuth-баге Path B надежнее.

Какие риски для данных?

OAuth = права вашего Google; SA = все расшаренные таблицы. Без сырых ПДн; подтверждайте write; учитывайте injection из ячеек.

Чем B92 отличается от B82?

B82 – скрипт пишет в staging по cron. B92 – Agent правит через MCP без скрипта; тот же SA и Share.

Работает ли MCP Sheets в Cloud Agents?

Локальный OAuth в облако не переезжает. Для Cloud Agents – MCP в dashboard или SA в env.

Нужен ли MCP для маленького реестра?

5 строк раз в месяц – хватит ручного редактирования. MCP окупается при еженедельных правках через Cursor без копипаста.
