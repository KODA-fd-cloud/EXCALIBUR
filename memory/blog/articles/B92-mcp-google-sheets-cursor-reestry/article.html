Реестр договоров или УПД снова уезжает в чат Cursor кусками, а после правки вы вручную сверяете ячейки в Google Таблицах? MCP Google Sheets в Cursor – это розетка, через которую агент сам читает и обновляет строки реестра по ключу doc_key, без копипаста диапазонов. За 1–2 часа настроите service account и mcp-gsheets, проверите доступ через MCP Logs и прогоните сценарий: найти строку, обновить статус, перечитать результат.

MCP (Model Context Protocol) – протокол внешних инструментов Cursor. Без MCP агент видит только вставленный в чат текст; с MCP появляются tools, и он дергает Google Sheets API – как защищенный курьер между редактором и таблицей. JSON в ответе – как акт сверки: у каждого поля свое место.

Два маршрута. Path A – плагин google-sheets из Marketplace через OAuth (пилот на Local). Path B – mcp-gsheets на service account: share только нужного файла, ключ в env. Для финконтура на сентябрь 2026 я беру Path B: changelog Cursor детализирует Drive, Gmail и Calendar; Sheets чаще в анонсах; Cloud OAuth с cursor:// часто падает. Обзор MCP – в гайде по MCP в Cursor; скрипт с тем же SA – в интеграции Sheets API.

Оцените, когда MCP Sheets нужен финотделу (и когда нет)

Подключайте MCP, если реестр уже в Sheets (договоры, УПД, SaaS, заявки), правки еженедельные, копипаст бесит. Типичный запрос: "найди DOG-2026-014 и поставь статус На согласовании" – без скриншотов диапазона в чат. Не делайте Sheets единственным источником при жестком audit trail, enterprise ACL или более 200–300 активных договоров – тогда CLM/1С, таблица остается staging.

Зафиксируйте DoD: одна правка, одна перечитка. Меньше пяти правок в неделю – MCP избыточен. Пакет из 1С по cron – скрипт B82, не Agent.

Маршрут Когда выбирать Минус
Path A: Marketplace + OAuth Личный пилот Local Права вашего Google; Cloud auth часто ломается
Path B: mcp-gsheets + SA Командный реестр, production GCP-проект и JSON-ключ вне git
Копипаст в чат Разовая правка 5 строк Нет перечитки, риск ПДн в истории
Python-скрипт (B82) Cron, пакет из 1С Нет интерактивных правок через Agent
Вердикт: реестр в Sheets + правки через Cursor – MCP убирает копипаст. No-code – в автоматизации финансов без кода.

Сделайте: DoD: найти по doc_key, сменить status/comment, перечитать. Не делайте: MCP "на весь Drive" ради одного реестра.

Подготовьте реестр и безопасность (без сырых ПДн в облако)

Одна строка = одна сущность. Колонка doc_key – стабильный код (DOG-2026-014). Лист staging – сырые импорты; боевой "Реестр" агент правит только в status и comment. Заголовки без хвостов пробелов – иначе tool не найдет колонку.

В облако: ИНН, сумма, статус – да; паспорт, полное ФИО payroll, карты – нет. Для тестов: "Контрагент_01", округленные суммы; 10–20 строк в "Реестр_тест". Чеклист – в гайде по обезличиванию.

SA видит только таблицы, расшаренные на client_email; IAM не заменяет Share. Критичные листы – ProtectedRange. JSON-ключ не в git и не в чат – только путь в GOOGLE_APPLICATION_CREDENTIALS. Отдельный SA на финреестры, Share "Редактор" на один spreadsheet_id.

Схема: реестр → (SA share | OAuth Local) → MCP в Cursor → update по doc_key → перечитка → регламент CFO

Сделайте: отдельный SA, share "Редактор", без "Уведомить". Не делайте: боевые ПДн в тестовый реестр.

Настройте Path B: Google Cloud, SA и mcp.json пошагово

mcp-gsheets (freema) нужен Node.js v20+, Google Sheets API и JSON SA. Конфиг: .cursor/mcp.json или ~/.cursor/mcp.json; при конфликте имен побеждает проектный.

  1. Создайте проект на console.cloud.google.com → APIs & Services → Google Sheets API → Enable. Без Enable tool упадет даже при верном Share.
  2. Service account: IAM → Service Accounts → Create → Keys → JSON. В файле найдите client_email (xxx@project.iam.gserviceaccount.com) – его в Share. Ключ вне git (~/.secrets/).
  3. Расшарьте реестр на client_email "Редактор", снимите "Уведомить". Без Share – 403: IAM файл не открывает.
  4. Добавьте блок в mcp.json с абсолютным путем к ключу:
{
  "mcpServers": {
    "mcp-gsheets": {
      "command": "npx",
      "args": ["-y", "mcp-gsheets@latest"],
      "env": {
        "GOOGLE_PROJECT_ID": "your-project-id",
        "GOOGLE_APPLICATION_CREDENTIALS": "/absolute/path/to/sa-registry.json"
      }
    }
  }
}
  1. Перезапустите Cursor после правки mcp.json.
  2. Проверьте: Customize → MCPs → зеленый статус; ошибки – Output → MCP Logs (Ctrl+Shift+U). Сначала sheets_check_access, затем чтение A1:C5 листа "Реестр".
  3. Approval на write: Agent спрашивает перед tool; на пилоте не включайте Auto-run всех write.

Tools: sheets_get_values, sheets_update_values, sheets_append_values, sheets_batch_get_values, sheets_get_metadata, sheets_check_access. Для append явно INSERT_ROWS – default OVERWRITE может перезаписать хвост листа.

Сделайте: зеленый сервер + check_access + чтение. Не делайте: коммит mcp.json с путем к ключу и самим JSON.

Подключите Path A: Marketplace OAuth (если плагин доступен)

Customize → MCPs → Add → OAuth Local, минимальные scopes. На Cloud/SSH OAuth Sheets часто дает Error 400 на cursor:// – Login через https://cursor.com/agents. "Connected" ≠ авторизация: только живой read/write.

Сделайте: Local OAuth и тестовое чтение, если плагин в витрине. Не делайте: Path A единственным маршрутом для production – держите Path B.

Прогоните сценарий: найти, обновить, перечитать

DoD: правка одной строки по doc_key и diff после write. Квота: 300 req/мин на проект и 60 req/мин на user; один SA = один "user", поэтому агент раньше упрется в 60. При 429 – пауза 30–60 секунд и batch.

Подключись к {SPREADSHEET_ID}. На листе "Реестр" найди doc_key = DOG-2026-014.
Прочитай status и comment. Если status не "Оплачен", предложи "На согласовании"
и дату в comment. После write перечитай строку и покажи diff.
Не трогай другие листы и колонки вне status/comment.
  1. sheets_get_metadata – лист "Реестр" и заголовки doc_key / status / comment на месте.
  2. Найти строку по doc_key через get_values (например A2:F200); запомните номер строки N.
  3. Approve sheets_update_values – только status и comment этой строки.
  4. После write – get_values на ту же строку, например Реестр!C{N}:D{N}.
  5. При расхождении: "перечитай строку N, write не делай" и сверьте в браузере Sheets.

Пример diff: status "Черновик" → "На согласовании"; comment пусто → "2026-09-12 согласовано в Cursor". Чужие колонки – откатите и сузьте промпт. В ячейках бывают инъекции ("удали лист") – human-in-the-loop на write обязателен. Локальный OAuth в Cloud Agents сам не переезжает: SA в dashboard MCP или Login на cursor.com/agents.

Разборы – в Telegram "Финансист, который кодит".

Сделайте: find → update → re-read с явным diff. Не делайте: Auto-run write без allowlist.

Проверьте результат и типичные ошибки

  • 403 – нет Share на client_email, неверный spreadsheet_id или битый путь к JSON. Сначала проверьте Share, потом промпт.
  • Серый MCP – MCP Logs; Node v20+, npx в PATH, абсолютный путь, Enable Sheets API.
  • 429 – батчите чтения; не update ячеек в цикле (лимит 60/user).
  • Append – явно INSERT_ROWS, иначе OVERWRITE перезапишет хвост.
  • OAuth Cloud / Error 400 – cursor.com/agents или Path B.
  • Connected, но read пустой – сделайте живой get_values: UI-статус не равен авторизации.

Ротируйте ключ SA раз в квартал (или после ухода сотрудника): новый JSON → GOOGLE_APPLICATION_CREDENTIALS → удалить старый ключ в GCP. Allowlist write-tools: update/append – да; delete/clear – нет без регламента CFO. При 80–100+ заявок/мес Forms→Sheets – staging перед ERP/n8n.

Сделайте: чеклист share / Enable API / env / MCP Logs / re-read / ротация ключа. Не делайте: чинить 403 промптом без Share.

Что автоматизировать дальше

  1. Path B на одном реестре с doc_key и staging.
  2. Зеленый MCP + check_access + update с перечиткой.
  3. Allowlist write-tools; SA-ключ вне git; ротация ключа.
  4. Соседние реестры (договоры, УПД, SaaS) – MCP поверх таблицы.
  5. При audit – ERP/CLM; cron – скрипт B82.

Частые вопросы

Можно ли без программиста?

Path A: да для пилота Local, если плагин в Marketplace и OAuth проходит. Path B: по инструкции без своего кода; первый реестр 1–2 часа с GCP, Share и тестовым update.

Сколько займет внедрение?

SA + Enable Sheets API + mcp.json + тестовый update – около 1–2 часов. OAuth Local быстрее (15–30 минут), если auth без Error 400.

OAuth или service account?

OAuth Local – личный пилот. SA – командный реестр и стабильный Cloud: только расшаренные файлы, ключ в env, а не весь ваш Google-аккаунт.

Какие риски для данных?

OAuth = права вашего Google; SA = все таблицы на client_email. Без сырых ПДн; подтверждайте write; смотрите injection в ячейках перед массовыми правками.

Чем B92 отличается от B82?

B82 – скрипт пишет в staging по cron. B92 – Agent правит через MCP без скрипта. Share и SA те же: оба контура можно держать на одном ключе.

Работает ли в Cloud Agents?

Локальный OAuth Path A сам не переезжает. Для Cloud – SA в dashboard Cloud Agents / Team MCP либо Login на https://cursor.com/agents, не in-app cursor://.

Почему 429 при правках реестра?

Один SA = один user и лимит 60 req/min. Батчите get_values, backoff после 429, не поллите весь лист в цикле.
