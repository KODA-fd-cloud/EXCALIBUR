Реестр договоров или УПД снова уезжает в чат Cursor кусками, а статусы правятся руками в Google Таблицах? MCP Google Sheets в Cursor – розетка: агент сам читает и обновляет строку по doc_key, без копипаста. За 1–2 часа выберете Path A (Marketplace + OAuth) или Path B (mcp-gsheets + SA), проверите MCP Logs и прогоните: найти строку → обновить статус → перечитать.

MCP (Model Context Protocol) – протокол внешних инструментов Cursor. Без него агент видит только текст из чата; с MCP появляются tools, а Sheets API работает как защищенный курьер к таблице. JSON – как акт сверки: у поля свое место. Для финансиста это разница между "скопировал диапазон в чат" и "агент сам открыл нужную строку реестра".

На 08.09.2026 два маршрута. Path A – плагин google-sheets из Marketplace через OAuth (пилот). Path B – freema/mcp-gsheets на service account: расшарили только реестр, ключ в env. Changelog 03.08.2026 детально описывает Drive, Gmail и Calendar; Sheets есть в Marketplace, но Cloud OAuth часто падает с Error 400 на cursor://. Обзор MCP – в гайде по MCP; тот же SA скриптом – в интеграции Sheets API.

Оцените, когда MCP Sheets нужен финотделу (и когда нет)

Подключайте MCP, если реестр уже в Sheets (договоры, УПД, SaaS, заявки) и правки повторяются каждую неделю. Не делайте Sheets единственным источником при жестком audit trail, enterprise ACL или более 200–300 договоров – тогда CLM/1С, таблица = staging. Разовая правка пяти строк быстрее копипастом; пакет из 1С по cron – скриптом B82. Живые остатки из базы – через MCP к 1С, не через Sheets.

Маршрут Когда выбирать Минус
Path A: Marketplace + OAuth Личный пилот Права вашего Google; Cloud OAuth и serialization баги
Path B: mcp-gsheets + SA Командный реестр, финконтур GCP-проект и JSON-ключ вне git
Копипаст в чат Разовая правка 5 строк Нет перечитки, риск ПДн в истории
Python-скрипт (B82) Cron, пакет из 1С Нет интерактивных правок через Agent
Вердикт: реестр в Sheets + правки через Cursor – MCP. Для production финконтура я беру Path B. No-code – в автоматизации без кода.

Сделайте: DoD до установки: найти по doc_key, сменить status/comment, перечитать. Не делайте: доступ "на весь Drive" ради одного файла.

Подготовьте реестр и безопасность (без сырых ПДн)

Одна строка = одна сущность. Колонка doc_key – код вроде DOG-2026-014. Лист staging – импорты из 1С/Forms; боевой "Реестр" правится точечно в status и comment. Заголовки зафиксируйте: агенту проще искать колонку, чем угадывать "Статус" vs "status".

В облако: ИНН, сумма, статус – да; паспорт, ФИО payroll, карты – нет. Для тестов – "Контрагент_01" и округленные суммы. Чеклист – в гайде по обезличиванию. Даже на пилоте не кладите выписку с реквизитами в ячейку "comment": indirect prompt injection читает и это.

SA видит только таблицы, расшаренные на client_email; IAM не заменяет Share. Scope spreadsheets – read/write всего файла; чувствительные листы – ProtectedRange. JSON-ключ не в git, путь в GOOGLE_APPLICATION_CREDENTIALS. Отдельный SA на финреестры лучше, чем общий "dev-bot" со старыми ключами.

Схема: реестр → (SA share | OAuth) → MCP в Cursor → update по doc_key → перечитка → регламент CFO

Сделайте: отдельный SA, Share одного файла "Редактор", без "Уведомить". Не делайте: боевые ПДн в тестовый реестр.

Настройте Path B: Google Cloud, SA и mcp.json пошагово

mcp-gsheets: Node.js v20+, Sheets API, JSON SA. Конфиг – .cursor/mcp.json или ~/.cursor/mcp.json; при совпадении имени побеждает проектный. Ключ – mcpServers (не VS Code servers). Absolute path к JSON обязателен: относительный часто дает серый статус без понятной ошибки.

  1. Создайте проект в Google Cloud → Enable APIs → Google Sheets API.
  2. Service account: IAM → Create → Keys → JSON. client_email скопируйте; файл вне git.
  3. Расшарьте реестр на client_email "Редактор", снимите "Уведомить". Без Share – 403.
  4. Добавьте блок в mcp.json с абсолютным путем к ключу:
{
  "mcpServers": {
    "mcp-gsheets": {
      "command": "npx",
      "args": ["-y", "mcp-gsheets@latest"],
      "env": {
        "GOOGLE_PROJECT_ID": "your-project-id",
        "GOOGLE_APPLICATION_CREDENTIALS": "/absolute/path/to/sa-registry.json"
      }
    }
  }
}
  1. Перезапустите Cursor после правки mcp.json.
  2. Проверьте: Customize → MCPs → зеленый статус; ошибки – MCP Logs (Ctrl+Shift+U). Tool sheets_check_access или чтение A1:C5.
  3. Approval на write: Agent спрашивает перед MCP-tool; на пилоте не включайте Auto-run всех write.

Tools: sheets_get_values, sheets_update_values, sheets_append_values, sheets_get_metadata, sheets_check_access. Для append явно INSERT_ROWS: default OVERWRITE ведет себя иначе и может затереть соседние строки. Сначала check_access и get_metadata – потом любой write.

Сделайте: зеленый сервер + check_access + тестовое чтение. Не делайте: коммит ключа в git.

Подключите Path A: Marketplace OAuth для пилота

Плагин Google Sheets есть в Marketplace: Customize → MCPs → Add → OAuth, минимальные scopes. Локальный auth обычно ок; Cloud Agents часто падают с Error 400 на cursor:// – Login через cursor.com/agents или сразу Path B. Официальный разбор MCP и Cloud Agents – в справке Cursor по MCP.

Баг update_values: 2D-массив сериализуется в строки → API 400. В промпте: values как JSON-массив массивов; при сбое – retry. "Connected" ≠ authorized: зеленый индикатор не гарантирует валидный токен на write.

Сделайте: OAuth и тестовое чтение на пилоте. Не делайте: считать зеленый индикатор финалом; для командного реестра держите Path B.

Прогоните сценарий: найти, обновить, перечитать

DoD: правка строки по doc_key и diff после write. Квота Sheets API: 300 req/min на проект, 60/min на user; 429 – пауза; batchUpdate = 1 запрос вместо цикла по ячейкам. На пилоте хватит одной тестовой строки DOG-2026-014.

Подключись к {SPREADSHEET_ID}. На листе "Реестр" найди doc_key = DOG-2026-014.
Прочитай status и comment. Если status не "Оплачен", предложи "На согласовании"
и дату в comment. После write перечитай строку и покажи diff.
Параметр values – JSON-массив массивов, не строка.
Не трогай другие листы и колонки вне status/comment.
  1. sheets_get_metadata – лист "Реестр" и заголовки на месте.
  2. Найти строку по doc_key через get_values.
  3. Approve sheets_update_values – только status и comment.
  4. После write – get_values на ту же строку.
  5. При расхождении: "перечитай строку N, write не делай".

Indirect prompt injection: в ячейках бывают тексты-"инструкции". Human-in-the-loop на каждый write обязателен. Cloud Agents не наследуют Desktop OAuth – нужен SA в Team MCP / env. Сценарий find → update → re-read – ваш акт сверки с агентом.

Разборы – в Telegram "Финансист, который кодит".

Сделайте: find → update → re-read на тестовой строке. Не делайте: Auto-run write без allowlist.

Проверьте результат и типичные ошибки

  • 403 – нет Share на client_email или неверный путь к JSON.
  • Серый MCP – MCP Logs; Node v20+, npx, абсолютный путь; ключ mcpServers.
  • 429 – батчите; не update по ячейке в цикле.
  • Append – явно INSERT_ROWS.
  • Serialization 400 – values как массив массивов; retry.
  • Cloud OAuth – Login на cursor.com/agents или Path B с SA.

При >80–100 заявок/мес Forms→Sheets – staging перед ERP или n8n поверх Sheets. Ротируйте ключ SA и держите allowlist write-tools. Если write прошел, а re-read показывает старое значение – не повторяйте update сразу: сначала get_values и сверка диапазона.

Сделайте: чеклист share / env / MCP Logs / re-read. Не делайте: чинить 403 промптом без Share.

Что автоматизировать дальше

  1. Path B на одном реестре с doc_key и staging.
  2. Зеленый MCP + check_access + update с перечиткой.
  3. Allowlist write-tools; SA-ключ вне git.
  4. Соседние реестры (договоры, УПД, SaaS) – MCP поверх таблицы.
  5. При audit – ERP/CLM; cron – скрипт B82; остатки в 1С – MCP к 1С.

Сначала один реестр и стабильный DoD, потом масштабируйте. Материалы – в закрытом клубе KODA.

Частые вопросы

Можно ли без программиста?

Path A: да для пилота, если OAuth проходит. Path B: по инструкции; первый реестр 1–2 часа с GCP и Share. Cursor подскажет JSON, но Share и ключ вне git – ваша зона ответственности.

Сколько займет внедрение?

SA + mcp.json + тестовый update – около 1–2 часов. OAuth быстрее, если auth без Error 400. Если статус серый – сразу MCP Logs, не угадывайте причину.

OAuth или service account?

OAuth – личный пилот. SA – командный реестр, минимальный blast radius; удобнее для Cloud Agents без интерактивного логина. Для production финконтура я выбираю SA.

Какие риски для данных?

OAuth = права вашего Google; SA = все расшаренные таблицы. Без сырых ПДн; подтверждайте write; следите за injection из ячеек. Не давайте Auto-run на sheets_update_values.

Чем B92 отличается от B82?

B82 – скрипт пишет в staging по cron. B92 – Agent правит через MCP без скрипта; тот же SA и Share. Оба маршрута совместимы: cron грузит, Agent точечно правит статус.

Работает ли в Cloud Agents?

Desktop OAuth в облако не переезжает. Нужен SA в env / Team Integrations или Login через cursor.com/agents. На старте проще Path B.

Нужен ли MCP для маленького реестра?

Если правок меньше пяти в неделю – копипаст быстрее. MCP окупается, когда статус и comment правятся регулярно и нужна перечитка без ручного диапазона.
