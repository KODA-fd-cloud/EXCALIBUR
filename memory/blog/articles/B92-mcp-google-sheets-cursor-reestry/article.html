Реестр договоров или УПД снова уезжает в чат Cursor кусками, а после правки вы вручную сверяете ячейки в таблице? MCP Google Sheets - "розетка": агент сам читает и обновляет строки реестра по doc_key без копипаста диапазонов. За 1-2 часа настроите Path B (service account + mcp-gsheets), проверите доступ в MCP Logs и прогоните сценарий: найти строку, обновить статус, перечитать результат.

MCP (Model Context Protocol) - протокол внешних tools в Cursor. Без него агент видит только вставленный в чат текст; с MCP дергает Google Sheets API, как защищенный курьер между редактором и таблицей. JSON - как акт сверки: у каждого поля свое место.

На сентябрь 2026 Path B - production-default: mcp-gsheets (freema) + service account, share только нужного реестра, ключ в env. Path A - Marketplace-плагин google-sheets через OAuth: пилот, но витрина Sheets нестабильна с августа 2026, OAuth из IDE часто ломается на cursor://. Обзор MCP - в гайде MCP Cursor; скрипт с тем же SA - в Sheets API для финотдела.

Подготовьте реестр и безопасность (без сырых ПДн)

Одна строка = одна сущность. Колонка doc_key (DOG-2026-014) - ключ поиска. Лист staging для импортов; "Реестр" правится точечно в status/comment.

В облако: ИНН, сумма, статус - да; паспорт, полное ФИО payroll, карты - нет. Тесты: "Контрагент_01", округленные суммы. Чеклист - в гайде по обезличиванию. SA видит только share на client_email; IAM Cloud не заменяет Share. JSON-ключ не в git.

Настройте Path B: Google Cloud, SA и mcp.json

mcp-gsheets: Node.js v20+, Sheets API, JSON SA. Конфиг: .cursor/mcp.json или ~/.cursor/mcp.json; при конфликте имен побеждает проектный.

  1. Проект на console.cloud.google.com → Enable APIs → Google Sheets API.
  2. Service account: IAM → Create → Keys → JSON. Скопируйте client_email, файл вне git.
  3. Share реестра на client_email "Редактор", снимите "Уведомить". Без Share - 403.
  4. Блок mcp.json с абсолютным путем к ключу:
{
  "mcpServers": {
    "mcp-gsheets": {
      "command": "npx",
      "args": ["-y", "mcp-gsheets@latest"],
      "env": {
        "GOOGLE_PROJECT_ID": "your-project-id",
        "GOOGLE_APPLICATION_CREDENTIALS": "/absolute/path/to/sa-registry.json"
      }
    }
  }
}
  1. Перезапустите Cursor после правки mcp.json.
  2. Проверьте: Customize → MCPs → зеленый; ошибки - Output → MCP Logs (Ctrl+Shift+U). Tool sheets_check_access или чтение A1:C5.
  3. Approval на write: Agent спрашивает перед tool; не включайте Auto-run всех write на пилоте.

Tools: sheets_get_values, sheets_update_values, sheets_append_values, sheets_get_metadata. Для append явно INSERT_ROWS (default OVERWRITE).

Сделайте: зеленый сервер + check_access + чтение. Не делайте: коммит пути к ключу в git.

Проверьте результат и типичные ошибки

  • 403 - нет Share на client_email или путь к JSON.

Частые вопросы

Можно ли без программиста?

Path A: да для пилота, если плагин в витрине и OAuth проходит. Path B: по инструкции; первый реестр ~1-2 ч с GCP и Share.

Сколько займет внедрение?

SA + mcp.json + тестовый update - 1-2 часа. OAuth быстрее, если плагин доступен и без bug cursor://.

OAuth или service account?

OAuth - личный пилот. SA - командный реестр и production на сентябрь 2026: только расшаренные файлы.

Какие риски для данных?

OAuth = права вашего Google; SA = все расшаренные таблицы. Без сырых ПДн; подтверждайте write; смотрите injection из ячеек.

Чем B92 отличается от B82?

B82 - скрипт в staging по cron. B92 - Agent через MCP без скрипта; тот же SA и Share.

Работает ли в Cloud Agents?

Локальный OAuth не переезжает. Нужен SA в env или Login на cursor.com/agents.

Нужен ли MCP для маленького реестра?

5 строк раз в месяц - хватит руками. MCP окупается при еженедельных правках без копипаста.
