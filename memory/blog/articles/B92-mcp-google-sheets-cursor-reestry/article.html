Реестр договоров снова копируете в чат Cursor кусками, а после правки вручную сверяете ячейки в Google Таблицах? MCP Google Sheets – это "розетка", через которую агент сам читает и обновляет строки по ключу doc_key, без копипаста диапазонов. За 1–2 часа выберете путь (официальный remote MCP Google или service account + community-сервер), пропишете mcp.json, прогоните сценарий "найти → обновить статус → перечитать" и закрепите approval на каждый write.

MCP (Model Context Protocol) – протокол, через который Cursor подключает внешние инструменты. Без него агент видит только то, что вы вставили в чат; с MCP у него появляются tools, и он дергает Google Sheets API как защищенный курьер между редактором и таблицей. Ответ в JSON – как акт сверки: у каждого поля свое место.

На 09.09.2026 у финотдела два рабочих маршрута. Path A – официальный remote Google Sheets MCP по URL sheetsmcp.googleapis.com с OAuth вашего Google. Path B – community-сервер (mcp-gsheets или mcp-google-sheets) на service account: расшарили только нужный реестр, ключ в env, агент не видит весь Drive. Не путайте с плагинами Workspace: changelog Cursor от 03.08.2026 подтверждает Drive, Gmail и Calendar; отдельного Sheets cell-editor в Marketplace нет, а Drive MCP не пишет ячейки. Обзор протокола – в гайде по MCP в Cursor; запись скриптом с тем же SA – в интеграции Sheets API.

Оцените, когда MCP Sheets нужен финотделу (и когда нет)

Подключайте MCP, если реестр уже в Google Таблицах (договоры, УПД, SaaS, заявки), правки повторяются каждую неделю, а копипаст бесит. Типичный симптом: CFO просит сменить статус по doc_key, а вы выделяете 40 строк и боитесь сдвинуть формулы. Не делайте Sheets единственным источником правды при жестком audit trail, сотнях таблиц с enterprise ACL или сотнях активных договоров – тогда CLM или 1С, таблица остается staging-слоем.

Маршрут Когда выбирать Минус
Path A: remote Sheets MCP + OAuth Личный пилот, быстрый старт без SA Права вашего Google; нужен enable API в GCP
Path B: mcp-gsheets / mcp-google-sheets + SA Командный реестр, production финконтура GCP-проект, JSON-ключ вне git, Share файла
Копипаст в чат Разовая правка 5 строк Нет перечитки, риск ПДн в истории чата
Python-скрипт (B82) Cron, пакет из 1С Нет интерактивных правок через Agent
Вердикт: если реестр в Sheets и правки идут через Cursor – MCP убирает копипаст. Для пилота на своем аккаунте берите Path A; для командного файла с минимальным blast radius – Path B. No-code-контур – в автоматизации финансов без кода.

Сделайте: до установки зафиксируйте DoD: найти строку по doc_key, сменить status/comment, перечитать. Не делайте: доступ "на весь Drive" ради одного реестра и не ждите "плагин Sheets из Marketplace" – его в официальном changelog нет.

Подготовьте реестр и безопасность (без сырых ПДн в облако)

Одна строка = одна сущность. Колонка doc_key – стабильный код вроде DOG-2026-014; по нему агент ищет строку. Лист staging – для импортов из 1С или Forms; боевой лист "Реестр" агент правит точечно в колонках status и comment.

В облако и в чат: ИНН, сумма, статус – да; паспорт, полное ФИО в payroll, номера карт – нет. Для тестов замените названия на "Контрагент_01", суммы округлите. Чеклист – в гайде по обезличиванию данных.

На Path B SA видит только таблицы, расшаренные на client_email; IAM Cloud не заменяет Share. На Path A OAuth дает права вашего Google – scopes минимальные (spreadsheets / drive.file по доке Google). JSON-ключ SA не в git. Google предупреждает про indirect prompt injection: ячейка с вредоносным текстом может подтолкнуть к лишним write – подтверждайте каждый write-tool вручную.

Схема: реестр в Sheets → (OAuth remote | SA share) → mcp.json в Cursor → Agent read/update по doc_key → перечитка → регламент CFO

Сделайте: отдельный SA или OAuth-пилот, доступ только к нужному файлу. Не делайте: боевые ПДн в тестовый реестр и auto-approve на update_values.

Настройте Path A или Path B: GCP, mcp.json и первый запуск

Конфиг – в проектном .cursor/mcp.json или глобальном ~/.cursor/mcp.json; при совпадении имени побеждает проектный. После правки сохраните и перезапустите Cursor. Поля url / command / env – в Cursor Help: MCP.

Path A – официальный remote Sheets MCP

  1. Создайте проект в Google Cloud и включите: gcloud services enable sheets.googleapis.com sheetsmcp.googleapis.com.
  2. Настройте OAuth consent со scopes Sheets MCP (spreadsheets, при необходимости drive.file – по доке Google Sheets MCP).
  3. Добавьте remote-сервер в mcp.json:
{
  "mcpServers": {
    "sheets": {
      "url": "https://sheetsmcp.googleapis.com/mcp/v1"
    }
  }
}
  1. Пройдите OAuth при первом вызове tool. Tools: get_values, get_spreadsheet, update_values, update_spreadsheet, update_formulas, insert_dimension.

Сделайте Path A для пилота на личном Google без JSON-ключа. Не делайте Path A default для командного production, если нужен blast radius только на один файл.

Path B – service account + community MCP

  1. Создайте проект → Enable Google Sheets API.
  2. Service account: IAM → Create → Keys → JSON. client_email скопируйте, файл вне git.
  3. Расшарьте реестр на client_email ролью "Редактор", без "Уведомить". Без Share будет 403.
  4. Пропишите mcp.json (freema/mcp-gsheets, Node 20+):
{
  "mcpServers": {
    "mcp-gsheets": {
      "command": "npx",
      "args": ["-y", "mcp-gsheets@latest"],
      "env": {
        "GOOGLE_APPLICATION_CREDENTIALS": "/absolute/path/to/sa-registry.json"
      }
    }
  }
}

Альтернатива uvx (xing5/mcp-google-sheets 0.6.3): сузьте tools через ENABLED_TOOLS (~19 tools ≈ 13K tokens по умолчанию).

{
  "mcpServers": {
    "google-sheets": {
      "command": "uvx",
      "args": ["mcp-google-sheets@latest"],
      "env": {
        "SERVICE_ACCOUNT_PATH": "/absolute/path/to/sa-registry.json",
        "ENABLED_TOOLS": "get_sheet_data,update_cells,list_spreadsheets,list_sheets"
      }
    }
  }
}

Сделайте Path B для общего реестра и share одного файла. Не делайте: относительный путь к ключу и commit JSON в git.

Разборы контуров – в закрытом клубе KODA.

Проверьте подключение и прогоните сценарий реестра

После рестарта: Customize → MCPs – зеленый статус. Логи: Output → MCP Logs (Ctrl+Shift+U / Cmd+Shift+U). Connected ≠ authorized: Path B без Share → 403; Path A без consent → ошибка OAuth.

  1. Живой read: "Прочитай A1:G5 листа Реестр" или sheets_check_access / get_values.
  2. Промпт с DoD: к {SPREADSHEET_ID} на листе Реестр найди doc_key = DOG-2026-014; прочитай status и comment; если status ≠ "Оплачен", предложи "На согласовании" и дату в comment; после write перечитай строку и покажи diff.
  3. Approval: подтверждайте каждый write вручную; в Cursor 3.6+ не кидайте update в общий allowlist без регламента.
  4. Сверка: в браузере status и comment совпали с diff агента.

Квоты: 300 req/min на проект и 60/min на user (read/write отдельно). SA = один user; пакеты могут дать HTTP 429 – backoff.

Сделайте: один тестовый update + перечитка. Не делайте: массовый rewrite статусов без фильтра по doc_key.

Закрепите регламент и решите, что автоматизировать дальше

В регламенте CFO: кто подтверждает write, какие колонки трогает агент (только status/comment), где ключ SA, как часто ротируете JSON (тема B93). При Forms→Sheets свыше 80–100 заявок/мес таблица – staging перед n8n/ERP.

  • Allowlist: read + точечный update; delete/append – отдельно.
  • Отдельный SA на контур реестров, не общий "dev-ключ".
  • Тот же SA можно кормить cron из B82 – MCP не отменяет пакетную загрузку.
  • Cloud Agents: MCP настраивается в dashboard / Team Integrations; локальный OAuth сам не переезжает.

Сделайте: runbook на страницу + тестовый doc_key в staging. Не делайте: MCP "на все таблицы Drive" и auto-approve write в production.

Частые вопросы

Можно ли подключить MCP Google Sheets в Cursor без программиста?

Path A (remote OAuth) ближе к "да" для пилота: enable API + mcp.json с url + consent. Path B (SA + mcp.json) – около 1–2 часов по чеклисту GCP; код писать не нужно, но Share и абсолютный путь к ключу обязательны.

Сколько займет внедрение на один реестр?

OAuth или SA + mcp.json + тестовый update с перечиткой: ориентир 1–2 часа. Больше времени уходит на чистку колонок и регламент approval.

Какие риски для данных при MCP Sheets?

OAuth = права вашего Google; SA-ключ = все файлы, расшаренные на client_email. Не кладите сырые ПДн; подтверждайте write; учитывайте prompt injection из ячеек. Ключ вне git, scopes – минимум.

OAuth (Path A) или service account (Path B)?

OAuth – личный пилот. SA – командный реестр и минимальный blast radius: отозвали Share – доступ пропал. Для production финконтура я выбираю Path B.

Чем это отличается от интеграции Sheets API скриптом?

Скрипт (B82) пишет в staging по расписанию. Здесь Agent через MCP правит строку по doc_key в диалоге. Оба слоя можно держать на одном SA.

Есть ли плагин Google Sheets в Cursor Marketplace?

На 09.09.2026 changelog Workspace-плагинов подтверждает Drive, Gmail и Calendar. Для ячеек – Sheets MCP (remote Google или community на SA). Drive MCP ячейки не пишет – см. форум Cursor.

Работает ли Google Sheets MCP в Cloud Agents?

Да, если MCP отдельно настроен в dashboard / Team Integrations. Локальный OAuth с десктопа сам не переносится – для облака заранее спланируйте auth.
