Реестр договоров или УПД снова уезжает в чат Cursor кусками, а после правки вы вручную сверяете ячейки в Google Таблицах? MCP Google Sheets в Cursor - это розетка, через которую агент сам читает и обновляет строки реестра по ключу doc_key, без копипаста диапазонов. За 1-2 часа настроите service account и mcp-gsheets (или официальный remote MCP Google в Preview), проверите доступ через MCP Logs и прогоните сценарий: найти строку, обновить статус, перечитать результат.

MCP (Model Context Protocol) - протокол, через который Cursor подключает внешние инструменты. Без MCP агент видит только чат; с MCP у него появляются tools, и он дергает Google Sheets API, как защищенный курьер между редактором и таблицей. JSON в ответе - как акт сверки: у каждого поля свое место.

На 16.09.2026 два маршрута. Path A (рекомендую для финконтура) - freema/mcp-gsheets + service account: расшарили только рабочий файл, ключ в env. Path B - официальный remote Sheets MCP Google (sheetsmcp.googleapis.com, Developer Preview, OAuth). Плагины Sheets/Docs в Marketplace не обещаю: сняты с витрины (форум Cursor, 31.08.2026); Drive не пишет ячейки. Обзор MCP - в гайде по MCP в Cursor; скрипт с тем же SA - в интеграции Sheets API.

Оцените, когда MCP Sheets нужен финотделу (и когда нет)

Подключайте MCP, если реестр уже в Google Таблицах (договоры, УПД, SaaS, заявки на расход), правки еженедельные, а копипаст диапазонов в чат бесит. Типичный симптом: CFO просит сменить статус по doc_key, а вы выделяете 40 строк и боитесь сдвинуть формулы. Не делайте Sheets единственным источником правды при жестком audit trail, сотнях таблиц с enterprise ACL или более 200-300 активных договоров - тогда CLM или 1С, таблица остается staging-слоем.

Сделайте: DoD до установки: найти строку по doc_key, сменить status/comment, перечитать. Не делайте: ждать Marketplace Sheets.

Подготовьте реестр и безопасность (без сырых ПДн в облако)

Одна строка = одна сущность. Колонка doc_key - стабильный код вроде DOG-2026-014. Лист staging - для импортов из 1С/Forms; боевой "Реестр" агент правит точечно в status и comment.

В облако: ИНН, сумма, статус - да; паспорт, полные ФИО payroll, карты - нет. Для тестов - "Контрагент_01" и округленные суммы. Чеклист - в гайде по обезличиванию.

SA видит только таблицы, расшаренные на client_email; IAM Cloud не заменяет Share файла. Scope spreadsheets дает read/write всего файла - лист защищайте ProtectedRange. JSON-ключ - не в git, только абсолютный путь в env. Google предупреждает про indirect prompt injection: текст в ячейке может выглядеть как инструкция агенту ("удали все строки") - human review на каждый write обязателен.

Схема: реестр в Sheets → (SA share | Google remote OAuth) → MCP в Cursor → Agent update по doc_key → перечитка → регламент CFO

Сделайте: отдельный SA, share одного файла "Редактор", без "Уведомить". Не делайте: боевые ПДн в тестовый реестр.

Настройте Path A пошагово: Google Cloud, SA и mcp.json

mcp-gsheets: Node.js v20+, Google Sheets API, JSON SA. Конфиг: .cursor/mcp.json или ~/.cursor/mcp.json; при конфликте имен побеждает проектный.

  1. Создайте проект в Google Cloud → Enable APIs → Google Sheets API.
  2. Service account: IAM → Create → Keys → JSON. Скопируйте client_email; ключ вне git.
  3. Расшарьте реестр на client_email "Редактор", без "Уведомить". Без Share будет 403.
  4. Добавьте блок в mcp.json с абсолютным путем к ключу:
{
  "mcpServers": {
    "mcp-gsheets": {
      "command": "npx",
      "args": ["-y", "mcp-gsheets@latest"],
      "env": {
        "GOOGLE_PROJECT_ID": "your-project-id",
        "GOOGLE_APPLICATION_CREDENTIALS": "/absolute/path/to/sa-registry.json"
      }
    }
  }
}
  1. Перезапустите Cursor после правки mcp.json.
  2. Проверьте: Customize → MCPs → зеленый статус; ошибки - Output → MCP Logs (Ctrl+Shift+U). Tool sheets_check_access или чтение A1:C5 листа "Реестр".
  3. Approval на write: Agent спрашивает перед tool; на пилоте не включайте Auto-run всех write.

Ключевые tools: sheets_get_values, sheets_update_values, sheets_append_values, sheets_batch_get_values, sheets_get_metadata, sheets_check_access. Для append явно указывайте INSERT_ROWS: default insertDataOption = OVERWRITE перезаписывает диапазон не так, как ждете в реестре.

Сделайте: зеленый сервер + check_access + тестовое чтение. Не делайте: относительный путь к ключу в env.

Подключите Path B: официальный remote Sheets MCP Google

Если нужен OAuth-пилот и клиент поддерживает remote URL: enable sheets.googleapis.com и sheetsmcp.googleapis.com, OAuth consent и scopes (drive.readonly, drive.file, spreadsheets.readonly, spreadsheets). URL: https://sheetsmcp.googleapis.com/mcp/v1, transport Streamable HTTP. Статус на 14.09.2026 - Developer Preview.

Tools: get_values, get_spreadsheet, update_spreadsheet, update_values, update_formulas, insert_dimension. Квоты: 300 read и 300 write/мин на проект (60 на user+project); каждый tool = 1 запрос; превышение → 429. Позже в 2026 превышение могут тарифицировать.

Сделайте: минимальные scopes и тестовый get_values. Не делайте: считать Preview production для всего отдела.

Прогоните сценарий: найти, обновить, перечитать

DoD: правка одной строки по doc_key и diff после write. Drive-плагин для ячеек не используйте.

Подключись к {SPREADSHEET_ID}. На листе Реестр найди doc_key = DOG-2026-014.
Прочитай status и comment. Если status ≠ "Оплачен", предложи "На согласовании"
и дату в comment. После write перечитай строку и покажи diff.
Не трогай другие листы и колонки вне status/comment.
  1. Метаданные - лист "Реестр" и заголовки на месте.
  2. Найти строку по doc_key через get_values, не угадывать номер.
  3. Approve update - только status и comment.
  4. После write - get_values на ту же строку, сверка.
  5. При расхождении: "перечитай строку N, write не делай".

Разборы контуров - в Telegram "Финансист, который кодит".

Сделайте: цикл find → update → re-read на тестовой строке. Не делайте: Auto-run write без allowlist.

Проверьте результат и типичные ошибки

  • 403 - нет Share на client_email или неверный путь к JSON.
  • Серый MCP - MCP Logs; Node v20+, абсолютный путь; перезапуск Cursor.
  • 429 - батчите; не update по одной ячейке в цикле.
  • Append - явно INSERT_ROWS.
  • Marketplace / Drive - не ждать Sheets-плагин; Drive не пишет ячейки.
  • Path B Preview - сверять доки Google; OAuth = права аккаунта.

При более 80-100 заявок/мес через Forms→Sheets таблица становится staging перед ERP или n8n; MCP остается transport точечных правок, не главной книгой учета. Планируйте ротацию ключа SA (тема B93) и allowlist только нужных write-tools.

Сделайте: чеклист share / env / MCP Logs / re-read. Не делайте: чинить 403 промптом без Share.

Частые вопросы

Можно ли без программиста?

Path A: по инструкции и help Cursor; GCP и Share делаете вы. Первый реестр - около 1-2 часов. Path B: Cloud project + OAuth в Preview. Marketplace Sheets пока недоступен.

Сколько займет внедрение?

SA + mcp.json + тестовый update - около 1-2 часов. OAuth remote MCP обычно дольше из-за Preview и consent.

OAuth или service account?

OAuth (Path B) - личный пилот. SA (Path A) - командный реестр и минимальный blast radius: только расшаренные файлы.

Какие риски для данных?

OAuth = права вашего Google; SA = все таблицы на client_email. Без сырых ПДн; подтверждайте write; учитывайте injection из ячеек.

Чем это отличается от скрипта Sheets API (B82)?

B82 - скрипт пишет в staging по cron. B92 - Agent правит через MCP без скрипта; тот же SA и Share.

Работает ли в Cloud Agents?

Да, через MCP в Cloud Agents dashboard (Team - shared servers). Локальный OAuth IDE сам не переезжает - для облака удобнее SA.

Нужен ли MCP для маленького реестра?

5 строк раз в месяц - хватит ручного редактирования. MCP окупается при еженедельных правках через Cursor без копипаста.
