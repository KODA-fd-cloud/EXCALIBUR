Реестр договоров или УПД снова уезжает в чат Cursor кусками, а статус вы правите руками в Google Таблицах? MCP Google Sheets в Cursor - это розетка: агент сам читает и обновляет строку по doc_key, без копипаста диапазонов. За 1-2 часа подключу mcp-gsheets на service account, проверю доступ через MCP Logs и прогоню сценарий: найти строку → обновить статус → перечитать результат.

MCP (Model Context Protocol) - протокол, через который Cursor подключает внешние инструменты. Без него агент видит только вставленный в чат текст; с MCP появляются tools, и он дергает Google Sheets API - как защищенный курьер между редактором и таблицей. JSON в ответе - как акт сверки: у каждого поля свое место.

Три маршрута. Path B (для финконтура): community-сервер mcp-gsheets на service account - расшарили только рабочий реестр, ключ в env, агент не видит весь Drive. Path A: плагин Marketplace через OAuth, если Sheets в витрине (changelog Workspace на 18.09.2026 детализирует Drive, Gmail, Calendar; Sheets там не расписан). Path C: официальный remote MCP sheetsmcp.googleapis.com - Developer Preview сентября 2026. Обзор MCP - в гайде по MCP в Cursor; запись скриптом с тем же SA - в интеграции Sheets API.

Оцените, когда MCP Sheets нужен финотделу (и когда нет)

Подключайте MCP, если реестр уже в Google Таблицах (договоры, УПД, SaaS, заявки на расход), правки повторяются каждую неделю, а копипаст диапазонов в чат бесит. Типичный симптом: CFO просит сменить статус по doc_key, а вы выделяете десятки строк и боитесь сдвинуть формулы. Не делайте Sheets единственным источником правды при жестком audit trail, сотнях таблиц с enterprise ACL или потоке заявок выше 80-100 в месяц без ERP - тогда 1С или CLM, таблица остается staging-слоем.

Маршрут Когда выбирать Минус
Path B: mcp-gsheets + SA Командный реестр, production GCP-проект и JSON-ключ вне git
Path A: Marketplace + OAuth Личный пилот, если Sheets в витрине Права вашего Google

Вердикт: для финконтура берите Path B. Marketplace и remote Google MCP - пилот. No-code-контур - в автоматизации финансов без кода.

Сделайте: DoD до установки - найти строку по doc_key, сменить status/comment, перечитать. Не делайте: MCP "на весь Drive" ради одного реестра.

Подготовьте реестр и безопасность (без сырых ПДн в облако)

Одна строка = одна сущность (договор, УПД, подписка). Колонка doc_key - стабильный код вроде DOG-2026-014; по нему агент ищет строку, а не по названию контрагента. Лист staging - для сырых импортов из 1С или Forms; боевой лист "Реестр" агент правит точечно в колонках status и comment.

В облако и в чат агента: ИНН контрагента, сумма, статус - да; паспорт, полное ФИО в payroll, номера карт - нет. Для тестов замените названия на "Контрагент_01", суммы округлите. Чеклист - в гайде по обезличиванию данных. Google прямо предупреждает об indirect prompt injection: недоверенный текст в ячейках может подсказать агенту лишние действия - подтверждайте каждый write-tool вручную.

Service account видит только таблицы, расшаренные на client_email; IAM в Cloud Console не заменяет Share файла. Scope spreadsheets дает read/write всего файла; чувствительные листы закрывайте Protected ranges. JSON-ключ - не в git, только абсолютный путь в GOOGLE_APPLICATION_CREDENTIALS.

Схема: реестр в Sheets → (SA share | OAuth) → MCP в Cursor → Agent update по doc_key → перечитка → регламент CFO

Сделайте: отдельный SA, share одного файла "Редактор", без "Уведомить". Не делайте: боевые ПДн в тестовый реестр и auto-approve на все write.

Настройте Path B: Google Cloud, SA и mcp.json пошагово

Сервер mcp-gsheets (freema/mcp-gsheets) требует Node.js v20+, включенный Google Sheets API и JSON service account. Конфиг лежит в проектном .cursor/mcp.json или глобальном ~/.cursor/mcp.json; при совпадении имени сервера побеждает проектный файл. Connected в UI еще не значит, что файл расшарен - сначала share, потом tools.

  1. Создайте проект в Google Cloud → Enable APIs → Google Sheets API.
  2. Создайте service account: IAM → Service Accounts → Keys → JSON. Скопируйте client_email; ключ вне репозитория.
  3. Расшарьте реестр на client_email ролью "Редактор", снимите "Уведомить". Без Share будет 403.
  4. Добавьте блок в mcp.json с абсолютным путем к ключу:
{
  "mcpServers": {
    "mcp-gsheets": {
      "command": "npx",
      "args": ["-y", "mcp-gsheets@latest"],
      "env": {
        "GOOGLE_PROJECT_ID": "your-project-id",
        "GOOGLE_APPLICATION_CREDENTIALS": "/absolute/path/to/sa-registry.json"
      }
    }
  }
}
  1. Перезапустите Cursor. Customize → MCPs: зеленый статус. Ошибки - Output → MCP Logs (Ctrl+Shift+U / Cmd+Shift+U).
  2. Проверьте tool sheets_check_access или запрос: "прочитай A1:C5 листа Реестр в {SPREADSHEET_ID}".
  3. Path A/C: Marketplace → Add + OAuth с минимальными scopes, если Sheets в витрине. Remote Path C - url https://sheetsmcp.googleapis.com/mcp/v1 (Preview; включите sheetsmcp.googleapis.com). Redirect: https://www.cursor.com/agents/mcp/oauth/callback и desktop http://localhost:8787/callback. OAuth = права личного Google, не SA.
  4. Прогоните промпт: metadata → найти doc_key → update status/comment → get_values → сверка. Approval на каждый write.
  5. Закрепите регламент: allowlist write-tools; при append - INSERT_ROWS (default OVERWRITE); квота write 300/мин, при 429 - batch.


Иллюстрация: Path B - service account расшарен только на реестр, Agent правит строку через MCP-tool

Тестовый промпт: "Подключись к {SPREADSHEET_ID}. На листе Реестр найди doc_key = DOG-2026-014. Прочитай status и comment. Если status не Оплачен, предложи На согласовании и дату в comment. После write перечитай строку и покажи diff."

Сделайте: Path B + один update с перечиткой. Не делайте: ключ SA в git и auto-approve без diff.

Проверьте результат и разберите типичные ошибки

"Connected" в UI не равно "authorized" к файлу. Сначала sheets_check_access или чтение маленького диапазона A1:C5, потом write. После любого update - повторный get_values той же строки и сверка diff глазами CFO или ответственного за реестр.

  • 403 / unauthorized: файл не расшарен на client_email или нет scope spreadsheets.
  • Пустой tool list: нет Node 20+, битый путь к JSON - смотрите MCP Logs.
  • Overwrite строк: append без INSERT_ROWS затер соседние данные.
  • Cloud Agents: локальный OAuth не переезжает сам; для облака - SA или Team Dashboard → Plugins & MCPs.
  • 429: квота write; объединяйте правки в batch.

Сделайте: чеклист "share → green MCP → read → write → re-read". Не делайте: массовый update всего листа.

Что автоматизировать дальше после первого реестра

Когда сценарий find → update → re-read стабилен на одном файле, подключайте соседние реестры той же схемой: договоры, УПД, SaaS-подписки. Sheets остается staging; при росте объема и нужде в audit trail выносите поток в n8n или ERP (n8n - как супер-Excel, где формулы сами гоняют данные между системами), а Cursor правит только статусы в staging.

Ротируйте JSON-ключ SA по регламенту (соседняя тема B93). Не копируйте один ключ на все таблицы "для удобства" - blast radius растет вместе с share.

Сделайте: второй реестр после успешного пилота. Не делайте: перевод главной книги 1С в Sheets "потому что MCP удобный".

Частые вопросы

Можно ли подключить MCP Google Sheets без программиста?

Path A (Marketplace + OAuth) - да для пилота, если Sheets в витрине. Path B - по инструкции: Cursor поможет с JSON, GCP-клики займут основное время. Первый реестр обычно 1-2 часа.

Сколько займет внедрение Path B?

Cloud + SA + share + mcp.json + тестовый update с перечиткой - ориентир 1-2 часа. OAuth быстрее при доступной витрине, но для командного реестра надежнее SA.

OAuth или service account - что выбрать?

OAuth - личный пилот и Path C. Service account - командный реестр и минимальный blast radius: агент видит только расшаренные файлы.

Чем это отличается от интеграции Sheets API скриптом?

Скрипт (B82) пишет в staging по расписанию. B92 - Agent вызывает MCP-tools в чате без Python. SA и Share файла те же.

Какие риски для финансовых данных?

OAuth = права вашего Google; SA-ключ = все файлы на этот email. Не кладите сырые ПДн; подтверждайте write; учитывайте injection из ячеек. Ключ вне git, ротация по регламенту.

Работает ли MCP Sheets в Cloud Agents?

Да, через Team Dashboard → Plugins & MCPs. OAuth из локальной IDE сам не переезжает - для облака надежнее SA.

Что с официальным Google Sheets MCP?

URL https://sheetsmcp.googleapis.com/mcp/v1, Developer Preview (дока 14.09.2026). Эксперимент OAuth. Для финконтура с least privilege - Path B: mcp-gsheets + SA.

Что дальше

  1. Соберите Path B: SA, share одного реестра, mcp.json, зеленый MCP.
  2. Прогоните find → update → re-read по одному doc_key.
  3. Закройте write-tools allowlist и уберите ПДн из тестов.
  4. Добавьте второй реестр или вернитесь к скрипту B82 для пакетов.
