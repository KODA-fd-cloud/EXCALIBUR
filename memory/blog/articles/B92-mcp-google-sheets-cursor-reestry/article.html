Копируете диапазон реестра в чат Cursor, правите статус руками и снова вставляете строки – это медленно и легко ошибиться. MCP Google Sheets даёт агенту "кнопки" к таблице: найти строку по doc_key, обновить статус и сразу перечитать результат без копипаста. За 1–2 часа вы подключите mcp-gsheets через service account, расшарите только рабочий реестр и прогоните сценарий find → update → re-read.

MCP (Model Context Protocol) – USB-розетка для Cursor: в неё втыкается сервер с инструментами, агент вызывает их с вашим подтверждением. Sheets API – защищённый курьер между Cursor и таблицей. JSON service account – пропуск "робота" только к файлам, которыми вы с ним поделились. Ниже – реестры финотдела, не "свой MCP с нуля".

Доступность Cursor зависит от региона и аккаунта: с начала сентября 2026 у части пользователей из РФ встречается "not available in your region". Гайд – при живом Cursor; обход ограничений не описываю. Path B (SA + mcp-gsheets) при необходимости переносится на другой MCP-клиент.

Решите, нужен ли MCP Google Sheets финотделу

Делайте, если реестр уже в Sheets, правки статуса повторяются, а копипаст бесит. Не делайте MCP поверх сотен таблиц с жёстким enterprise ACL – для audit trail лучше 1С/CLM (чтение остатков из Cursor – в гайде MCP к 1С), Sheets оставьте staging.

Схема: Реестр в Sheets → (SA share | OAuth | Google remote MCP) → MCP в Cursor → Agent update по doc_key → перечитка → регламент CFO
Путь Когда брать Минус
Path B: mcp-gsheets + SA Командный финконтур, узкий blast radius GCP, Node 20+, JSON-ключ
Path A: Marketplace / OAuth Личный пилот, если auth доступен OAuth cursor:// часто ломается
Path C: sheetsmcp.googleapis.com Официальный remote MCP Google OAuth client в GCP, не one-click

Для production беру Path B. Общий MCP без Sheets – в гайде MCP для финансиста. SA без агента (скрипт) – в интеграции Sheets API.

Подготовьте реестр и уберите сырые ПДн

Одна строка = одна сущность. Колонка doc_key стабильна (DOG-2026-014) – тот же каркас, что в реестре договоров в Sheets. Лист staging – импорт, лист Реестр – статусы.

В облако можно: doc_key, статус, дата, код контрагента, условная сумма. Нельзя: паспорт, полные ФИО, сканы. Маскируйте: ООО "Ромашка" → Kontragent_17, ИНН → INN_***893. Чеклист – в обезличивании данных.

Сделайте: копию реестра под пилот. Не делайте: доступ агента ко всему Drive.

Настройте Path B: service account и mcp.json

Service account – служебный сотрудник Google без личного Gmail. Он видит только расшаренные файлы: IAM в Cloud не заменяет "Поделиться" на таблице.

  1. Создайте проект Google Cloud и включите Google Sheets API.
  2. Создайте service account, скачайте JSON-ключ, скопируйте client_email.
  3. В Sheets: "Поделиться" → client_email → роль Редактор → без "Уведомить".
  4. Установите Node.js v20+ (нужен npx mcp-gsheets).
  5. Создайте проектный .cursor/mcp.json или глобальный ~/.cursor/mcp.json (при конфликте имён побеждает проектный).
  6. Вставьте блок ниже. Путь к JSON – абсолютный. Ключ не в git.
  7. Перезапустите Cursor после правки mcp.json.
  8. Customize → MCPs: зелёный статус. Иначе Output → MCP Logs (Ctrl+Shift+U).
  9. Проверьте sheets_check_access или запрос "прочитай A1:C5 листа Реестр".

Scope spreadsheets – read/write на весь файл. Служебные листы – ProtectedRange. Ключ SA = сейф: права на файл = ущерб при утечке.

Path A: Add to Cursor + OAuth. Error 400 на cursor://callback – auth через https://cursor.com/agents. Connected ≠ запись: нужен живой read. Path C: URL https://sheetsmcp.googleapis.com/mcp/v1 по доке Google (Sheets API + Sheets MCP API).

Сделайте: один реестр + один SA + один зелёный MCP. Не делайте: ключ в репозиторий или share всего диска.

Прогоните сценарий: найти → обновить → перечитать

DoD: строка по doc_key обновлена, diff показан, write подтверждён вручную. По умолчанию Cursor спрашивает approval; Auto-review включайте после пилота.

Подключись к таблице {SPREADSHEET_ID}. На листе Реестр найди строку,
где doc_key = DOG-2026-014. Прочитай status и comment. Если status
не "Оплачен", предложи "На согласовании" и допиши в comment дату.
После write перечитай строку и покажи diff.
  1. sheets_get_metadata – лист и колонки на месте.
  2. Найдите строку по doc_key (get_values / batch_get).
  3. Подтвердите update/append только в status/comment.
  4. Сразу get_values на ту же строку и сверка diff.
  5. Для append: default OVERWRITE; для сдвига строк – INSERT_ROWS.

Квоты: 300 req/min на проект и 60/min на user. Один SA = один user – агент упирается в 60 раньше. HTTP 429 – пауза. Later in 2026 Google планирует биллинг за overage: API не "вечно бесплатный без оговорок".

Сделайте: approval на каждый write. Не делайте: массовый rewrite всего листа.

Проверьте ошибки и закройте контур безопасности

  • Unauthorized: файл не на client_email или неверный SPREADSHEET_ID.
  • Сервер серый: нет Node 20+, битый путь JSON, нет рестарта – MCP Logs.
  • 429: меньше параллельных tool-calls, без цикла "прочитай всё".
  • Prompt injection: в ячейках бывают скрытые инструкции – без auto-run write.
  • Path A: Connected в UI ≠ успешная запись.

Регламент: allowlist write-tools, ротация ключа SA, пилот на копии. При >80–100 заявок/мес Sheets – staging перед n8n/ERP. База – в автоматизации финансов без кода. Живые разборы – в Telegram "Финансист, который кодит".

Сделайте: чеклист share → ключ вне git → approval → re-read. Не делайте: SA-Editor на десятки старых таблиц.

Спланируйте рост после первого реестра

Дальше: второй реестр (например УПД в Sheets) на том же SA (отдельный share), шаблон промпта с DoD, запрет write без diff. Нужен audit и поток – платёжный календарь Sheets + n8n, Sheets как витрина статусов.

Практика Cursor для финотдела – в закрытом клубе KODA.

Сделайте: зафиксируйте SA, файлы, кто ротирует ключ. Не делайте: масштаб на весь Drive до первого re-read.

Частые вопросы

Можно ли подключить MCP Google Sheets без программиста?

Path A – да для пилота, если плагин и OAuth доступны. Path B – по инструкции: Cursor поможет с JSON, GCP-клики займут час. Первый production-контур обычно 1–2 часа, не "ноль кликов".

Сколько займёт внедрение mcp-gsheets в Cursor?

SA + share + mcp.json + тестовый update: ориентир 1–2 часа. OAuth быстрее, если auth проходит сразу. Заложите время на обезличивание копии реестра.

OAuth или service account – что выбрать?

OAuth – личный пилот. SA – командный реестр и узкий share. Для финконтура рекомендую Path B (SA).

Чем это отличается от скрипта Sheets API без MCP?

Скрипт пишет в staging кодом. Здесь Agent вызывает MCP-tools по промпту без отдельного .py на каждый статус. SA и share те же, слой доступа другой.

Какие риски для данных?

OAuth наследует права аккаунта. JSON SA открывает все расшаренные таблицы. Без сырых ПДн, write вручную, помните про injection из ячеек, ротируйте ключ.

Работает ли Sheets MCP в Cloud Agents?

Да, если MCP настроен в Cloud Agents dashboard. Локальный OAuth IDE не переезжает сам – настройте сервер в Cloud отдельно и проверьте read/write.

Что делать при "not available in your region"?

Проверьте ошибку и статус аккаунта. Статья про паттерн MCP + Sheets, не про доступ к IDE. Обход не описываю. Path B перенесите на другой MCP-клиент при необходимости.
