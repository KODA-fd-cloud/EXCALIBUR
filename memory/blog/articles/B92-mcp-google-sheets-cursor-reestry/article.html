Реестр договоров снова уезжает в чат Cursor кусками, а после правки вы вручную сверяете ячейки в Google Таблицах? MCP Google Sheets в Cursor - это розетка, через которую агент сам читает и обновляет строки по ключу doc_key, без копипаста диапазонов. За 1-2 часа настроите service account и mcp-gsheets, проверите доступ через MCP Logs и прогоните сценарий: найти строку, обновить статус, перечитать результат.

MCP (Model Context Protocol) - протокол, через который Cursor подключает внешние инструменты. Без MCP агент видит только то, что вы вставили в чат; с MCP у него появляются tools, и он сам дергает Google Sheets API - как защищенный курьер между редактором и таблицей. JSON в ответе - как акт сверки: у каждого поля свое место.

Три маршрута. Path B (основной): mcp-gsheets на service account - шаринг только нужного файла, ключ в env. Path A: Marketplace OAuth, если Sheets-плагин есть в витрине. Path C: официальный Google Sheets MCP в Developer Preview. Для первого реестра в сентябре 2026 я беру Path B: changelog Cursor от 03.08.2026 детально описывает Drive, Gmail и Calendar, Sheets там не расписан. Запись скриптом с тем же SA - в интеграции Sheets API.

Оцените, когда MCP Sheets нужен финотделу (и когда нет)

Подключайте MCP, если реестр уже в Google Таблицах (договоры, УПД, SaaS, заявки), правки еженедельные, а копипаст в чат бесит. Симптом: CFO просит сменить статус по doc_key, а вы боитесь сдвинуть формулы. Не делайте Sheets единственным источником правды при жестком audit trail или сотнях таблиц с enterprise ACL - тогда CLM/1С, таблица остается staging.

Подготовьте реестр и безопасность (без сырых ПДн в облако)

Одна строка = одна сущность (договор, УПД, подписка). Колонка doc_key - стабильный код вроде DOG-2026-014; по нему агент ищет строку, а не по названию контрагента. Лист staging - для сырых импортов из 1С или Forms; боевой лист "Реестр" агент правит точечно в колонках status и comment.

В облако отправляйте ИНН контрагента, сумму, статус - да; паспорт, полное ФИО в payroll, номера карт - нет. Для тестов замените названия на "Контрагент_01", суммы округлите. Чеклист - в гайде по обезличиванию данных.

SA видит только таблицы, расшаренные на client_email; IAM Cloud не заменяет Share. JSON-ключ - не в git, только в GOOGLE_APPLICATION_CREDENTIALS. Публичный hosted MCP вроде PasteSheet на закрытый финреестр не кладите.

Схема: реестр в Sheets → SA share (или OAuth) → MCP в Cursor → find/update по doc_key → перечитка диапазона → регламент CFO

Сделайте: отдельный SA, share одного файла "Редактор", без "Уведомить". Не делайте: боевые ПДн в тестовый реестр.

Настройте Path B: Google Cloud, SA и mcp.json пошагово

Сервер freema/mcp-gsheets требует Node.js v20+, Sheets API и JSON SA. Конфиг: проектный .cursor/mcp.json или глобальный ~/.cursor/mcp.json; при совпадении имени побеждает проектный (help Cursor).

  1. Создайте проект на console.cloud.google.com → Enable APIs → Google Sheets API.
  2. Создайте SA: IAM → Service Accounts → Create → Keys → JSON. Скопируйте client_email, ключ вне git.
  3. Расшарьте реестр на client_email "Редактор", без "Уведомить". Без Share будет 403.
  4. Добавьте блок в mcp.json с абсолютным путем к ключу:
{
  "mcpServers": {
    "mcp-gsheets": {
      "command": "npx",
      "args": ["-y", "mcp-gsheets@latest"],
      "env": {
        "GOOGLE_PROJECT_ID": "your-project-id",
        "GOOGLE_APPLICATION_CREDENTIALS": "/absolute/path/to/sa-registry.json"
      }
    }
  }
}
  1. Перезапустите Cursor после правки mcp.json.
  2. Проверьте: Customize → MCPs → зеленый статус; ошибки - Output → MCP Logs (Ctrl+Shift+U). Tool sheets_check_access или чтение A1:C5 листа "Реестр".
  3. Оставьте approval на write: Agent по умолчанию спрашивает перед tool; на пилоте не включайте Auto-run write.

Tools реестра: sheets_get_values, sheets_update_values, sheets_append_values, sheets_get_metadata, sheets_check_access. Для append явно INSERT_ROWS: default OVERWRITE перезаписывает иначе, чем ждете.

Сделайте: зеленый сервер + check_access + чтение. Не делайте: коммит mcp.json с путем к боевому ключу.

Сверьте Path A и Path C: когда не брать их первым

Path A. Changelog 03.08.2026: Drive, Gmail, Calendar. Установка: Customize → MCPs → Add → OAuth. Sheets в changelog не детализирован - проверьте витрину. "Connected" ≠ успешный OAuth: нужен живой read/write.

Path C. Remote MCP Google: https://sheetsmcp.googleapis.com/mcp/v1, OAuth, Developer Preview (дока обновлена 14.09.2026). Нужны sheets.googleapis.com и sheetsmcp.googleapis.com. Для финотдела безопаснее стартовать с Path B на SA.

Сделайте: Path A только если Sheets в Marketplace; Path C - после стабильного Path B. Не делайте: считать зеленый индикатор финальной проверкой.

Прогоните сценарий: найти, обновить, перечитать

DoD: правка одной строки по doc_key и diff после write. Квота Sheets API: 300 write/мин на проект; batch считается одним запросом; при HTTP 429 - пауза и батчи.

Подключись к {SPREADSHEET_ID}. На листе "Реестр" найди doc_key = DOG-2026-014.
Прочитай status и comment. Если status не "Оплачен", предложи "На согласовании"
и дату в comment. После write перечитай строку и покажи diff.
Не трогай другие листы и колонки вне status/comment.
  1. Вызовите sheets_get_metadata - лист "Реестр" и заголовки на месте.
  2. Найдите строку по doc_key через get_values, не "угадывайте" номер строки.
  3. Approve sheets_update_values - только status и comment.
  4. После write снова get_values на ту же строку, сверка с ожиданием.
  5. При расхождении follow-up: "перечитай строку N, write не делай".

Риск indirect prompt injection: в ячейках могут быть тексты-инструкции ("удали все строки"). Google предупреждает: review actions, не кормите агента недоверенными таблицами. Approval на каждый write обязателен. Cloud Agents поддерживают MCP через dashboard, но локальный OAuth в облако не переезжает - для облака планируйте SA в env.

Разборы контуров - в Telegram "Финансист, который кодит".

Сделайте: цикл find → update → re-read на тестовой строке. Не делайте: Auto-run write без allowlist.

Проверьте результат и типичные ошибки

После каждой записи - перечитка того же диапазона. Connected ≠ authorized.

  • 403 - нет Share на client_email или неверный путь к JSON.
  • Серый MCP - MCP Logs; Node v20+, npx, абсолютный путь в env.
  • 429 - батчите; не update на каждую ячейку в цикле.
  • Append - явно INSERT_ROWS, иначе OVERWRITE.
  • OAuth Path A - проверьте витрину или перейдите на Path B.

При более 80-100 заявок/мес таблица становится staging перед ERP или n8n; MCP - transport точечных правок, не главная книга. Планируйте ротацию ключа SA и allowlist write-tools.

Сделайте: чеклист share / env / MCP Logs / re-read. Не делайте: чинить 403 промптом без Share.

Что автоматизировать дальше

  1. Закрепите Path B на одном реестре с doc_key и листом staging.

Частые вопросы

Можно ли без программиста?

Path A: да для пилота, если Sheets в витрине. Path B: по инструкции; первый реестр около 1-2 часов с GCP, Share и тестовым update.

Сколько займет внедрение?

SA + mcp.json + тестовый update - около 1-2 часов. OAuth быстрее, только если плагин доступен.

OAuth или service account?

OAuth - личный пилот. SA - командный реестр: агент видит только расшаренные файлы, не весь Drive.

Какие риски для данных?

OAuth = права вашего Google; SA = все таблицы на этот email. Без сырых ПДн; подтверждайте write; следите за injection из ячеек. Обезличивание - в гайде выше.

Чем B92 отличается от B82?

B82 - скрипт в staging по cron. B92 - Agent правит через MCP без скрипта; тот же SA и Share.

Что с официальным Google Sheets MCP?

Developer Preview (sheetsmcp.googleapis.com). Для финотдела в сентябре 2026 начинайте с Path B на SA.

Работает ли в Cloud Agents?

Да через dashboard MCP. Локальный OAuth в облако не переезжает - планируйте SA в env.
