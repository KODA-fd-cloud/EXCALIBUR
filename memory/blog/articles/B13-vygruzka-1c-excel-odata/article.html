Каждый понедельник одно и то же: открыть отчёт в 1С, "Сохранить как" в Excel, поправить шапку руками и надеяться, что вчерашний день не выпал. Выгрузка из 1С в Excel через OData решает это иначе: база отдаёт нужный срез по HTTP-запросу, а Excel или Google Sheets обновляют его по кнопке. Ниже – пошаговый маршрут: когда хватает OData, как опубликовать standard.odata, как подтянуть данные в Excel и Sheets и что не тащить в облако.

OData в 1С – стандартный REST-интерфейс платформы (протокол OData 3.0). Простыми словами: защищённый курьер между учётной базой и таблицей. Вы даёте URL и логин пользователя с правами чтения, курьер приносит структурированный JSON – как акт сверки, где у каждого поля своё место. После публикации базы на веб-сервере объекты доступны по адресу …/odata/standard.odata/ИмяРесурса.

Честно: "без программиста" значит "без программиста на каждый отчёт". Публикацию на IIS/Apache или в облаке и состав объектов админ обычно делает один раз. Дальше финансист самообслуживается. Если цель – миллионы строк и сложная СКД, OData не мучайте: зовите 1С-ника. Для ДДС, справочников и регулярных срезов курьера хватает.

Когда хватает OData, а когда нужен программист 1С

Сверьте задачу с инструментом. Ручной "Сохранить как" – разовый снимок глазами. OData – повторяемый запрос к живой базе. Заказная обработка / SQL / экстрактор – когда объём или логика не лезут в HTTP-срез.

Критерий Сохранить как Excel OData → Excel / Sheets Программист / экстрактор
Кто делает Финансист сам Админ один раз, дальше финансист 1С-ник / подрядчик
Обновление Каждый раз руками Кнопка / Power Query Регламент / пайплайн
Объём Пока глаз и файл тянут Малые и средние срезы; на больших – таймауты Большие выгрузки, сложные join
Когда выбирать Разовый отчёт в пятницу ДДС, справочники, еженедельный срез СКД, недоступный объект, закрытый контур
Правило выбора: регулярный срез с фильтром и автообновление – берите OData. Сложные join, витрина на миллионы строк или объект вне состава OData – зовите программиста. Иначе потеряете вечер на таймауты и длину фильтра (в отраслевых обзорах её часто ограничивают примерно 255 символами).

Сделайте: зафиксируйте одну сущность и период. Не делайте: обещать себе "выгружу всю базу" – у листа Excel потолок около миллиона строк, у OData ещё и таймауты.

Как опубликовать базу и проверить URL standard.odata

Без публикации курьер не выйдет из офиса. База должна быть на веб-сервере (IIS или Apache; Apache 2.4 – с платформы 8.3.8+) либо уже в облаке 1С. В конфигураторе включают публикацию и галку стандартного интерфейса OData. "Без IIS" ≠ "без веб-сервера": это Apache или облако провайдера.

  1. Опубликуйте базу на веб-сервере со стандартным интерфейсом OData (или попросите админа).
  2. Откройте в браузере https://ВАШ_ХОСТ/…/odata/standard.odata – служебная страница, не 404.
  3. Проверьте метаданные: …/odata/standard.odata/$metadata. Это каталог сущностей.
  4. Ограничьте состав объектов (настройка OData / УстановитьСоставСтандартногоИнтерфейсаOData): только нужные Catalog_* и регистры.
  5. Создайте отдельного пользователя 1С только на чтение. Пароль – не в общий чат и не в ячейку листа.
  6. Сделайте первый запрос: Entity?$format=json&$top=10. Нужен JSON, не HTML-ошибка.

Имена ресурсов: Catalog_…, Document_…, AccumulationRegister_…_RecordType. В моей практике на УНФ для ДДС рабочие сущности:

  • AccumulationRegister_ДвиженияДенежныхСредств_RecordType – движения
  • Catalog_СтатьиДвиженияДенежныхСредств, Catalog_Контрагенты, Catalog_Организации, Catalog_Кассы, Catalog_БанковскиеСчета – справочники

В движениях часто есть СуммаПриход / СуммаРасход и ссылки *_Key. Точные имена смотрите в $metadata вашей конфигурации.

GET https://ONEC_BASE_URL/odata/standard.odata/AccumulationRegister_ДвиженияДенежныхСредств_RecordType?$format=json&$top=100
Authorization: Basic …

Сделайте: сначала $top=10, потом наращивайте. Не делайте: открывать весь состав OData "на всякий случай".

Выгрузка в Excel и CSV: запрос, фильтр, лимиты

Когда URL отвечает JSON, тяните его в Excel через Power Query ("Данные" → "Из интернета" / канал OData). Сохраняете запрос один раз – дальше жмёте "Обновить".

  1. Скопируйте URL сущности с $format=json и разумным $top (в моих скриптах: движения до 2000 строк, справочники до 500 – это лимит практики, не закон 1С).
  2. В Excel укажите URL и учётку пользователя 1С (логин/пароль совпадают с веб-доступом).
  3. Добавьте $select и $filter по периоду – чем короче фильтр, тем меньше риск упереться в лимит длины.
  4. Сохраните запрос на лист staging, например raw_dds. Сводные стройте поверх staging.
  5. Если Power Query капризничает – сохраните JSON/CSV и откройте файл. Запасной путь, не стыдно.
Схема: 1С (OData) → HTTP с фильтром → JSON → Power Query / CSV → лист raw_* → сводная / отчёт CFO

Для УНФ в облаке URL часто уже опубликован. On-prem без публикации снаружи Excel "из интернета" не подключится.

Сделайте: регламент "кто жмёт Обновить, какой период, какой $top". Не делайте: тащить всю историю за 10 лет одним запросом.

Связка с Google Sheets: кнопка "Обновить из 1С"

Тот же standard.odata можно дергать из Apps Script. По смыслу это супер-Excel: скрипт сам ходит за данными. В моём контуре ДДС кнопка называется "Обновить из 1С": берёт учётку из свойств документа, ходит на OData по Basic Auth и кладёт строки на raw_dds.

// псевдокод паттерна refreshFrom1C
base = …getProperty("ONEC_BASE_URL") // …/odata/standard.odata
url = base + "/" + entity + "?$format=json&$top=" + N;
resp = UrlFetchApp.fetch(url, {
  headers: { Authorization: "Basic …" },
  validateHttpsCertificates: true
});
// JSON → лист raw_dds

Учётку сохраняют через функцию вроде saveOnecCredentials в PropertiesService, не в ячейку A1. HTTPS с проверкой сертификата – разумный минимум.

Блокер: сервер 1С должен быть доступен с IP Google. Если база только во внутренней сети, UrlFetchApp получит "Адрес недоступен". Тогда: локальный Python/CSV → файл на Диск → уже Sheets.

Если собираете финконтур из таблиц дальше – разбор от Excel к финконтуру за 30 дней. Кейсы по 1С публикую в Telegram "Финансист, который кодит".

Сделайте: один лист raw_* + кнопка + понятный период. Не делайте: писать пароль 1С в скрипт или в общий чат.

Безопасность: отдельный пользователь, права, что не тащить в облако

OData ходит под пользователем ИБ. Права курьера = права этой учётки. Отдельный read-only пользователь и узкий состав объектов – гигиена, не паранойя.

  • Не публикуйте в OData полные карточки физлиц, если они не нужны для отчёта.
  • Google Sheets – чужой облачный контур. Туда только рабочие срезы, не "выгрузка всего".
  • Сырую выгрузку с ИНН и ФИО не копируйте в ChatGPT. Сначала обезличьте: контрагенты → коды, уберите ИНН, суммы при необходимости замените на индексы. Маршрут – в статье как обезличить финансовые данные перед ChatGPT.
  • Пароли 1С – в Properties / менеджере секретов; ротируйте при увольнении.

Сделайте: чеклист "что можно в облачный лист" до первой кнопки. Не делайте: одну общую учётку админа 1С для OData. Избегайте выгрузки ПДн "на всякий случай".

Что дальше

  1. Проверьте в браузере …/odata/standard.odata и $metadata.
  2. Соберите первый JSON с $top=10 по одной сущности.
  3. Подключите Power Query или сохраните CSV на staging-лист.
  4. Если нужен Sheets – убедитесь, что URL 1С доступен из интернета, затем повесьте кнопку обновления.
  5. Зафиксируйте регламент: кто обновляет, какой период, куда пишется raw_*.

Частые вопросы

Работает ли OData на УНФ?

Да: это механизм платформы 1С. Нужны публикация и состав объектов. В облаке URL часто уже есть – иначе тикет в хостинг. On-prem – галка публикации у админа.

Нужен ли HTTPS для выгрузки из 1С в Excel?

Для доступа снаружи – да. В моей практике скрипт ходит по HTTPS с проверкой сертификата. Внутри LAN иногда оставляют HTTP, но пароль тогда в открытом периметре.

Чем OData отличается от обычной выгрузки Excel из отчёта?

"Сохранить как" – разовый снимок. OData – повторяемый HTTP-запрос с фильтром и автообновлением в Power Query или скрипте. Один раз настроили – дальше жмёте "Обновить".

Можно ли подключить OData без IIS?

Да: Apache или облачная публикация. Без любого веб-сервера/публикации снаружи OData не заработает.

Можно ли сразу лить данные из 1С в Google Sheets?

Да, если URL базы доступен из интернета. Иначе Apps Script вернёт "Адрес недоступен" – тогда локальный Python/CSV и файл на Диск.

Нужен ли программист на каждый отчёт через OData?

На чтение уже опубликованных сущностей – нет. На сложный отчёт СКД, объект вне OData или миллионы строк – да.
