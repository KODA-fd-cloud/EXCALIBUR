## action_outline

1. **Собрать минимальный реестр** — лист `Реестр_сверок`: контрагент (код/ИНН-маркер), период сверки, сальдо по нашим данным, канал отправки (email/ЭДО/почта), дата отправки, срок ответа, статус, дата ответа, сумма расхождения, ответственный, ссылка на файл/папку, дата последнего касания, следующий шаг.
2. **Задать статусы без CRM** — `draft` → `sent` → `awaiting` → `agreed` / `dispute` / `no_response` → `closed`; опционально `reminder_1` / `reminder_2`. Условное форматирование по просрочке срока ответа.
3. **Определить кого сверять** — не «все подряд»: приоритет по обороту, незакрытому сальдо, давности последней сверки; отдельный лист `Очередь` или фильтр на реестре (как в алгоритме массовой сверки Entera: отбор → параметры → отправка → контроль).
4. **Наполнить из источника** — выгрузка из 1С (акты / ОСВ 60/62/76) или ручной ввод; staging `raw_*`, в облако — только маркеры контрагентов и суммы, без сырых ПДн/полных реквизитов в публичные чаты.
5. **Зафиксировать канал и шаблон письма** — ЭДО если есть; иначе email с PDF/Excel + срок ответа (например 5–7 рабочих дней); шаблон мягкого напоминания без угроз судом в первом касании.
6. **Собрать автонапоминания** — Google Sheets → n8n (или Apps Script) → email/Telegram: триггер по статусу `sent`/`awaiting` и дате `срок_ответа < сегодня`; лимит касаний (например 2 напоминания), пауза после ответа, исключение `dispute`.
7. **Вести протокол расхождений** — при `dispute`: отдельная колонка/лист «операции в споре», ссылка на первички; статус не закрывать, пока не сверены УПД/платёжки; итог — новый акт или протокол разногласий.
8. **Связать с дебиторкой и закрытием месяца** — согласованное сальдо → обновление реестра ДЗ (B14); незакрытые `awaiting`/`dispute` — чеклист-блокер закрытия месяца; еженедельный разбор KPI: % ответов, сумма в споре, контрагенты без ответа > N дней.

### Конкурентный зазор (serp_gap)

1. **Реестр как staging-таблица финансиста**, не монитор внутри 1С и не SaaS Entera/СБИС.  
2. **Контроль ответов:** статусы + срок + напоминания Sheets → n8n, без обязательной CRM.  
3. **Честная граница данных:** что можно в Sheets (период, статус, сумма, код контрагента), чего не тащить (полные реквизиты, сырые выгрузки в публичный чат).  
4. **Мост на B14** (дебиторка) и чеклист закрытия месяца — конкуренты этого почти не связывают.  
5. **Дисклеймер 2026:** форма 0510477 — про госсектор; коммерция по-прежнему на произвольной/договорной форме.
