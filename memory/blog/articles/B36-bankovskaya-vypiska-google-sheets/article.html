Каждое утро вы скачиваете выписку из клиент-банка, вставляете строки в Google Sheets и молитесь, чтобы формулы не сломались. Это можно заменить: CSV из банка, письмо с вложением или API Т-Бизнеса и Сбера автоматически попадают в staging-таблицу по расписанию. Ниже - выбор маршрута без 1С, Apps Script с ежедневным триггером и проверка первой недели, чтобы цифры совпали с банком.

Если у вас уже есть 1С с DirectBank, это другой контур: банк стучится в учётную систему, а не в таблицу. Здесь - финотдел на Sheets как управленческий слой. Контекст no-code автоматизации - в гайде по автоматизации финансов без кода. Правила обезличивания перед ChatGPT - в статье про защиту данных.

Оцените, когда нужна автоматизация выписки (и когда хватит CSV)

Мало операций в неделю - ручная выгрузка CSV раз в пятницу быстрее, чем писать скрипт. Несколько счетов, ежедневный ДДС или сверка с контрагентами каждое утро - пора ставить расписание. Ловушка: банк отдаёт только 1CClientBankExchange (.txt) для 1С. Для Sheets нужен CSV или Excel; если их нет, ищите API банка или промежуточный парсер.

Сделайте: посчитайте минуты в месяц на копипаст и сравните с одним вечером на настройку. Не делайте: автоматизировать "на будущее" при десяти строках в неделю - поддержка скрипта съест выгоду.

Создайте staging-лист с колонками и дедупом

Staging - промежуточный журнал: сюда падает всё сырое из банка, отсюда вы ведёте ДДС. Отдельный лист raw_import только на append: правки в отчёте не должны затирать источник.

  1. Создайте листы raw_import, staging и log в одной книге Google Sheets.
  2. Задайте колонки staging: date, amount, counterparty, purpose, account, hash.
  3. Считайте hash из даты, суммы и назначения - так вы не задвоите операцию при повторном импорте.
  4. Зафиксируйте знак суммы: приход плюс, расход минус - один раз на всю компанию.
  5. Не смешивайте staging с красивым отчётом для собственника на одном листе.

Сделайте: пустую структуру до первого файла из банка. Не делайте: тащить ИНН и номера карт клиентов "на всякий случай" - лишний риск по 152-ФЗ.

Сравните маршруты: CSV, e-mail, T-API и Sber API

API для финансиста - как защищённый курьер между банком и таблицей: вы не качаете файл руками, банк отдаёт структурированный реестр операций. Выберите один основной канал и один запасной.

Маршрут Когда брать Сложность старта Риски
CSV / Excel из Drive 1-2 счёта, банк даёт CSV Низкая (есть sample Google) Кодировка CP1251, разделитель ;
E-mail с вложением Банк шлёт выписку на почту Средняя Спам, дубли писем, формат вложения
T-API (Т-Бизнес) Счета в Т-Банке, нужен ежедневный поток 1-2 дня с тестами Токен 90 дней без использования, пагинация
Sber API Уже подключены к Sber API для ЮЛ Выше (OAuth, заявка) Лимит ~5 запросов/сек, scope MCP_STATEMENT
Вердикт: начните с CSV + Drive, если банк отдаёт файл. Переходите на T-API, когда устали от ручной выгрузки или счетов больше двух. Sber API - если интеграция уже одобрена банком.

Сделайте: один канал на счёт. Не делайте: параллельно CSV и API в один лист без hash - получите дубли.

Настройте импорт CSV из Google Drive через Apps Script

Google Apps Script - встроенный "супер-Excel" внутри таблицы: код сам читает папку, парсит CSV и дописывает строки. Официальный sample Import CSV data делает то же: trigger, append, перенос в processed/ и письмо с итогом.

  1. Создайте папку Drive bank_inbox и подпапку processed.
  2. Расширения → Apps Script → вставьте функцию импорта (фрагмент ниже).
  3. Укажите ID папки и имя листа staging в константах, не в ячейках таблицы.
  4. Запустите вручную, проверьте 5 первых строк против клиент-банка.
  5. После успеха включите time-driven trigger (следующий блок).
function importCsvFromDrive() {
  var folder = DriveApp.getFolderById('FOLDER_ID');
  var files = folder.getFilesByType(MimeType.CSV);
  var sheet = SpreadsheetApp.getActive().getSheetByName('staging');
  while (files.hasNext()) {
    var file = files.next();
    var rows = Utilities.parseCsv(file.getBlob().getDataAsString('UTF-8'));
    // map bank columns → staging, compute hash, skip duplicates
    sheet.getRange(sheet.getLastRow() + 1, 1, rows.length, rows[0].length).setValues(rows);
    file.moveTo(DriveApp.getFolderById('PROCESSED_FOLDER_ID'));
  }
}

Если в назначении кракозябры - пересохраните CSV в UTF-8 или укажите windows-1251 в getDataAsString. Комиссии банка часто идут отдельной строкой - не выкидывайте их при фильтре "только контрагенты".

Сделайте: лог ошибок на лист log. Не делайте: хранить пароли от клиент-банка в коде или ячейках.

Подключите e-mail или банковский API при необходимости

E-mail: фильтр писем от адреса банка → Apps Script GmailApp.search → Utilities.parseCsv на вложении → тот же staging. Помечайте письмо меткой "обработано", чтобы не парсить дважды.

T-API: токен в ЛК Т-Бизнес → Интеграции, scope "Счета и выписки". Запрос GET /api/v1/statement через UrlFetchApp: лимит 1-5000 операций, пагинация nextCursor, до 20 запросов в секунду. Данные с июня 2023, даты в ISO 8601 (UTC) - сверьте часовой пояс с вашим ДДС.

function fetchTinkoffStatement(token, account, from, to) {
  var url = 'https://business.tinkoff.ru/openapi/api/v1/statement?account=' +
    account + '&from=' + from + '&to=' + to + '&limit=1000';
  var resp = UrlFetchApp.fetch(url, {
    headers: { Authorization: 'Bearer ' + token },
    muteHttpExceptions: true
  });
  // map JSON operations → staging rows; loop while nextCursor present
}

Sber API: scope MCP_STATEMENT, метод выписки по рублёвому счёту. Старт тяжелее из-за OAuth - имеет смысл, если API уже выдан. Альтернатива оркестрации - Make или n8n, но Apps Script не требует отдельного сервера.

Сделайте: токены только в PropertiesService.getScriptProperties(). Не делайте: отправлять сырые выписки в ChatGPT для "разбора" - сначала обезличьте данные.

Поставьте ежедневный триггер и проверьте первую неделю

Расписание - как регламент закрытия месяца, только каждый день в одно время.

Схема: клиент-банк / API / почта → Apps Script → staging → (далее ДДС и сверка) → лист log при ошибке
  1. Создайте installable trigger: Extensions → Triggers → функция импорта, раз в день, час до начала рабочего дня.
  2. Или кодом: ScriptApp.newTrigger('importCsvFromDrive').timeBased().everyDays(1).atHour(7).create().
  3. Помните лимиты: не более 20 triggers на скрипт; runtime trigger 90 мин/день (consumer) или 6 ч (Workspace); один запуск до 6 минут.
  4. Неделю 1 сверяйте staging с клиент-банком построчно: даты, комиссии, знак суммы.
  5. UrlFetchApp: до 20 000 вызовов/день на consumer - для одной выписки с пагинацией хватает с запасом.

Сделайте: отдельный сервисный Google-аккаунт с доступом только к этой книге. Не делайте: включать trigger до ручной проверки - ошибка кодировки размножится на сотни строк.

Защитите токены и персональные данные

Облако Google - чужой сейф с ключами у провайдера: удобно, но выписка - коммерческая тайна. Токен банка в ячейке A1 увидит любой редактор таблицы; в Script Properties - только владелец скрипта.

  • Токены T-API и Sber - только Properties, ротация по регламенту (T-API: 90 дней без использования).
  • Не грузите полные реквизиты контрагентов в LLM; для анализа - обезличенная копия.
  • Ограничьте sharing книги: финотдел и собственник, не "вся компания".

Сделайте: чеклист безопасности из гайда по обезличиванию. Не делайте: публиковать скрин staging с живыми ИНН в Telegram или чатах.

Частые вопросы

Можно ли настроить импорт выписки без программиста?

Да для CSV: возьмите официальный sample Google, подставьте ID папки и проверьте вручную. T-API - по шаблону UrlFetchApp выше; Sber API чаще потребует помощи с OAuth на старте.

Сколько времени займёт внедрение?

CSV и trigger - один вечер. T-API с тестами - 1-2 дня. Sber API - от сроков заявки в банке плюс настройка токена.

Какие риски для персональных данных и 152-ФЗ?

Данные лежат в Google Cloud; ограничьте доступ к книге, токены в Properties, в нейросети только обезличенные копии. Пошаговый регламент - в статье про обезличивание.

Банк отдаёт только .txt для 1С - что делать?

Ищите экспорт CSV/Excel в клиент-банке. Если его нет - API банка или отдельный парсер txt; не пытайтесь "скормить" txt Sheets без маппинга полей.

Нужна ли 1С, если выписка уже в Sheets?

Нет для управленческого ДДС и сверки. 1С с DirectBank - другой маршрут, когда бухгалтерия живёт в учётной системе.

Make или n8n вместо Apps Script?

Да, если нужны десятки интеграций с уведомлениями. Apps Script проще, когда вся логика внутри одной таблицы - см. обзор no-code для финансов.

Как не задвоить операции при повторном импорте?

Колонка hash перед append, папка processed для CSV, метка на обработанных письмах. Перед append проверяйте, есть ли hash на staging.
