Выписки и реестры живут в Google Sheets, а собственник ждёт дайджест в Telegram к вечеру – руками это ломается на первом отпуске. Как установить n8n для финотдела: поднять self-hosted Docker с HTTPS, задать WEBHOOK_URL и собрать первый workflow Sheets → фильтр → Telegram. В итоге у вас свой "супер-Excel" между таблицей и чатом, без отдачи сырых выписок на чужой SaaS.

n8n – визуальный конструктор сценариев: узлы сами таскают данные между сервисами, как формулы между листами. Self-hosted здесь = свой сейф в офисе (или на вашем VPS), а не арендованная ячейка в чужом банке. Docker – упаковка программы "как есть": поставили контейнер и не собираете зависимости руками. Официальный образ – docker.n8n.io/n8nio/n8n; на дату статьи в docs указан stable 2.32.6 – для прода берите stable, не beta.

Зачем финотделу свой n8n, а не только ручные выгрузки

Ручной контур знаком: обновил лист → скопировал сумму → написал в Telegram. Работает, пока один человек и один файл. Как только появляется реестр ДДС и дебиторка, копипаст становится узким местом. Связка Sheets → n8n → Telegram закрывает дайджест собственнику без найма разработчика.

Я ставлю n8n, чтобы один раз описать правило: "новая строка с типом Расход и суммой больше X → короткое сообщение в чат". Базу no-code я разбирала в материале про автоматизацию финансов без кода; здесь – установка и первый рабочий контур.

Сделайте: выпишите 1–2 события, которые шлёте руками каждый день. Не делайте: тащить в первый workflow всю банковскую выгрузку – начните с дайджеста по одной таблице.

Выберите контур: Cloud или self-hosted под выписки и 152-ФЗ

Перед docker compose up решите, где живут данные. n8n Cloud удобен новичкам: сервис уже крутится, trial Starter/Pro без карты. По открытому прайсу (annually): Starter около 20€/мес (2,5K executions), Pro 50€ (10K). Execution – полный прогон сценария, не один шаг. Данные Cloud – на стороне n8n в EU (Frankfurt). Self-hosted Community бесплатен для внутреннего использования; сервер и обновления – на вас.

Критерий n8n Cloud Self-hosted (Docker)
Где данные Хостинг n8n (EU) Ваш VPS / сервер
Старт Минуты, без Docker Нужны Docker, домен, HTTPS
Выписки / ПДн Риск чужого контура Контролируете сами

Вердикт: для сырых выписок и живых ИНН я беру self-hosted. Cloud – только на уже обезличенных срезах. Полное сравнение с Make – отдельная тема; здесь фокус на установке n8n.

Сделайте: список полей, которые никогда не уезжают в облако. Не делайте: выбирать Cloud "потому что проще", если в Sheets лежат полные ФИО и номера счетов.

Установите n8n: Docker Compose, домен, HTTPS и WEBHOOK_URL

Официальный путь для прода – Docker Compose с Traefik (авто-HTTPS от Let's Encrypt) и доступом только по HTTPS. Порт редактора по умолчанию 5678; в проде его вешают на 127.0.0.1:5678, чтобы в интернет смотрел только reverse proxy. Tunnel/`--tunnel` – для локальной разработки, не для боевого сервера.

  1. Возьмите VPS с публичным IP. Установите Docker Engine и Docker Compose.
  2. Выделите домен. Создайте A-запись поддомена, например n8n → IP сервера. Дождитесь ответа DNS.
  3. Откройте на firewall только 80 и 443. Порт 5678 наружу не публикуйте.
  4. Скопируйте официальный пример Compose+Traefik из docs n8n. Заполните .env: DOMAIN_NAME, SUBDOMAIN, GENERIC_TIMEZONE=Europe/Moscow, SSL_EMAIL.
  5. Задайте N8N_PROTOCOL=https и WEBHOOK_URL=https://n8n.ваш-домен/ – без этого вебхуки и OAuth часто ломаются.
  6. Добавьте длинный N8N_ENCRYPTION_KEY (в менеджер паролей). За proxy: N8N_PROXY_HOPS=1.
  7. Запустите docker compose up -d. Откройте https://n8n.ваш-домен, создайте owner-аккаунт, проверьте timezone.
# ключевые переменные .env (подставьте свои значения)
DOMAIN_NAME=example.com
SUBDOMAIN=n8n
GENERIC_TIMEZONE=Europe/Moscow
SSL_EMAIL=fin@example.com
N8N_PROTOCOL=https
WEBHOOK_URL=https://n8n.example.com/
N8N_ENCRYPTION_KEY=сгенерируйте_длинную_строку
N8N_PROXY_HOPS=1

docker compose up -d
# обновление: docker compose pull && docker compose down && docker compose up -d

По умолчанию данные лежат в volume (часто SQLite в /home/node/.n8n). Для пилота хватает; PostgreSQL – через DB_TYPE=postgresdb, когда нужен запас по бэкапам. Ноутбук годится для учёбы на localhost; для дайджеста "пока я в отпуске" нужен сервер 24/7.

Сделайте: один HTTPS-инстанс с бэкапом volume. Не делайте: открывать http://IP:5678 в интернет "на пару дней".

Соберите первый workflow: Sheets → фильтр → Telegram

Цель вечера – одно сообщение: "в реестре появилась строка". Google Sheets Trigger ловит Row added / Row updated. У Google нет вебхука на лист, поэтому триггер идёт через polling – интервал в настройках ноды. API = защищённый курьер между таблицей и n8n.

  1. Google OAuth. На self-hosted нужен Custom OAuth2: Cloud Console → Sheets API + Drive API → OAuth Client → redirect URI из n8n (на проде HTTPS-домен + /rest/oauth2-credential/callback). Несовпадение даёт redirect_uri_mismatch.
  2. Тестовая таблица. Колонки: дата, тип, сумма, статья, комментарий. Без ИНН и полных ФИО – привычка из гайда по обезличиванию данных.
  3. Telegram-бот. BotFather /newbot (username на bot) → Access Token в credentials n8n. Узнайте chat_id чата или группы.
  4. Цепочка. Sheets Trigger (Row added) → IF/Filter (тип = Расход, сумма > порога) → Telegram Send a text message.
  5. Тест. Добавьте строку → смотрите Executions → включите Active.
Схема: Новая строка в Sheets → Trigger (polling) → Filter → Telegram-дайджест → (позже) напоминание по дебиторке

В Telegram: дата, статья, сумма, ссылка на лист – без выписки и паспорта контрагента. Тот же паттерн ляжет на реестр дебиторки и автонапоминания.

Если OAuth-приложение Google в режиме Testing, согласие живёт около 7 дней – credential придётся переподключать, пока не оформите статус по правилам Google.

Разборы сценариев – в канале "Финансист, который кодит".

Сделайте: один Active-workflow на тестовой таблице. Не делайте: слать в Telegram PDF с полной выпиской "для удобства".

Пройдите чек-лист безопасности перед продом

Автоматизация без паранойи по секретам – дыра шире экономии часа в неделю. Пройдите список до боевого реестра.

  • HTTPS обязателен; HTTP по IP:порт в интернет – нет.
  • Порт 5678 только localhost за Traefik/nginx.
  • N8N_ENCRYPTION_KEY задан и лежит в сейфе паролей.
  • WEBHOOK_URL с https совпадает с доменом.
  • Volume n8n в регулярном бэкапе.
  • Сильный owner-пароль; лишних пользователей нет.
  • Google OAuth: минимальные scopes, точный redirect URI.
  • Для бота – лист без лишних ПДн.
  • В Telegram не копируйте ИНН/ФИО "на всякий случай".
  • Токен бота и Client Secret не в git и не в общем Doc.
  • Обновления: pull → down → up -d.
  • Сырые выгрузки 1С не гоняйте через чужие SaaS – для локальной модели см. установку Ollama.

Сделайте: отметьте пункты галочками. Не делайте: считать self-hosted автоматическим соответствием 152-ФЗ – важны доступы и что уезжает в Telegram.

  2. Добавьте фильтр: только строки со статусом "на проверку финдиру".
  3. Свяжите инстанс с реестром дебиторки отдельным workflow.

Частые вопросы

Нужен ли VPS или хватит ноутбука с Docker?

Для учёбы хватит ноутбука и localhost:5678. Для дайджеста в отпуске берите VPS с доменом и HTTPS: машина 24/7, порт 5678 не в интернет.

Чем self-hosted n8n отличается от Make и n8n Cloud для финотдела?

Self-hosted держит сценарии и креды у вас. Cloud и Make быстрее стартуют, но данные идут через чужой контур. Для выписок и ПДн я выбираю Docker; для обезличенных пилотов Cloud допустим.

Можно ли работать без SSL, только по IP и порту?

Для прода – нет. Без HTTPS ломаются вход, OAuth Google и WEBHOOK_URL. Официальный Compose завязан на Traefik и Let's Encrypt.

Почему Google OAuth не коннектится на self-hosted?

Чаще всего неверный redirect URI или не включён Drive API вместе с Sheets. Нужен Custom OAuth2, не Managed. Сверьте URI символ в символ с тем, что показывает n8n.

Что писать в Telegram, чтобы не светить ПДн?

Дата, статья, сумма, код строки или ссылка на лист. Не отправляйте ИНН, полные ФИО, сканы и выписки целиком. Сомневаетесь – маскируйте поля до отправки.

Хватит ли SQLite или сразу ставить PostgreSQL?

Для пилота SQLite в volume обычно достаточно. PostgreSQL – когда растёт число executions или нужны предсказуемые бэкапы БД.

Как обновлять n8n без потери workflow?

Бэкап volume, затем docker compose pull, down, up -d. Не удаляйте named volume. После обновления проверьте Executions на тестовом workflow.
