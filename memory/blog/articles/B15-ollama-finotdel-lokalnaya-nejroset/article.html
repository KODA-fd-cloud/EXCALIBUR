Облачный ChatGPT удобен, пока в промпт не попадает выгрузка из 1С с ИНН и живыми суммами. Локальная нейросеть закрывает другой запрос: разобрать CSV и черновик пояснений внутри своего контура. Как установить Ollama для финотдела – ниже по шагам: установка, выбор модели под железо, рабочие сценарии, честные лимиты галлюцинаций и правило "сырое 1С не в облако".

Ollama – это рантайм, который поднимает языковую модель на вашем компьютере или сервере и отдаёт API, обычно на порту 11434. Простыми словами: свой сейф с нейросетью в офисе, а не арендованная ячейка в чужом банке. Движок бесплатный и открытый; у каждой модели свои лицензионные условия – их смотрите отдельно, если используете в коммерции.

Зачем финотделу локальная модель вместо ChatGPT

Не "вместо навсегда", а "для другого класса задач". В облако я не тащу сырые выгрузки, полные карточки контрагентов и внутренние регламенты с коммерческой тайной. Локально можно прогнать структуру файла, набросать категории ДДС и черновик текста к отчёту – при условии, что цифры потом сверите руками.

Критерий ChatGPT / облако Ollama локально
Данные Уходят к провайдеру Остаются на машине (если не включили облачные фичи)
Сила модели Обычно выше на сложных текстах Зависит от железа и размера модели
Стоимость токенов Подписка / API Электричество и время GPU/CPU
Когда брать Обезличенные задачи, сильный reasoning Черновики по внутренним CSV, пилот без облака
Вердикт: для финотдела Ollama – контур "можно трогать файл". Для сложных рассуждений на уже обезличенных данных облачная модель часто сильнее. Политика важнее бренда модели.

Сделайте: список "что никогда не уходит в облако". Не делайте: считать локальный запуск автоматическим compliance – доступ к папке и бэкапы тоже часть контура.

Установка Ollama и выбор модели под железо

Официальный путь: сайт ollama.com → установщик под Windows / macOS / Linux. На Windows это обычный Setup.exe, сервис появляется в трее. На Linux часто ставят одной командой install.sh. После установки проверьте версию в терминале и откройте в браузере http://localhost:11434 – должна быть служебная строка, что Ollama запущена.

  1. Скачайте и установите Ollama с официального сайта.
  2. В PowerShell/терминале: ollama --version.
  3. Проверьте API: браузер → http://localhost:11434.
  4. Выберите модель под память: на слабом ПК начинайте с компактных Qwen/Llama (порядка 7–8B в квантованном виде), не с гигантов.
  5. Запустите: ollama run qwen3:8b или актуальную короткую модель из библиотеки Ollama – первая загрузка скачает веса.
  6. Задайте тестовый промпт без секретов: "перечисли колонки, которые нужны для сверки двух CSV".

GPU (NVIDIA и совместимые стеки) ускоряет ответ; на CPU тоже можно, просто медленнее – это нормально для черновиков, плохо для "ответить за 2 секунды в чате собственнику". Миф "нужна карта за сотни тысяч" для старта преувеличен: важнее, чтобы выбранная модель влезала в память. На ноутбуке с 16 ГБ RAM разумнее маленькая квантованная модель, чем "самая умная" из каталога, которая уйдёт в своп и будет отвечать минутами.

Если нужен режим без облачных обращений самого Ollama, в гайдах 2026 фигурируют настройки вроде OLLAMA_NO_CLOUD=1 / отключение cloud в конфиге сервера – проверьте актуальную документацию на дату установки. По умолчанию сервис слушает localhost; не торчите порт 11434 в интернет без защиты. Для командного пилота лучше одна выделенная машина в LAN, чем "у каждого своя лама и свой хаос версий".

ollama --version
ollama pull qwen3:8b
ollama run qwen3:8b
# API: http://localhost:11434

Сделайте: одну рабочую модель и один тестовый чат. Не делайте: качать три огромные модели "про запас" и забивать диск.

Сценарии: сверка CSV, категоризация ДДС, черновик пояснений

Локальная LLM – не замена Excel и не замена бухгалтера. Три задачи, где она реально экономит время.

  1. Сверка структуры CSV. Скармливаете заголовки двух файлов (без полных ПДн) и просите: ключ сопоставления, какие колонки сумм, где риск разных разделителей.
  2. Категоризация ДДС. Даёте словарь статей и 20–50 обезличенных назначений платежа – модель предлагает статью; вы принимаете или правите.
  3. Черновик пояснений. На вход – уже посчитанные итоги (не сырой миллион строк): "объясни рост расхода по статье X на 12% к прошлому месяцу" – текст правите вы.
Схема: Выгрузка 1С → обезличивание / срез → CSV на диск → Ollama (промпт) → черновик → ручная проверка цифр → отчёт

Перед любым облачным чатом тот же принцип: маскируйте ИНН, ФИО, живые суммы при необходимости. Маршрут – в статье как обезличить финансовые данные перед ChatGPT. Локально правило мягче по утечке наружу, но привычку обезличивать я оставляю: меньше случайно утащить файл в облачный чат "по привычке".

Рабочий промпт для категоризации держите коротким: словарь статей + 20 строк назначений + инструкция "если не уверена – статья Прочее и комментарий почему". Так проще ловить ошибки, чем когда модель растекается на полстраницы "аналитики".

Сделайте: один пилот на 30 строках, не на годовой выгрузке. Не делайте: просить модель "пересчитай итог по файлу" без контрольной суммы в Excel.

Ограничения: галлюцинации цифр и ручная проверка

Модели уверенно ошибаются в арифметике и в "фактах из файла", которого они не видели целиком. Если контекст обрезан – получите красивый, но ложный вывод. Для финотдела это критично.

  • Итоги и проценты считайте в Excel/скрипте; модели отдавайте уже готовые числа для текста.
  • Любую сумму из ответа сверяйте с исходником (ctrl+F / сводная).
  • Не используйте ответ LLM как первичный учётный документ.
  • Длинные выгрузки режьте: сначала скрипт/сводная, потом пояснение.

Честно: на сложных таблицах сильная облачная модель часто аккуратнее маленькой локальной. Локальность покупает контур данных, не магию точности. Я отдельно запрещаю себе фразы модели вроде "итог сошёлся" без приложения контрольной суммы из скрипта или сводной. Если нужен агентный контур в терминале – смотрите также Claude Code для финотдела.

Типичный провал пилота: загрузили годовую выгрузку целиком, контекст обрезался, модель "домыслила" строки, финансист не заметил. Лечится дисциплиной среза: период, топ-N, уже агрегированные итоги.

Сделайте: чеклист "цифра в ответе = цифра в файле". Не делайте: вставлять ответ модели в письмо собственнику без сверки.

Связка с Cursor / скриптами и политика "сырое 1С не в облако"

Ollama отдаёт HTTP API. Cursor, скрипты и даже n8n в Docker могут ходить на него как на локальный endpoint (из Docker на хост часто нужен http://host.docker.internal:11434). Для финансиста практичный стек: папка с CSV + Cursor для скрипта сверки + Ollama для черновика текста по уже посчитанным итогам.

Политика, которую я фиксирую письменно в команде:

  • Сырые выгрузки 1С с ПДн – не в облачные чаты.
  • В индекс/чат локальной модели – только нужный срез или обезличенный файл.
  • Секреты (логины OData, пароли) – не в промпт.
  • Порт 11434 – только localhost или закрытая сеть.

Кейсы по локальному контуру и вайб-кодингу разбираю в Telegram "Финансист, который кодит". Уроки и материалы – в закрытом клубе KODA.

Сделайте: одну страницу политики данных финотдела. Не делайте: открывать Ollama в интернет "чтобы с телефона было удобнее".

Что дальше

  1. Установите Ollama и проверьте localhost:11434.
  2. Скачайте одну компактную модель и прогоните тестовый промпт без секретов.
  3. Подготовьте обезличенный CSV на 30 строк и сценарий категоризации или сверки структуры.
  4. Любые суммы из ответа сверьте с Excel.
  5. Зафиксируйте правило: сырое 1С не в облако; API только в контуре.

Частые вопросы

Какая видеокарта нужна для Ollama?

Желательна совместимая GPU с достаточным объёмом памяти под выбранную модель – так быстрее. Точную "минимальную карту" под каждую модель смотрите в карточке модели: важнее вместить веса, чем бренд.

Можно ли запускать Ollama только на CPU?

Да. Ответ будет медленнее. Для черновиков финотдела это часто приемлемо, для интерактива "здесь и сейчас" – раздражает.

Ollama бесплатна?

Сам движок – да, open source. Веса моделей качаются отдельно и у каждой своя лицензия; электричество и железо – ваши.

Чем локальная модель хуже ChatGPT?

Часто слабее на сложных рассуждениях и длинном контексте, сильнее по контролю данных. Выбор – по задаче, не по моде.

Безопасно ли скармливать выгрузки 1С в Ollama?

Безопаснее, чем слать их в облако, но не значит "можно всё". Ограничьте доступ к папке, не кладите лишние ПДн, не выставляйте API наружу.

Как связать Ollama с Cursor?

Через локальный API endpoint (порт 11434) в настройках совместимого провайдера/агента или через скрипт, который дергает API. Сначала проверьте ответ curl/браузером, потом подключайте IDE.
