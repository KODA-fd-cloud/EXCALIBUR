Платёжный календарь в Google Sheets – это не "красивая таблица на неделю", а список обязательств с датой, суммой и статусом, по которому видно кассовый разрыв до того, как он случится. n8n здесь не для автоплатежа в банк, а для напоминаний: дата подошла – ответственный получил Telegram или email. Ниже рабочий контур без ERP: колонки, формула разрыва, сценарий n8n и стыковка с банковской выпиской через staging.

Если уже автоматизируете финотдел без кода – рядом гайд автоматизация финансов no-code. Если боль в дебиторке, а не в исходящих платежах – реестр дебиторки и напоминания.

Соберите минимальные колонки календаря

Календарь – как очередь на кассе: кто, сколько, когда, в каком статусе. Лишние колонки "на всякий случай" убивают дисциплину заполнения. Старт – один лист calendar и справочник статусов.

Колонка Зачем Пример
due_date Дата платежа (обязательство) 2026-08-05
counterparty Кому платим ООО Ромашка
amount Сумма со знаком: расход < 0 или отдельная колонка type -150000
type in / out (приход / расход) out
status planned / approved / paid / skipped approved
owner Кто отвечает за оплату @olga
payment_id Стабильный ключ строки (для n8n и дедупа) pay_2026_08_05_romashka
note Договор, счёт, комментарий счёт 441
  1. Создайте таблицу → лист calendar с шапкой из таблицы выше.
  2. Заведите лист cash: дата, opening_balance, expected_in, expected_out, closing (формулы).
  3. Статусы только из списка: иначе n8n фильтр разъедется.
  4. payment_id сделайте уникальным: дата + контрагент + сумма или UUID.
  5. Запретите удалять оплаченные строки – меняйте status на paid.
  6. Первую неделю заполняйте вручную: зарплата, аренда, налоги, крупные поставщики.
Вердикт: 8 колонок хватает для малого финотдела. Не делайте: копию 1С "все счета учёта" в Sheets на старте.

Сделайте: 20–40 живых строк на ближайшие 14 дней. Не делайте: пустой шаблон "заполним потом".

Посчитайте кассовый разрыв без ERP

Кассовый разрыв – день, когда накопительный остаток уходит ниже нуля (или ниже вашего страхового остатка). Sheets считает это быстрее, чем ощущение "вроде хватит".

  1. На листе cash задайте стартовый остаток на сегодня (ячейка opening).
  2. По каждой дате: expected_in = SUMIFS приходов со status в {planned, approved}.
  3. expected_out = SUMIFS расходов с теми же статусами (paid уже в банке – не тащите второй раз).
  4. closing = opening + in + out; следующая строка opening = предыдущий closing.
  5. Подсветите условным форматированием closing < min_cash (например 200 000 ₽).
  6. Раз в день сверяйте opening с фактическим остатком по банку (см. staging ниже).
// псевдоформулы на листе cash (строка даты D)
// expected_out:
=SUMIFS(calendar!C:C, calendar!A:A, D2, calendar!E:E, "out", calendar!F:F, "<>paid")
// closing:
=B2+C2+D2

Практика: я держу горизонт 14 дней детально и 30 дней укрупнённо (неделями). Дальше 30 – шум, если нет твёрдых договоров. План зарплаты и налогов – отдельными строками с type=out и status=approved заранее, иначе разрыв "внезапно" в день выплаты.

Сделайте: один красный день на тесте = понятно, кого двигать. Не делайте: обещать точный прогноз на квартал из пустого календаря.

Настройте n8n: дата → Telegram/email ответственному

n8n – диспетчер напоминаний, не банк-клиент. Сценарий читает Google Sheet, фильтрует строки на сегодня/завтра со status=approved и шлёт сообщение owner.

  1. В n8n: Google Sheets → Read rows (лист calendar) по расписанию раз в час или в 09:00.
  2. Filter: due_date = сегодня (или ≤ сегодня) AND status = approved AND type = out.
  3. Optional: Ignore rows where reminded_at уже заполнен (колонка reminded_at).
  4. Telegram / Email: текст с counterparty, amount, due_date, payment_id.
  5. Update row: reminded_at = now, чтобы не спамить каждый час.
  6. Отдельная ветка: status стал paid → тихий лог или реакция в чат "закрыто".
Схема: Sheets (источник правды) → n8n Schedule → Filter → Telegram owner → Update reminded_at 
Напоминание оплаты
payment_id: pay_2026_08_05_romashka
Кому: ООО Ромашка
Сумма: -150000
Дата: 2026-08-05
Статус в таблице: approved

Без n8n можно начать с уведомлений Google Apps Script (time-driven + MailApp) – хуже масштабируется на несколько каналов, но для одного финансиста хватает. Excel Desktop + Power Automate – ок, если команда живёт в Microsoft 365, а не в Sheets.

Сделайте: один тестовый платёж на сегодня и реальное сообщение в Telegram. Не делайте: автосоздание платёжки в банк без ручной подписи.

Свяжите календарь с банковской выпиской через staging

Прямо писать "оплачено" из сырой выписки в calendar опасно: задвоите статусы и потеряете ручные правки. Staging – промежуточный лист raw_bank: дата, сумма, контрагент, назначение, hash строки.

  1. Импортируйте выписку CSV/Excel на лист raw_bank (не трогайте исходный файл).
  2. Считайте hash = дата|сумма|нормализованное назначение – для дедупа.
  3. Сопоставление с calendar: вручную или полуавтоматом по сумме+дате±2 дня+контрагенту.
  4. Только после матча ставьте status=paid и bank_hash в calendar.
  5. Несовпавшие строки raw_bank – очередь разбора, не "магия статуса".
  6. Opening на листе cash раз в день берите из банка, не из мечты календаря.

Подробнее про нормализацию выписки – в очереди темы staging; общий контур сверки CSV – сверка CSV на Python. Здесь важный контракт: calendar отвечает за будущее и решения, raw_bank – за факт банка.

Сделайте: правило "paid только с bank_hash". Не делайте: затирать planned-строки импортом выписки.

Что нельзя обещать: автоплатёж без контроля

Напоминание ≠ платёж. Автоплатёж без подписи – зона риска для кассы и для вас лично. В малом бизнесе нормальный DoD такой:

  • Календарь показывает разрыв и очередь на оплату.
  • n8n будит ответственного.
  • Человек проверяет остаток и проводит платёж в банк-клиенте.
  • Факт из выписки закрывает status=paid.
  • Никаких токенов банк-API "на весь счёт" в n8n "чтобы быстрее".
  • Два ответственных на крупные суммы (four-eyes) – если сумма выше порога.

Разборы таких контуров без сказок про "ИИ сам заплатит поставщикам" – в Telegram "Финансист, который кодит".

Сделайте: порог суммы, выше которого только ручная оплата. Не делайте: сценарий n8n → банк "в прод" без письменного правила.

Частые вопросы

Можно ли без n8n?

Да: Google Apps Script по таймеру + email/Telegram Bot API, или просто ручной просмотр листа утром. n8n удобен, когда каналов и фильтров становится больше одного.

Хватит ли Excel вместо Google Sheets?

Да, если файл в OneDrive/SharePoint и команда там живёт. Для n8n и одновременного доступа нескольких людей Sheets обычно проще.

Как не задвоить платежи?

Стабильный payment_id, статус paid только с bank_hash, запрет удалять строки, reminded_at против повторных алертов. Не импортируйте выписку поверх calendar.

Нужна ли 1С для платёжного календаря?

Нет для старта. 1С полезнее как источник факта (оплаты, остатки), а календарь решений может жить в Sheets и сверяться раз в день.

Что писать в Telegram-напоминании?

payment_id, контрагент, сумма, дата, статус. Без паники и без "срочно всем". Одна строка – одно действие.

Как часто гонять n8n?

Раз в день утром достаточно для малого объёма. Часовой cron – только если платежи появляются днём и owner реально реагирует.

Можно ли слать напоминание контрагенту, а не себе?

Для исходящих платежей – себе/финансисту. Контрагентам уместнее в контуре дебиторки (входящие деньги), это другой процесс.
