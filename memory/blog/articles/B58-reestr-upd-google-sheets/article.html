УПД подписан, оплата прошла, а на закрытии квартала всплывает: авансовый СФ не в реестре, исправительный документ без связи с исходным. Внутренний реестр УПД и счетов-фактур в Google Sheets с контролем комплекта (документ, договор, оплата, ЭДО) собирается за день без программиста. Ниже - структура листов, формулы kit_status, анти-дубли и регламент сверки без подмены журнала посредника и без сырых ПДн в облаке.

УПД объединяет первичку и СФ: статус "1" - с функцией счёта-фактуры, "2" - без СФ. С 1 января 2026 для ЭДО действует формат УПД 5.03; электронные ТОРГ-12 через операторов больше не ходят, бумага и неформализованный ЭДО без принуждения. С 1 апреля 2026 новая печатная форма: строка 5б для авансовых СФ, ОГРНИП вместо свидетельства ИП, ставка НДС 22% в колонках реестра. Официального шаблона "реестра УПД в Google Sheets" от ФНС нет - таблицу проектирует финотдел под свой комплект.

Журнал учёта счетов-фактур по ст. 174 НК обязателен посредникам и сдаётся в ИФНС ежеквартально. Внутренний реестр в Sheets - управленческий инструмент: одна строка на документ, контроль "дыр" между ЭДО, договором и оплатой. API оператора - как защищённый курьер между кабинетом ЭДО и таблицей: приносит метаданные без тел документов. Статусы ЭДО - в гайде по реестру статусов, no-code маршруты - в автоматизации финансов.

Оцените, когда реестр УПД в Google Sheets нужен финотделу (и когда нет)

Сделайте реестр в Sheets, если в месяц от 20 до 500 входящих и исходящих УПД и СФ, статусами пользуются бухгалтерия и закупки, а в 1С или кабинете ЭДО нет дашборда комплектности. Симптом: "есть УПД, нет оплаты" или "СФ без связанного УПД" всплывает на закрытии квартала. Не делайте Sheets заменой книг покупок/продаж, журнала СФ для посредников или учётной системы. Не делайте отдельный Excel на каждого менеджера - дубли и расхождения неизбежны.

Маршрут наполнения Когда выбирать Минус
Ручной ввод в день документа До 30–50 документов/мес, один ответственный Человеческий фактор, задержки

Вердикт: если комплектность документов бьёт по закрытию месяца - начните с двух листов "Исходящие" и "Входящие" и ручного ввода. Следующий шаг - CSV или API по шаблону статусов ЭДО.

Подготовьте данные и безопасность (без сырых ПДн в облако)

Зафиксируйте правило комплекта: для каждой сделки цепочка договор или заказ → УПД (статус 1 или 2) → при необходимости отдельный СФ → статус ЭДО → платёж. Одна строка реестра = один первичный документ с уникальным doc_key: ИНН + номер + дата + тип (УПД/СФ). Это как номер проводки в журнале: без ключа дубли не поймаете.

В таблицу кладите: ИНН, КПП, суммы, номера и даты, код операции (01 - продажа, 02 - аванс), ссылку на файл в Drive или кабинет ЭДО. Не кладите: паспортные данные, полные банковские реквизиты, сканы в общий доступ. Сканы - в папке Drive с ограниченным sharing, на листе только HYPERLINK. Перед ChatGPT или Claude замените контрагентов на "Контрагент_01", суммы округлите; чеклист - в гайде по обезличиванию. Сделайте: доступ по ролям Workspace. Не делайте: ссылку "anyone with the link can edit".

Настройте таблицу, формулы и сценарий наполнения пошагово

Схема workflow: документ в ЭДО или почте → строка в реестре → статус подписи → привязка к договору и оплате → kit_status OK → еженедельная сверка с 1С

Листы: Исходящие, Входящие, Справочник, log (ошибки импорта). Колонки: doc_key, тип (УПД/СФ), статус УПД (1/2), № и дата, контрагент, ИНН/КПП, сумма без НДС, НДС, всего, код операции, № договора, ссылка на файл, edo_status, payment_status, kit_status, ответственный, updated_at.

  1. Создайте листы Исходящие и Входящие с колонками выше; данные со второй строки. На Справочнике - edo_status (отправлен, ожидает подписи, подписан обеими, отклонён) и payment_status (не оплачен, частично, оплачен).
  2. Соберите doc_key формулой: =СЦЕПИТЬ(E2;"-";F2;"-";C2) где E - ИНН, F - номер, C - тип. Один ключ на документ - иначе merge из CSV создаст дубли.
  3. Настройте data validation для типа, статуса УПД, edo_status и payment_status - Reject input, чтобы произвольный текст не ломал фильтры.
  4. Анти-дубли: условное форматирование =СЧЁТЕСЛИ($A:$A;A2)>1 для doc_key - дубль виден до закрытия месяца.
  5. Формула kit_status: =ЕСЛИ(И(G2="1";ПУСТО(D2));"Дыра: УПД1 без СФ";ЕСЛИ(И(H2="подписан обеими";I2="оплачен");"OK";"Проверить")). Подстройте буквы столбцов под свою шапку.
  6. Условное форматирование: красный - kit_status содержит "Дыра"; жёлтый - edo_status "ожидает подписи" и дата старше 7 дней.
  7. Защитите шапку и формулы - случайная правка doc_key ломает сверку с 1С.
  8. Выберите маршрут наполнения: (A) ручной ввод в день документа; (B) CSV из ЭДО + merge; (C) API оператора; (D) n8n: папка incoming_docs → OCR → draft → approved бухгалтером.

Для маршрута B - скрипт merge по doc_key: обновляет существующую строку или добавляет новую, ошибки пишет на log.

function mergeCsvToRegistry() {
  var ss = SpreadsheetApp.getActiveSpreadsheet();
  var sheet = ss.getSheetByName('Входящие');
  var csv = ss.getSheetByName('csv_import').getDataRange().getValues();
  var data = sheet.getDataRange().getValues();
  var keyCol = 0;
  var keys = data.slice(1).map(function(r) { return r[keyCol]; });
  for (var i = 1; i < csv.length; i++) {
    var row = csv[i];
    var key = row[0];
    var idx = keys.indexOf(key);
    if (idx >= 0) {
      sheet.getRange(idx + 2, 1, 1, row.length).setValues([row]);
    } else {
      sheet.appendRow(row);
      keys.push(key);
    }
  }
  SpreadsheetApp.flush();
  Logger.log('Merge done, rows: ' + sheet.getLastRow());
}

Runtime Apps Script - до 6 минут на запуск, UrlFetch - 20 000 вызовов/день на consumer. Google Sheets API не атомарен: после записи скриптом перечитайте строку и сверьте doc_key. Связку с реестром договоров делайте по колонке № договора - не копируйте весь договор на лист УПД.

Проверьте результат и типичные ошибки

На первой неделе сверьте 10 случайных строк с кабинетом ЭДО или 1С. Отдельно проверьте: УПД статус 2 без отдельного СФ (это норма), аванс со строкой 5б, исправительный документ с привязкой к исходному doc_key. Регламент: новая строка - в день документа, edo_status - не реже раза в неделю при ручном контуре.

Ошибка Последствие Что сделать
Дата как текст Фильтры и CF молчат Формат ячейки "Дата"; проверка ISDATE
Разный формат номера Дубли doc_key и пропуски Единый шаблон: без пробелов, ведущие нули
УПД1 без строки СФ kit_status "Дыра" ложно или наоборот Статус УПД 1 = СФ внутри; отдельная строка только для чистого СФ

Не делайте сверку только по сумме - у разных контрагентов совпадения случаются. Делайте сверку по doc_key и контрагенту. УПД нельзя использовать, когда нужен только счёт-фактура без первички - такой документ в реестр как УПД не заносите.

Автоматизируйте дальше: ЭДО, договоры и очередь approval

Когда реестр стабилен, подключите авто-статусы ЭДО по API, связку с реестром договоров и очередь draft/approved через n8n - как супер-Excel, где строки сами приходят из папки, а бухгалтер только подтверждает. При более 1000 строк в месяц перенесите метаданные в 1С, Sheets оставьте дашбордом kit_status. Сценарии - в клубе KODA; материалы - на koda-fd.ru.

Частые вопросы

Можно ли обойтись без программиста?

Да. Структура листов, validation, kit_status и анти-дубли на формулах закрывают MVP за 2–4 часа. Скрипт merge - копипаст из статьи; API оператора - по шаблону из гайда по статусам ЭДО.

Сколько займёт внедрение?

Базовая таблица с двумя листами - 2–4 часа. CSV merge или триггер Apps Script - ещё 1–2 часа. Регламент внесения в день документа и доступы Drive - отдельный час, без них реестр устареет за неделю.

Какие риски для данных в Google Sheets?

Утечка через широкий sharing и лишние ПДн на листе. Ограничьте доступ, не храните паспортные данные и полные реквизиты счетов. Перед нейросетью обезличьте ИНН и суммы - см. гайд по обезличиванию.

Чем реестр в Sheets отличается от журнала учёта СФ?

Журнал СФ обязателен для посредников по ст. 174 НК РФ и сдаётся в ИФНС. Внутренний реестр в Sheets - для контроля комплекта у любой компании, не заменяет книги покупок/продаж.

Нужен ли реестр, если уже есть 1С и ЭДО?

Если 1С показывает комплект "документ, договор, оплата, ЭДО" - отдельный Sheets не обязателен. Если закупки и CFO не видят "дыр" без обхода кабинета - Sheets как дашборд kit_status оправдан.

Как учитывать УПД статус 2 и отдельные счета-фактуры?

УПД статус 2 - одна строка без отдельного СФ. Чистый СФ на аванс (строка 5б с апреля 2026) - отдельная строка с типом СФ и кодом операции 02. Связывайте с договором по № договора.

Когда пора уходить с Sheets на 1С?

Когда строк больше 1000 в месяц, нужен аудит правок и единый источник для НДС-отчётности. До этого Sheets + регламент даёт контроль комплекта без доработки ERP.
