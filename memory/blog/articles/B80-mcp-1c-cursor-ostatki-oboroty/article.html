Остатки по 62 счёту снова через "Сохранить как" в Excel, а потом кусками в чат Cursor? MCP к 1С даёт агенту "розетку" в учётную базу: вы спрашиваете на русском про остатки и обороты, Cursor вызывает tool и возвращает цифры из 1С без ручной выгрузки. За один вечер настроите read-only доступ через OData или HTTP-расширение, пропишете mcp.json и сверите 2–3 строки с оборотно-сальдовой ведомостью.

MCP (Model Context Protocol) – открытый протокол, через который Cursor подключает внешние инструменты. Простыми словами: без MCP агент видит только то, что вы вставили в чат; с MCP у него появляются кнопки-tools, и он сам ходит за свежими данными. API здесь – как защищённый курьер между 1С и редактором; JSON из tool – как структурированный акт сверки, где у каждого поля своё место.

Это следующий шаг после MCP для папки CSV: не файлы на диске, а живая база. Если OData уже опубликован – финансист может собрать пилот сам. Если нужно ставить расширение и IIS – зовите админа базы на вечер. Разовая выгрузка без повторов – проще через OData в Excel.

Оцените, когда MCP к 1С нужен финотделу (и когда нет)

Задача B80 – не "подключить модный протокол", а перестать таскать остатки и обороты через XLS в чат. Подходит, когда запросы повторяются: дебиторка по счёту 62, обороты по 41, сверка с управленческим срезом каждую неделю.

Нужно: ad-hoc аналитика на естественном языке, быстрая проверка "сколько на счёте X на дату Y", сверка перед совещанием без десятка Excel-вкладок.

Не нужно: OData и HTTP-сервис не опубликованы, админа нет, а достаточно разовой выгрузки – оставайтесь на B13 или CSV + filesystem MCP из B21. Не нужно, если ждёте "MCP = прямой SQL в базу" – работают только OData или HTTP-сервис с правами вашего пользователя 1С.

Вердикт: MCP к 1С для CFO – когда есть транспорт (OData или HTTP) и повторяющиеся вопросы к остаткам/оборотам. Не делайте: обещать "розетку в базу за час", если в браузере не открывается standard.odata и нет расширения под HTTP.

Сделайте: откройте в браузере URL OData вашей базы или спросите админа про HTTP-сервис – это gate до установки MCP. Не делайте: ставить десять MCP-серверов "из каталога" вместо одного рабочего контура к 1С.

Подготовьте данные и безопасность без сырых ПДн в облако

Текст запроса и ответ tool уходят в облачную модель Cursor – это риск 152-ФЗ и коммерческой тайны. Параллельно секреты базы не должны попасть в git.

  • Отдельный пользователь 1С только на чтение – без прав проведения и записи.
  • Пароли и URL базы – в переменных окружения или ${env:…} в mcp.json, не строкой в репозитории.
  • Privacy Mode в Cursor на пилоте; в промпт не вставляйте сырые ФИО, ИНН и полные наименования контрагентов.
  • Маскируйте тестовые данные: коды вместо имён, суммы с коэффициентом – подробнее в гайде по обезличиванию.
  • На пилоте оставляйте ручное подтверждение tool; Auto-run всех инструментов – только после понимания, что вызывается.
Критерий Трек OData (1c-odata-mcp) Трек HTTP (INFATON MCP35 / mcp-1c)
Что нужно в 1С Опубликованный standard.odata Расширение .cfe + HTTP-сервис, веб-сервер
Ключевые tools read.analytics.get_debtors, get_sales, get_cashflow get_balance, get_register_totals
Кто ставит Финансист, если OData уже живой Админ базы + веб-сервер (IIS/Apache)
Запись в базу Только чтение по умолчанию Зависит от расширения; на пилоте – read-only user

Сделайте: чеклист read-only user / env / gitignore до первого tool call. Не делайте: подключать боевую базу под пользователем с полными правами и паролем в открытом JSON.

Настройте MCP пошагово: OData или HTTP-расширение

Два рабочих маршрута к остаткам и оборотам. Выберите один; смешивать на пилоте не обязательно. Суммарно в Cursor рекомендуют держать порядка 40 MCP-tools – лишние серверы отключайте.

Схема: Cursor Agent → подтверждение tool → stdio-обёртка (Node/npx) → OData или HTTP POST /hs/mcp/ → 1С → JSON с остатками/оборотами

Трек A: OData через 1c-odata-mcp

  1. Проверьте OData в браузере: https://ВАШ_ХОСТ/…/odata/standard.odata – не 404.
  2. Установите Node.js LTS, если его ещё нет на рабочей машине.
  3. Создайте проектный файл .cursor/mcp.json в корне папки с проектом финотдела.
  4. Добавьте сервер с npx; URL и логин read-only – через env.
  5. Сохраните JSON и полностью перезапустите Cursor.
  6. Откройте Settings → Tools & MCP (Ctrl+Shift+J): дождитесь зелёного индикатора.
  7. В Agent запросите: "Покажи дебиторскую задолженность по счёту 62 за июль 2026" – подтвердите вызов read.analytics.get_debtors.
{
  "mcpServers": {
    "onec-odata": {
      "command": "npx",
      "args": ["-y", "1c-odata-mcp"],
      "env": {
        "ONEC_ODATA_URL": "https://ВАШ_ХОСТ/base/odata/standard.odata",
        "ONEC_USERNAME": "${env:ONEC_READONLY_USER}",
        "ONEC_PASSWORD": "${env:ONEC_READONLY_PASS}"
      }
    }
  }
}

Трек B: HTTP-расширение и get_balance

  1. Попросите админа установить расширение INFATON MCP35 (или feenlace mcp-1c) и опубликовать HTTP-сервис для расширения на IIS/Apache.
  2. Убедитесь, что endpoint отвечает по Basic Auth (например POST на /hs/mcp/).
  3. Клонируйте репозиторий MCP35 или скачайте бинарник mcp-1c – укажите URL и учётку в env.
  4. Пропишите сервер в mcp.json с command node index.mjs или путь к exe.
  5. Перезапустите Cursor, проверьте зелёный статус в Tools & MCP.
  6. В Agent: "Остатки и обороты по счёту 62 за период 01.07.2026–31.07.2026 с разбивкой по контрагентам" – tool get_balance.
{
  "mcpServers": {
    "onec-http": {
      "command": "node",
      "args": ["D:/mcp/MCP35/index.mjs"],
      "env": {
        "ONEC_URL": "https://ВАШ_ХОСТ/base",
        "ONEC_USER": "${env:ONEC_READONLY_USER}",
        "ONEC_PASSWORD": "${env:ONEC_READONLY_PASS}"
      }
    }
  }
}

Пути и имена переменных сверьте с README выбранного сервера – у OData и HTTP-обёрток они отличаются. Сделайте: один трек до первого успешного tool. Не делайте: копировать пароль в args вместо env.

Проверьте результат и типичные ошибки

Definition of Done – не "зелёная лампочка", а совпадение цифр с отчётом 1С. Откройте "Оборотно-сальдовую ведомость" или "Ведомость по счёту" за тот же период и сверьте 2–3 строки: сальдо начальное, оборот Дт/Кт, сальдо конечное.

  1. Зафиксируйте один счёт и один период для теста (например 62, июль 2026).
  2. Запустите тот же срез в типовом отчёте 1С и сохраните скрин или выгрузку для сравнения.
  3. Сравните итоги и 2–3 контрагента с ответом Agent после tool call.
  4. Если цифры "из головы" без вызова tool – повторите промпт с явным "используй MCP tool get_balance / get_debtors".
  5. При красном индикаторе откройте Output → MCP Logs: частые причины – нет Node, неверный URL, 401/403, база не опубликована.

Типичные ошибки: OData не включён – 1c-odata-mcp не подключится к COM/SQL напрямую. HTTP 401 – логин не read-only или неверный Basic Auth. Пустой ответ – период или счёт указаны в формате, который tool не понимает; уточните account_code и period_from/period_to. Слишком много tools – отключите лишние MCP-серверы в Cursor.

Сделайте: сверку как обязательный шаг пилота. Не делайте: принимать ответ агента без tool call как источник для управленческих решений.

Автоматизируйте дальше: что подключить после пилота

После get_balance / get_debtors логично расширить контур: get_register_totals для регистров накопления, get_cashflow для ДДС, связка с CSV-fallback из B21 на случай недоступности базы.

  1. Добавьте второй tool-сценарий (обороты по регистру накопления или cashflow).
  2. Зафиксируйте шаблон промпта в rules или заметке финотдела – период, счёт, разбивка.
  3. Настройте регламент обезличивания перед каждым ad-hoc запросом с контрагентами.
  4. Если нужен свой HTTP под приложение – смотрите очередь B81; no-code автоматизацию вокруг – в автоматизации финотдела no-code.
  5. Не раздувайте число MCP-серверов: один контур к 1С + при необложенности filesystem на папку выгрузок.

Разборы интеграций 1С и Cursor публикую в Telegram "Финансист, который кодит". Уроки по автоматизации финконтура – в закрытом клубе KODA.

Сделайте: один стабильный сценарий "остатки/обороты + сверка" перед новыми tools. Не делайте: включать запись в базу через MCP без двойного предохранителя и без согласования с админом.

Частые вопросы

Можно ли подключить MCP к 1С без программиста?

Да, если OData уже опубликован: ставите 1c-odata-mcp через npx, прописываете mcp.json и read-only пользователя. Если нужно расширение, публикация "для расширения" и IIS – минимум админ базы на один вечер.

Сколько времени займёт первый рабочий запрос?

При готовом OData – 1–2 часа на smoke-test и сверку с ОСВ. С нуля HTTP + расширение – ориентир один вечер с админом; зависит от инфраструктуры и версии платформы (для INFATON MCP указывают 1С 8.3.20+).

Какие риски для данных при MCP к 1С?

Утечка через облачную модель (текст запроса + JSON ответа) и компрометация учётки в git. Снижайте: read-only, env-секреты, обезличивание, Privacy Mode, ручное подтверждение tools.

MCP даёт прямой SQL к базе 1С?

Нет. Только OData или HTTP-сервис; права ограничены пользователем 1С. execute_query в mcp-1c – SELECT через HTTP, не произвольный доступ к SQL-серверу.

Чем это отличается от MCP для CSV-папки (B21)?

B21 читает файлы на диске через filesystem MCP. B80 ходит в живую базу 1С tools get_balance / get_debtors – без промежуточного XLS в чат.

Нужно ли ставить BSL Language Server MCP?

Нет для финотдела. BSL MCP – для разработчиков 1С (код, метаданные). Для остатков и оборотов берите OData или HTTP data-серверы из таблицы выше.
