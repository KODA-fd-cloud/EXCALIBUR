Каждый новый чат в Cursor снова объясняете: не коммить data/, не совать ИНН в промпт, скрипты класть в scripts/. Через час агент предлагает "для удобства" залить сырую выгрузку 1С в репозиторий. Cursor Rules для финотдела – это короткий устав в файлах проекта: стиль, папки и запреты, которые подхватываются без копипаста в каждый диалог.

Rules – не "магический system prompt навсегда". Это инструкции, которые Cursor подмешивает в контекст агента по правилам проекта. Простыми словами: как регламент закрытия месяца, только для ИИ, который правит код рядом с вашими CSV.

Связка такая: база знаний и промпты – в базе знаний ChatGPT/Cursor для финотдела; вечерний пилот скрипта – в Cursor: скрипт и дашборд; здесь – как закрепить правила, чтобы пилоты не разъезжались.

Поймите, зачем rules, если "и так понятно из чата"

Чат забывчив. Новый Agent не читает вашу голову. Rules лежат в git и едут к коллеге вместе с репозиторием. Без них каждый раз заново торгуетесь с моделью про ПДн и структуру папок.

Соберите минимальный набор правил финотдела

Не пишите роман. Rules, которые нельзя проверить действием, агент игнорирует первым. Ниже – каркас, который я кладу в пилоты со сверками и выгрузками.

  • Структура: data/ вход, out/ отчёты, scripts/ или src/ код; сырые CSV не в корне.
  • .gitignore: data/*.csv, .env, *.xlsx с ПДн.
  • Запрет: не вставлять в чат сырые ФИО/ИНН/телефоны; обезличивать – по гайду обезличивания.
  • Запрет: не коммитить выгрузки 1С и пароли OData/HTTP.
  • Стек по умолчанию: Python + pandas для сверки; Google Sheets / Apps Script – если проект про таблицы.
  • DoD: что считать готовым (файл в out/, print summary, без рефакторинга "всего мира").
  • Диффы: не переписывать проект целиком без явной просьбы.
  1. Откройте папку пилота в Cursor.
  2. Создайте AGENTS.md в корне с коротким уставом (см. следующий блок).
  3. Добавьте .cursor/rules/finotdel-security.mdc с alwaysApply: true.
  4. Добавьте .cursor/rules/python-reconcile.mdc с globs на **/*.py.
  5. В Customize → Rules проверьте, что файлы видны и тип применения верный.
  6. Новый чат Agent: "предложи структуру папки" – сверьте, что не предлагает коммитить data/.

Сделайте: security always + один scoped rule. Не делайте: alwaysApply на все подряд – сжигаете контекст.

Напишите пример AGENTS.md и project rules

По докам Cursor 2026 канон project rules – файлы .mdc в .cursor/rules/ с frontmatter description / globs / alwaysApply. AGENTS.md – простой markdown без frontmatter; вложенные AGENTS.md в подпапках поддерживаются, более глубокий приоритетнее. Legacy .cursorrules лучше мигрировать и удалить, не держать оба формата.

# AGENTS.md
Ты помогаешь финотделу автоматизировать сверки и отчёты.

Папки: data/ (вход), out/ (результаты), scripts/ (код).
Не коммить data/*.csv и .env.
Не проси сырые ПДн в чат. Ключи – коды, не ФИО/ИНН.

Стек по умолчанию: Python + pandas.
DoD: out/diffs.csv + краткий summary в терминале.
Не переписывай весь проект без явной просьбы.
---
description: Запреты ПДн и выгрузок 1С для финотдела
alwaysApply: true
---

# Security finotdel
- Не предлагай commit файлов из data/.
- Не вставляй пароли 1С/OData в код или mcp.json.
- Сырые выгрузки 1С не копируй в чат; только обезличенные срезы.
- Секреты – .env + .gitignore.
---
description: Стиль pandas-скриптов сверки CSV
globs:
  - "**/*.py"
alwaysApply: false
---

# Python reconcile
- Один скрипт – одна задача.
- read_csv: явно encoding и sep; ключи dtype str.
- Расхождения: merge how=outer, indicator=True.
- Результат в out/, без записи обратно в data/.

Создать rule можно через /create-rule в чате или Customize → Rules → Add Rule. Plain .md в .cursor/rules без frontmatter система rules игнорирует – нужен .mdc или выносите текст в AGENTS.md.

Четыре режима применения, коротко: Always – в каждый чат (только security и папки); Apply Intelligently – по description, когда агент сам решит; globs – когда в контексте файлы под маской; Manual – только если @упомянули rule. Для финотдела я почти не трогаю Manual на старте: про него забывают.

Проверка "правило живое": откройте Customize → Rules и убедитесь, что security в статусе Always, а python-rule прикрепляется к .py. Затем в Agent намеренно попросите "добавь data/bank.csv в git" – хороший устав должен отговорить или предложить .gitignore, а не git add.

Сделайте: три файла как выше и один тестовый чат с провокацией на commit data/. Не делайте: переносить в rules весь учебник pandas.

Свяжите rules с базой знаний и MCP

Rules говорят "как себя вести". База знаний – "что уже решили по методологии". MCP – "какими инструментами трогать диск". Без связки агент либо болтает абстрактно, либо лезет не туда.

  1. В AGENTS.md укажите путь к внутренней базе (папка kb/ или ссылка на гайд B16) и правило: сначала читай kb, потом выдумывай.
  2. Если используете filesystem MCP – в security-rule пропишите: только узкий path data/, не диск C.
  3. Запретите Auto-run всех tools на пилоте; подтверждение вызовов обязательно.
  4. Для табличного контура добавьте rule с globs на Code.gs / *.gs: секреты только Script Properties.
  5. Проверьте конфликт: User Rules не должны отменять запрет ПДн проекта.
Схема: AGENTS.md (устав) → rules/*.mdc (скоуп) → kb/ (методология) → MCP path (инструмент)

Сделайте: одно предложение в AGENTS.md про MCP path и kb/. Не делайте: подключать 10 MCP "потому что в топ-списке".

Внедрите в команду один шаблон без культа сложности

Один репозиторий-шаблон fin-pilot-template с AGENTS.md, .gitignore и двумя mdc. Клонируете под задачу сверки – правила уже на месте. Team Rules из дашборда Cursor полезны на большой команде; для двух-трёх человек хватает git.

  • Не плодите rule на каждый чих: 1 always security + 2–3 scoped.
  • Раз в месяц режьте мёртвые правила – иначе контекст засоряется.
  • Критичное дублируйте техникой: .gitignore и права папок; rules модель может проигнорировать.
  • Hooks/Skills – следующий уровень; на старте не смешивайте с rules.
  • Онбординг: "открой шаблон, прочитай AGENTS.md вслух, запусти тестовый чат".
  • Имена файлов rules – говорящие: finotdel-security.mdc, не rules1.mdc.
  • Вложенный AGENTS.md в scripts/ имеет смысл, только если там другой стек; иначе плодите противоречия.

Если в команде уже есть Claude Code или другие агенты, AGENTS.md остаётся общим языком: его читают несколько инструментов. Узкие Cursor-фичи (globs, agent-requested) оставляйте в .mdc – так не тащите Cursor-only синтаксис в чужой рантайм.

Короткие разборы таких шаблонов – в Telegram "Финансист, который кодит".

Сделайте: шаблон в git и один общий PR с rules. Не делайте: требовать 20 файлов rules как "культуру инженерии".

Частые вопросы

Rules работают на бесплатном тарифе Cursor?

Сами файлы rules – часть продукта и читаются в проекте. Лимиты Agent и моделей зависят от плана: сверяйте актуальный cursor.com/pricing. Без Agent правила бесполезны как "текст в папке".

Чем rules отличаются от system prompt / User Rules?

User Rules – ваши локальные привычки на все проекты. Project rules и AGENTS.md лежат в репозитории и шарятся с командой. System prompt модели вы не редактируете – только эти слои.

Нужны ли rules, если в команде один человек?

Да. Вы же не хотите каждый раз заново запрещать коммит data/. Для соло хватает AGENTS.md и одного always-security.

Сколько файлов rules достаточно на старте?

Один AGENTS.md плюс два-четыре .mdc. Если больше десяти в первый день – вы усложняете онбординг, а не помогаете агенту.

Модель всё равно нарушила правило. Что делать?

Усильте формулировку действием ("не предлагай git add data/"), продублируйте .gitignore, в чате явно @rule. Критичное не оставляйте только на текст rules.

Удалять ли старый .cursorrules?

После переноса в .cursor/rules/*.mdc с alwaysApply – да. Держать оба формата не стоит: поведение становится неочевидным.

Как связать rules с MCP?

В security-rule укажите узкий path filesystem MCP и запрет секретов в mcp.json. Сначала зелёный MCP на data/, потом расширение прав.
