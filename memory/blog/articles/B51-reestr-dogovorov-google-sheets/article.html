Договор подписан, скан лежит в папке, а срок оплаты или отказ от пролонгации всплывает уже после дедлайна. Реестр договоров в Google Sheets с графиком платежей и email-напоминаниями даёт финотделу одну таблицу вместо разрозненных Excel и переписки в мессенджерах. Ниже соберёте листы "Реестр" и "График оплат", настроите подсветку просрочки, ежедневный скрипт Apps Script и простой регламент: кто вносит договор в день подписания и как смотреть горизонт 30–45 дней.

Реестр договоров - журнал, где одна строка = один контракт: контрагент, сумма, сроки, ответственный, статус. Закон не требует обязательного реестра у всех (в отличие от 44-ФЗ), но без него CFO узнаёт о просрочке оплаты или автопродлении на планёрке. Договоры с контрагентами хранят 5 лет после прекращения (ст. 29 ФЗ-402, ст. 23 НК РФ) - таблица фиксирует сроки и ссылку на скан, не заменяя архив бухгалтерии.

Оцените, когда реестр в Google Sheets нужен финотделу (и когда нет)

Сделайте реестр в Sheets, если до 200–300 активных договоров, один владелец таблицы (офис-менеджер или финансист) и нет готового CLM или модуля в 1С. Типичный симптом: срок оплаты ищут в почте, а пролонгацию вспоминают за неделю до окончания. Не делайте Sheets единственным источником правды, если нужен жёсткий аудит изменений, сложные права доступа по контрагентам или сотни договоров с ежедневной синхронизацией с ERP - тогда таблица станет staging-слоем, а не заменой 1С.

Маршрут Когда выбирать Минус
Google Sheets (формулы + CF) Малый и средний финконтур, один владелец Без скрипта напоминания только визуальные
Sheets + условные уведомления Workspace, письмо при смене статуса ячейки Не срабатывает на пересчёт TODAY() ночью
Sheets + Apps Script Ежедневные email по датам оплаты и окончания Квота MailApp, лимит 6 мин на запуск
1С / CLM Аудит, ACL, интеграция с учётом Дольше внедрение, абонплата или IT
Вердикт: если просрочки по оплате и пролонгации бьют по дисциплине финотдела - начните с Sheets-реестра. Следующий уровень no-code - в гайде по автоматизации финансов.

Подготовьте данные и безопасность (без сырых ПДн в облако)

Создайте файл с листами Реестр, График оплат и Справочник. На Реестре - одна строка на договор: внутренний №, номер и дата договора, контрагент, ИНН, предмет, сумма, даты начала/окончания, автопродление, срок уведомления об отказе (дней), ответственный (email), статус, ссылка на скан в Drive. На Графике оплат - платежи: № договора, дата, сумма, тип (аванс, этап, финал), статус оплаты. Внутренний № - как номер в журнале проводок: не меняется при допсоглашении.

Безопасность: в таблицу кладите ИНН и деловые реквизиты, но не паспортные данные и адреса контактных лиц. Сканы - в папке Drive с ограниченным sharing, на листе только HYPERLINK. Не отправляйте файл с реальными контрагентами в ChatGPT - замените названия на "Контрагент_01", суммы округлите; чеклист - в гайде по обезличиванию. Сделайте: доступ по ролям Workspace (финотдел редактирует, остальные - просмотр). Не делайте: общую ссылку "anyone with the link can edit".

Настройте таблицу, формулы и напоминания пошагово

Схема workflow: договор подписан → строка в реестре → график оплат → подсветка сроков → ежедневный скрипт → email ответственному → еженедельный обзор 30–45 дней
  1. Создайте лист Реестр с колонками из блока подготовки; данные со второй строки. Статусы в Справочнике: "Действует", "Завершён", "Расторгнут", "На согласовании". Data validation "Dropdown from range" с Reject input - произвольный текст ломает фильтры и скрипт.
  2. Добавьте лист График оплат. Каждый платёж - отдельная строка по внутреннему №. Договор с тремя этапами даёт три строки, а не три колонки.
  3. Формула "дней до окончания": =J2-СЕГОДНЯ() или =DATEDIF(СЕГОДНЯ();J2;"D"). Дедлайн отказа от пролонгации: =J2-N2 (N2 - дней уведомления из договора, типично 30).
  4. Условное форматирование: красный - дата окончания < СЕГОДНЯ(); жёлтый - ≤30 дней; на Графике - неоплаченные с датой в прошлом.
  5. Защитите заголовки и формулы, чтобы случайная правка не сломала DATEDIF и списки.
  6. Канал напоминаний: условные уведомления (Инструменты → Условные уведомления) - письмо при смене статуса; для календарных дат - Apps Script + daily trigger, т.к. TODAY() при закрытом файле письмо не шлёт.
  7. Скрипт sendReminders(): Расширения → Apps Script, обход строк Графика и Реестра, MailApp.sendEmail, триггер Day timer 08:00.
function sendReminders() {
  var ss = SpreadsheetApp.getActiveSpreadsheet();
  var payments = ss.getSheetByName('График оплат');
  var today = new Date();
  today.setHours(0, 0, 0, 0);
  var reminderDays = 3;
  var data = payments.getDataRange().getValues();
  for (var i = 1; i < data.length; i++) {
    var due = new Date(data[i][2]);
    due.setHours(0, 0, 0, 0);
    var status = data[i][5];
    var email = data[i][6];
    if (status === 'Оплачен' || !email) continue;
    var diff = (due - today) / (1000 * 60 * 60 * 24);
    if (diff === 0 || diff === reminderDays) {
      MailApp.sendEmail(email,
        'Напоминание: оплата по договору ' + data[i][0],
        'Дата платежа: ' + Utilities.formatDate(due, 'GMT+3', 'dd.MM.yyyy') +
        ', сумма: ' + data[i][3]);
    }
  }
  Logger.log('Quota left: ' + MailApp.getRemainingDailyQuota());
}

Перед деплоем проверьте квоту MailApp: считаются получатели, не письма - 100/день на consumer Gmail, до 1500 на Workspace. Runtime скрипта - до 6 минут. Правило владельца: договор вносите в день подписания, допсоглашение обновляет сумму и срок в тот же день - иначе напоминания уходят по устаревшим датам.

Проверьте результат и типичные ошибки

Добавьте тестовую строку с датой платежа "завтра" и email себе. Запустите sendReminders() вручную, откройте Executions log - там видны ошибки имени листа или типа данных. Проверьте MailApp.getRemainingDailyQuota(). Раз в неделю просматривайте горизонт 30–45 дней: пролонгация, отказ, крупные платежи.

Ошибка Последствие Что сделать
Дата как текст Скрипт не сравнивает, CF молчит Формат ячейки "Дата"; проверка через ISDATE
Без setHours(0,0,0,0) Напоминание "день в день" пропускается Обнулять время у today и dueDate в коде
Неверное имя листа Exception в Executions Имена в getSheetByName() = вкладки файла
Дубли писем Спам ответственным Колонка "Напоминание отправлено" или PropertiesService
Только CF, без скрипта Никто не открыл таблицу - дедлайн прошёл Ежедневный trigger + еженедельный обзор CFO

Условные уведомления Workspace доступны не во всех аккаунтах - если пункта нет в меню, сразу идите в Apps Script. Квота UI Gmail и MailApp в скрипте - разные вещи.

Частые вопросы

Можно ли обойтись без программиста?

Да. Таблица на формулах, списках и условном форматировании закрывает MVP за 2–4 часа. Скрипт - копипаст из статьи и правка имён листов; Gemini в Workspace поможет переписать цикл, если файл обезличен.

Сколько займёт внедрение?

Базовый реестр и график оплат - 2–4 часа. Apps Script с триггером и тестом - ещё 1–2 часа. Регламент владельца и доступы Drive - отдельный час, без них напоминания не спасут.

Какие риски для данных в Google Sheets?

Утечка через широкий sharing и лишние ПДн на листе. Ограничьте доступ, не храните паспортные данные, сканы - по ссылке в защищённой папке. Перед нейросетью замените контрагентов и суммы - см. гайд по обезличиванию.

Чем отличается дедлайн пролонгации от даты оплаты?

Дата оплаты - строка на "Графике оплат". Дедлайн пролонгации - последний день отказа от автопродления (обычно за 30–45 дней до окончания). Разные колонки и разные напоминания в скрипте.

Нужен ли Google Workspace для email-напоминаний?

Consumer Gmail шлёт через MailApp, но квота 100 получателей/день. Для финотдела с десятками ответственных надёжнее Workspace и корпоративный домен.

Когда пора уходить с Sheets на 1С или CLM?

Когда договоров больше 300, нужен аудит правок и интеграция с учётом без ручного дубля. До этого Sheets + Apps Script даёт контроль сроков без абонплаты CLM.

Заменят ли условные уведомления ежедневный скрипт?

Нет. Они реагируют на изменение ячейки, а не на календарную дату ночью. Для "за 3 дня до оплаты" нужен time-driven trigger и MailApp.
