На Хабр Q&A №891699 автор описал знакомую боль: в Excel и Power Query OData к 1С подключается, в браузере с Basic Auth тоже, а скрипт Google Apps Script падает с "Адрес недоступен". Встроенного OData-коннектора в Google Sheets нет. Решение – один раз настроить публикацию 1С, открыть доступ для IP Google и написать короткий Apps Script с UrlFetchApp. После гайда у вас будет кнопка "Обновить из 1С" и staging-лист без сырых персональных данных в облаке.

OData – REST-интерфейс 1С (протокол 3.0): защищённый курьер между базой и таблицей. URL вида …/odata/standard.odata/ИмяРесурса + логин на чтение → JSON, как акт сверки с именованными полями. Apps Script ходит за ним через UrlFetchApp. Публикацию OData, HTTPS и whitelist IP Google админ делает один раз; если база только в LAN без интернета – GAS не поможет, нужен CSV или no-code.

Когда это нужно финотделу (и когда нет)

Сначала сверьте задачу с инструментом. Habr Q&A 891699 как раз про живой срез в общей Google-таблице, когда Excel на одном ПК уже неудобен, а команда работает в Sheets.

Сценарий Sheets + Apps Script + OData Альтернатива
Общий дашборд ДДС, остатков, справочников Да: кнопка обновления, несколько редакторов Power Query в Excel, если все с одного ПК
Разовая выгрузка "на глаз" Избыточно "Сохранить как" или Excel/OData
Отчёты СКД, регламентные задания, журнал регистрации Нет: стандартный OData их не отдаёт Обработка 1С или SQL
База только в LAN без HTTPS Нет: UrlFetchApp не дойдёт Файл на Диск или no-code автоматизация финансов
Вердикт: берите Sheets + GAS, если нужен повторяемый срез в облачной таблице и админ готов один раз открыть OData наружу по HTTPS. Не делайте: тащить в облако полные карточки физлиц и контрагентов с ИНН "на всякий случай".

Сделайте: зафиксируйте одну сущность (например, статьи ДДС или движения денег) и период. Не делайте: обещать себе "выгружу всю базу одним запросом" – у скрипта лимит около 6 минут на запуск и квоты Url Fetch.

Подготовка данных и безопасность (без сырых ПДн в облако)

Sheets – чужой облачный контур; Basic Auth без HTTPS передаёт пароль открытым текстом.

  1. Отдельный пользователь 1С на чтение с ролью УдаленныйДоступOData.
  2. Узкий состав OData: нужные Catalog_* и регистры, без Catalog_ФизическиеЛица, если ФИО не нужны.
  3. HTTPS с валидным сертификатом – самоподписанный SSL UrlFetchApp отвергнет.
  4. Staging-лист raw_*; на отчётный лист – коды и агрегаты, не полные реквизиты.
  5. Логин и пароль в PropertiesService, не в ячейке и не в чате.
  6. Перед LLM обезличьте данные – маршрут в гайде по обезличиванию перед ChatGPT.

Сделайте: чеклист "что можно в облако" до кнопки. Не делайте: учётку админа 1С и пароль в коде, как в Q&A без Properties.

Пошаговая настройка: от админа 1С до скрипта Apps Script

Маршрут, закрывающий Habr Q&A 891699. Имена сущностей берите из $metadata, не угадывайте.

Схема: админ публикует OData → тест URL в браузере → whitelist IP Google → Script Properties → UrlFetchApp + Basic Auth → парсинг JSON → лист raw_* → меню "Обновить из 1С"
  1. Чеклист для админа 1С: публикация на IIS/Apache (1С не ниже 8.3.5), галка "Публиковать стандартный интерфейс OData", узкий состав объектов, отдельный read-only пользователь, HTTPS, allowlist диапазонов IP Google на firewall (запросы GAS идут не с ПК пользователя, а из пула Google).
  2. Проверьте эндпоинт вручную: откройте https://ВАШ_ХОСТ/…/odata/standard.odata/$metadata, затем Catalog_СтатьиДвиженияДенежныхСредств?$format=json&$top=10 с Basic Auth в браузере или Postman. Должен прийти JSON с массивом value, не HTML-ошибка.
  3. Откройте таблицу → Расширения → Apps Script. Создайте лист raw_dds (или другое имя под ваш регистр).
  4. Один раз выполните функцию сохранения учётки (Run в редакторе):
function saveOnecCredentials(baseUrl, user, password) {
  PropertiesService.getScriptProperties().setProperties({
    ONEC_BASE_URL: String(baseUrl || "").replace(/\/$/, ""),
    ONEC_USER: String(user || ""),
    ONEC_PASSWORD: String(password || "")
  }, false);
}

Вызовите, например: saveOnecCredentials("https://host/base/odata/standard.odata", "odata_read", "пароль"). baseUrl – без хвоста сущности.

  1. Вставьте основной код – паттерн из Q&A, но с muteHttpExceptions: true и разбором кода ответа (ошибка "Адрес недоступен" часто маскирует сеть или SSL):
function refreshFrom1C() {
  var p = PropertiesService.getScriptProperties();
  var base = p.getProperty("ONEC_BASE_URL");
  var user = p.getProperty("ONEC_USER");
  var pass = p.getProperty("ONEC_PASSWORD");
  var url = base + "/Catalog_СтатьиДвиженияДенежныхСредств?$format=json&$top=500";
  var resp = UrlFetchApp.fetch(url, {
    method: "get", muteHttpExceptions: true,
    headers: { Authorization: "Basic " + Utilities.base64Encode(user + ":" + pass) }
  });
  if (resp.getResponseCode() !== 200) {
    SpreadsheetApp.getUi().alert("HTTP " + resp.getResponseCode());
    return;
  }
  var rows = JSON.parse(resp.getContentText()).value || [];
  var sh = SpreadsheetApp.getActive().getSheetByName("raw_dds") ||
    SpreadsheetApp.getActive().insertSheet("raw_dds");
  sh.clear();
  var hdr = Object.keys(rows[0] || {});
  sh.getRange(1, 1, 1, hdr.length).setValues([hdr]);
  sh.getRange(2, 1, rows.length, hdr.length).setValues(
    rows.map(function(r) { return hdr.map(function(h) { return r[h]; }); })
  );
}
function onOpen() {
  SpreadsheetApp.getUi().createMenu("1С")
    .addItem("Обновить из 1С", "refreshFrom1C").addToUi();
}
  1. Сохраните проект, обновите таблицу – меню "1С → Обновить из 1С". При первом Run выдайте права.
  2. Опционально: time-driven trigger с меньшим $top (лимит runtime 6 мин, квота Url Fetch до 20 000/день на consumer).

В Q&A лишний credentials: 'include' – для GAS хватит Authorization: Basic. Только HTTPS, не HTTP. Сделайте: $top=10 на тесте. Не делайте: тянуть Catalog_ФизическиеЛица из примера Q&A без нужды.

Проверка результата и типичные ошибки

После первого успеха сверьте строки с 1С и зафиксируйте HTTP-код в meta-листе.

Симптом Вероятная причина Что сделать
"Адрес недоступен" / exception fetch Firewall блокирует IP Google; HTTP вместо HTTPS; база только в LAN; самоподписанный SSL Allowlist IP Google; включить HTTPS; проверить URL с внешней сети, не из VPN офиса
HTTP 401 Неверный логин/пароль; нет роли OData; пользователь заблокирован Проверить Properties; роль УдаленныйДоступOData; тот же логин в браузере
Пустой value или 404 Объект не в составе OData; опечатка в Catalog_* Открыть $metadata, скопировать точное имя ресурса
Таймаут / обрыв на большом объёме Лимит 6 мин; тяжёлый запрос без $top Дробить $top, фильтр $filter по периоду, пагинация по @odata.nextLink

Ловушка Q&A: браузер с ПК открывает OData, GAS падает – Google ходит с других IP. Сделайте: логируйте getResponseCode(). Не делайте: отключать проверку SSL в production.

Что автоматизировать дальше

  1. Добавьте второй регистр (движения ДДС) тем же паттерном – отдельный raw_* лист.
  2. Постройте сводную на staging-листах; не смешивайте сырые ключи контрагентов с отчётом для собственника.
  3. Настройте триггер по расписанию, если команда забывает жать кнопку.
  4. Сверьте с банковской выпиской – OData даёт учёт, не заменяет банк.
  5. Если нужны формы, почта и webhook без кода – посмотрите автоматизацию финансов без кода (Make, Albato, n8n).

Excel/OData – в выгрузке 1С в Excel. Кейсы – в Telegram "Финансист, который кодит"; уроки – в клубе KODA.

Частые вопросы

Есть ли в Google Sheets встроенный OData-коннектор, как в Excel?

Нет. В Excel/Power Query есть "Из OData-канала", в Sheets – только Apps Script (UrlFetchApp) или сторонние коннекторы/no-code. Скопируйте скрипт из раздела выше и настройте Basic Auth через Properties.

Можно ли обойтись без программиста?

Скрипт – copy-paste и одна функция сохранения пароля. Публикацию OData, HTTPS и whitelist IP Google обычно делает админ 1С или подрядчик один раз. Без этого GAS не заработает, даже если код верный.

Почему в Q&A работает браузер, а UrlFetchApp пишет "Адрес недоступен"?

Запрос из браузера идёт с вашего ПК (или VPN), а GAS – из пула IP Google. Firewall должен пропускать оба контура. Плюс проверьте HTTPS и валидный сертификат – HTTP и самоподписанный SSL часто ломают fetch.

Сколько времени займёт первое подключение?

При готовой публикации OData – около одного рабочего дня на скрипт и тест. Если нужны HTTPS, состав объектов и whitelist – закладывайте от 2 до 5 дней с админом, без обещаний "за час".

Какие риски для данных при Basic Auth в облаке?

Пароль в Script Properties (доступ у редакторов скрипта), утечка через общий доступ к таблице, ПДн на листе. Минимизируйте: read-only пользователь, staging без ФИО/ИНН, ротация пароля при увольнении, обезличивание перед LLM.

Что делать, если объём не влезает в 6 минут?

Уменьшите $top, добавьте $filter по периоду или пагинацию по @odata.nextLink. Тяжёлое – в Python/CSV на Drive, в Sheets только import.
