Каждый раз, когда вы просите Cursor "выгрузи дебиторку из 1С", агент снова уточняет сущность OData, лимит строк и куда сохранить файл. Cursor Skill "выгрузка из 1С" упаковывает этот сценарий в SKILL.md: триггер, шаги для агента и связка с MCP-транспортом OData. После настройки вы повторяете выгрузку одной фразой и сверяете 2–3 суммы с отчётом 1С, а не объясняете правила в каждом чате.

Skill – это не замена публикации OData и не замена rules про ПДн. Rules задают "что нельзя", MCP даёт "розетку" для HTTP-запросов к базе, Skill описывает пошаговую процедуру выгрузки, когда вы говорите "дебиторка", "ДДС" или "реестр за период". Если OData ещё не опубликован, сначала пройдите гайд по выгрузке 1С в Excel через OData; Skill не создаёт URL сам.

Подготовьте данные и безопасность (без сырых ПДн в облако)

OData для ИИ – слой аккуратного чтения. Риски: массовый $top на весь регистр, утечка JSON с ФИО и ИНН в облачный чат, запись в базу без человека. Для fin-старта – только read-only MCP, узкий состав сущностей в публикации, отдельный пользователь ИБ с минимальными правами; логин латиницей (кириллица часто ломается коннекторами).

  1. Согласуйте с админом whitelist Catalog_* и AccumulationRegister_* в составе OData.
  2. Создайте пользователя read-only с ролью удалённого доступа OData.
  3. Храните URL, логин и пароль только в env / Script Properties, не в SKILL.md и git.
  4. Добавьте exports/ и data/ в .gitignore; полные выгрузки не коммитьте.
  5. В SKILL.md пропишите запрет: не вставлять сырой JSON с ПДн в чат; обезличивание – по гайду обезличивания для ChatGPT.
  6. Включите Privacy Mode в Cursor, если работаете с чувствительными срезами.

1c-odata-mcp по умолчанию read-only; write-tools видны в списке, но блокируются на уровне env. Для fin-skill write-сценарии не описывайте – только отдельный проект с preview/confirm и человеком в контуре.

# 1C OData Export

## When to Use
Повторяемая выгрузка из опубликованной базы 1С: ДДС, дебиторка, реестр документов за период.

## Preconditions
- OData опубликован (…/odata/standard.odata), сущность в whitelist references/entities.md
- MCP 1c-odata-mcp подключён, read-only
- Результат – exports/, не сырой JSON в чат

## Steps
1. Уточни сущность, период, $top (начни с 100–1000).
2. Вызови MCP read-tool или GET с $filter по дате.
3. Сохрани в exports/ с датой в имени файла.
4. Сверь 2–3 суммы с отчётом 1С; при расхождении – остановись.

## Errors
401 – роль OData / логин; пустой value – объект не в составе OData; timeout – уменьши $top.
Схема: Запрос "дебиторка" → Skill (процедура) → MCP tool → OData GET → exports/ → сверка с 1С

Структуру SKILL.md можно набросать через built-in /create-skill в Cursor. Детали сущностей держите в references/, не раздувайте основной файл (рекомендация spec: меньше 500 строк).

Сделайте: один skill под fin-export, не клонировать весь Desko77/cursor-1c-skills. Не делайте: хранить пароли в mcp.json в git.

Частые вопросы

Можно ли оформить Skill без программиста 1С?

SKILL.md и mcp.json финансист соберёт сам. Публикацию OData и состав сущностей обычно делает админ один раз; дальше вы повторяете сценарий через Agent без пересказа правил.

Сколько займёт внедрение?

При готовом OData – 1–2 часа на SKILL.md, references и smoke-test. С нуля (публикация + MCP + skill) – вечер с админом, если заранее знаете типичные ошибки состава OData.

Чем Skill отличается от Rules?

Rules – постоянная "конституция" проекта: ПДн, папки, git. Skill – процедура, которую агент включает при релевантном запросе "выгрузи дебиторку". Оба слоя нужны вместе.

Нужен ли отдельный MCP, если Skill уже есть?

Да. Skill инструктирует агента, как вызывать tools; транспорт – MCP (1c-odata-mcp или аналог). Без MCP skill останется текстом без доступа к базе.

Какие риски для данных при выгрузке через Agent?

Утечка через облачную модель и избыточный $top. Снижайте: read-only, whitelist сущностей, exports/ локально, обезличивание перед анализом в чате, при необходимости локальная модель.

Можно ли через skill писать в базу 1С?

Для fin-старта – нет, только read. Write в 1c-odata-mcp требует отдельных флагов и human-in-the-loop; оформляйте отдельный проект и skill, не смешивайте с выгрузкой CFO.
