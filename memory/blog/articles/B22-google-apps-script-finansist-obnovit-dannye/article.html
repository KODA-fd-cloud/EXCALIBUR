Каждый понедельник одно и то же: выгрузить ДДС из 1С, скачать CSV, Импорт в Google Sheets, снова поправить фильтры. Кнопка "обновить данные" через Google Apps Script убирает этот ритуал. За один вечер сделаете меню или кнопку в таблице, подключиете источник (CSV с Диска, webhook или OData 1С) и при желании откроете HTML-сводку без отдельного сайта.

Apps Script – как макрос Excel, только живёт в облаке Google и умеет ходить в интернет (UrlFetchApp), писать на листы и отдавать страницу через HtmlService. Для финансиста это не "выучить JavaScript", а собрать один сценарий: нажал – лист raw обновился.

В пилоте сводки кассы я так и делаю: таблица + Code.gs с refreshFrom1C() по OData УНФ и веб-UI "Сводка кассы". Ниже – общий маршрут и практика из этого контура. Про сам OData подробнее – в выгрузка 1С в Excel через OData. Про no-code рядом – в автоматизация финансов без кода.

Разберите, зачем кнопка, если есть ручной импорт CSV

Ручной импорт ломает привычку: забыли лист, сдвинули формулы, импортировали "в новую вкладку". Кнопка фиксирует маршрут. Меню в таблице – как кнопка "Провести" в учётной системе: одно действие, понятный результат.

Ручной CSV Раз в квартал, маленький файл Ошибки импорта, нет лога

Создайте первый скрипт: меню и функция "Обновить"

Кастомное меню работает только у скрипта, привязанного к таблице (Extensions → Apps Script). Код меню кладут в onOpen – simple trigger при открытии файла.

  1. Откройте нужную Google-таблицу → Расширения → Apps Script.
  2. Вставьте onOpen и функцию обновления, сохраните (Ctrl+S).
  3. Обновите вкладку таблицы или выполните onOpen вручную (▶ Run) и выдайте права.
  4. В меню сверху появится пункт, например "Финансы → Обновить данные".
  5. Проверьте toast и что целевой лист изменился.
  6. Альтернатива кнопке: Вставка → Рисунок → Assign script → имя функции без скобок.
function onOpen() {
  SpreadsheetApp.getUi()
    .createMenu("Финансы")
    .addItem("Обновить данные", "refreshData")
    .addToUi();
}

function refreshData() {
  var ss = SpreadsheetApp.getActive();
  var sh = ss.getSheetByName("raw_dds") || ss.insertSheet("raw_dds");
  // TODO: загрузка строк из Drive / UrlFetch / OData
  ss.toast("Обновление запущено", "Финансы", 5);
}

Если меню не видно – скрипт не сохранён, открыт не тот файл, или нет права редактора. Переоткройте вкладку. Имя меню одно на файл: повторный createMenu с тем же именем заменяет старое.

Сделайте: видимое меню + toast. Не делайте: хранить пароль 1С в ячейке "чтобы было удобно".

Выберите источник: CSV с Диска, webhook или OData 1С

API здесь – как курьер между системами. Apps Script может забрать файл с Drive, принять POST (doPost) или сходить UrlFetchApp на OData 1С. В пилоте сводки кассы основной путь – refreshFrom1C(): Basic Auth, справочники + AccumulationRegister движений денег → лист raw_dds, в meta пишется ops_count.

  1. Один раз выполните saveOnecCredentials(baseUrl, user, password) – учётные данные уходят в Script Properties, не на лист.
  2. baseUrl – адрес вида .../odata/standard.odata (без хвоста сущности).
  3. Вызовите refreshFrom1C() из меню или из HTML-кнопки.
  4. Проверьте raw_dds: есть заголовок date/month/article/... и строки операций.
  5. Если OData отвечает с BOM – срежьте первый символ перед JSON.parse (в боевом Code.gs так и сделано).
  6. Тяжёлый объём: снаружи python fetch + push_via_webapp.py шлёт POST в doPost на тот же webapp URL.
Схема пилота: кнопка/меню → refreshFrom1C (OData) → raw_dds + meta → HTML-сводка читает лист 
function saveOnecCredentials(baseUrl, user, password) {
  PropertiesService.getScriptProperties().setProperties({
    ONEC_BASE_URL: String(baseUrl || "").replace(/\/$/, ""),
    ONEC_USER: String(user || ""),
    ONEC_PASSWORD: String(password || "")
  }, false);
}

Сделайте: credentials в Properties + один успешный refresh. Не делайте: коммитить пароль в git-репозиторий со скриптом.

Соберите дашборд поверх листа: HtmlService без отдельного сайта

HtmlService.createTemplateFromFile("Index") в doGet отдаёт страницу "Сводка кассы" как веб-приложение Google. Отдельный VPS не нужен. В UI кнопка "Обновить из 1С" вызывает google.script.run.refreshFrom1C(), потом перечитывает getDashboardPayload().

  1. В проекте Apps Script файл HTML должен называться Index (без .html в имени внутри редактора).
  2. В Code.gs оставьте doGet, который evaluate() шаблон и ставит viewport.
  3. Развернуть → Новое развёртывание → Веб-приложение → Выполнять: от вашего имени.
  4. Доступ: сначала "Только я"; "Все" – только если понимаете, что URL увидят с данными сводки.
  5. После правок кода – новая версия развёртывания, иначе UI останется старым.
  6. Откройте URL с телефона и нажмите обновление – как smoke-test.

Фильтры, KPI и лента операций живут в Index.html; источник правды – листы таблицы. Мок-данные (seedMockData) удобны, чтобы отладить UI без боевой 1С. В том же проекте doPost принимает JSON от Python: raw_dds и dashboard целиком перезаписываются, в meta ставится source=python_push. Так вы не упираетесь в 6 минут UrlFetch, когда регистр толстый.

Практический порядок, которым я пользуюсь: сначала меню и refresh на малом $top, потом HTML-кнопка на том же refreshFrom1C, и только если упираемся в время – вынос выгрузки в fetch_cashflow.py. Не наоборот: иначе отлаживаете сразу три слоя.

Сделайте: webapp URL открывается и кнопка обновляет meta.updated_at. Не делайте: публиковать "всем" с паролем 1С в том же проекте без отдельной узкой учётки.

Проверьте права, триггеры и типичные поломки

Квоты Google реальны: UrlFetch около 20 000 вызовов/день на consumer и 100 000 на Workspace; один запуск скрипта – до 6 минут. Триггеры по времени (installable) удобны для ночного обновления, но съедают дневной runtime (90 мин consumer / 6 ч Workspace).

  • Меню не появилось → сохранить, reload, Run onOpen, проверить editor access.
  • Authorization required → первый Run с OAuth; для UrlFetch к 1С нужны scopes.
  • HTTP 401/403 от OData → учётка, права на регистр/справочники, публикация OData.
  • Таймаут → уменьшите $top, режьте период, или вынесите выгрузку в Python → doPost.
  • Webapp "старый" → не создали новую версию после правок.
  • Секреты → только PropertiesService; лист "settings" с паролем – антипаттерн.
  • Одновременные запуски → не жмите "Обновить" пятнадцать раз подряд: упрётесь в лимит параллельных выполнений.
  • Ответ 1С с кракозябрами → проверьте BOM и кодировку JSON; в пилоте перед parse срезается FEFF.

Отдельно про installable time-driven triggers: ночной refresh удобен, но на consumer-аккаунте легко съесть дневной runtime. Я ставлю триггер только после того, как ручной запуск стабильно укладывается в минуту-две и понятен rollback (оставить предыдущий raw или писать в лист-staging).

Разборы таких контуров – в Telegram "Финансист, который кодит".

Сделайте: чеклист квот и прав до "поставь на каждый час". Не делайте: часовой trigger на полную выгрузку без замера времени запуска.

Частые вопросы

Можно ли сделать кнопку без знания JavaScript?

Да для старта: скопируйте шаблон onOpen + refresh, замените имена листов и URL OData. Учить язык имеет смысл после первого успешного обновления, точечно по ошибкам.

Безопасно ли хранить пароль 1С в Apps Script?

Храните только в Script Properties через saveOnecCredentials, не на листе и не в git. Заведите отдельную учётку 1С с минимальными правами на нужные объекты OData.

Какие лимиты Google важны финансисту?

6 минут на один запуск, дневные лимиты UrlFetch и суммарный runtime триггеров. Если выгрузка жирная – Python снаружи и doPost, а не бесконечный UrlFetch в цикле.

Меню не появляется. Что проверить первым?

Сохранение файла, перезагрузка вкладки таблицы, права редактора, ручной Run onOpen. Меню не показывается читателям без права edit.

Нужен ли программист 1С?

Для публикации OData и прав узкой учётки – обычно да, один раз. Сам Apps Script и кнопку финкоманда собирает сама по шаблону.

Чем HTML-дашборд лучше листа с графиками?

Удобнее фильтры и мобильный просмотр по URL. Лист остаётся источником данных. Для совета директоров это всё ещё прототип, не замена BI.

Можно ли обойтись только Telegram без PWA/webapp?

Да, если бот дергает тот же backend/OData. В этом гайде фокус – Google Sheets + Apps Script; Telegram – соседний канал на том же контракте данных.
